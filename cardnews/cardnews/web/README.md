# 카드뉴스 수집기

인스타그램에서 캐러셀(카드뉴스)을 모아 슬라이드까지 보고 내려받는 정적 웹앱.

2026-09-16 부터 뿌리(`/`)는 리타에 넣는 **채팅 페이지**(`index.html`)다. 수집기는
이름을 바꿔 두었고 어디서도 링크하지 않는다 — 파일 목록에서 찾아 직접 친다.
채팅 페이지 설계: `docs/superpowers/specs/2026-09-16-카드뉴스-채팅페이지-design.md`.

## 실행

```
npm run dev
```

`http://localhost:8788` 에서 열린다. 이 서버는 Cloudflare 에 올라갈
`web/_worker.js` 를 **그대로 불러 쓴다.** 중계 로직을 두 벌 두면 로컬에서
되던 것이 배포에서 안 되는 일이 생기기 때문이다.

빌드는 없다.

## 배포 — Cloudflare Workers

```
npx wrangler login     # 처음 한 번만
npm run deploy
```

**대시보드의 드래그 앤 드롭으로는 안 된다.** 그렇게 올리면 Cloudflare 가
"정적 파일만 있는 Worker" 로 만들어서 `_worker.js` 가 코드로 실행되지 않고
그냥 파일로 서빙된다. 두 번 시도해서 두 번 다 그랬다.

```
/              200
/img?ping=1    404   <- 중계기가 안 돈다
/_worker.js    200   <- 스크립트가 아니라 파일로 취급됐다
```

`_worker.js` 를 알아서 인식하는 것은 Pages 인데, 대시보드가 더 이상 Pages 를
만들지 않는다. 그래서 `wrangler.jsonc` 에서 진입 스크립트를 직접 지정하고
명령으로 올린다.

`npm run build` 가 `web/` 에서 테스트·문서·`_worker.js` 를 뺀 `dist/` 를 만든다.
`_worker.js` 는 정적 파일이 아니라 진입 스크립트이므로 `dist/` 에 넣지 않는다.

배포 후 `주소/img?ping=1` 이 `ok` 를 주면 중계기가 살아 있는 것이다.

Cloudflare 를 고른 이유는 **대역폭이 무제한이고 이그레스 요금이 0원**이기
때문이다. 이 앱은 이미지를 통째로 중계하므로 트래픽이 전부인데, 다른 곳은
100GB 같은 천장이 있다. 배포도 월 500회라 고쳐 올리기가 자유롭다
(Netlify 무료는 월 20회).

## 검색어를 어떻게 쓰느냐가 제일 크다

주제만 넣어도 잘 나오는 검색어가 있고 릴스가 섞이는 검색어가 있다. 그래서
처음부터 참견하지 않고, **검색해봐서 카드뉴스가 5건 미만일 때만** 검색어 뒤에
"카드뉴스"를 붙여보라고 권한다. 버튼은 검색창을 바꿔주기만 하고 검색은
사용자가 누른다 — 누르는 순간 돈이 나가면 안 되기 때문이다.

권하는 근거는 본계정으로 로그인한 크롬에서 직접 세어본 결과다.

| 검색어 | 결과 |
|---|---|
| `#아이돌` | 게시물 25건, 카드뉴스와 릴스가 섞임 |
| `아이돌 카드뉴스` | 게시물 15건, **전부 카드뉴스** (릴스 링크 0건) |

띄어쓰기를 지우면 안 된다. `아이돌 카드뉴스` 와 `아이돌카드뉴스` 는 인스타에서
다른 검색이다. 그래서 검색어는 앞뒤·중복 공백만 정리하고 그대로 넘긴다.

## 계정에 따라 결과가 달라진다

같은 검색어라도 **어느 계정으로 보느냐에 따라 결과가 다르다.** 카드뉴스를 자주
보던 계정은 카드뉴스가, 그렇지 않은 계정은 릴스가 많이 나온다. 인스타 검색이
보는 사람의 이력에 맞춰지기 때문이다.

부계정 쿠키를 넣었는데 릴스만 나온다면 그 계정이 카드뉴스를 본 적이 없어서다.
부계정으로 카드뉴스 계정 몇 개를 팔로우하고 며칠 둘러보면 결과가 옮겨간다.

## 디자인은 별도 창에서 본다

그리드에서 카드를 누르면 **새 창**이 열린다. 창을 여러 개 띄워 나란히 놓고
디자인을 비교할 수 있다.

창 안에서 다 끝난다 — 슬라이드 넘기기(← →), 한 장/전체 저장, 원본 열기,
그리고 **이 계정 더 보기**. 계정 게시물 10건이 같은 창에 뜨고 거기서 다른
카드뉴스를 골라도 그 창에서 이어본다. 뒤로가기로 목록과 게시물을 오간다.

다만 계정 게시물을 받아오는 호출만은 원래 창이 대신 한다
(`window.opener.getAccountPosts`). 돈이 나가는 호출을 한 곳에 모아둬야
과금 지점이 흩어지지 않는다. 창은 받은 것을 그리기만 한다.

창을 크게 열었을 때 아래가 무너지던 문제를 세 가지 고쳤다. 실제 크롬으로
화면을 띄워 눈으로 확인한 것들이다.

- **높이를 `100vh` 로 가둬** 슬라이드가 크면 썸네일과 버튼이 밀려났다.
  이미지를 `62vh` 로 묶고 페이지가 늘어나 스크롤되게 했다.
- **폭에 제한이 없어** 창을 넓히면 내용이 끝없이 늘어나고 아래 버튼이 화면
  밖으로 잘려 나갔다. `max-width:1100px` 로 묶고 가운데 정렬했다.
- **실패한 썸네일을 감춰** 열 장이 다 실패하면 줄이 통째로 사라졌다. 자리를
  남기고 흐리게 표시한다. 옆 칸은 건드리지 않는다 — 썸네일의 옆은 다음
  썸네일이라 줄이 어그러진다.

썸네일에 `loading="lazy"` 를 붙였더니 화면에 보이는데도 빈 칸으로 남았다.
몇 장 안 되고 항상 보이므로 뺐다.

## 표지에 글자 없는 것 빼기

카드뉴스 표지에는 글자가 얹혀 있다. 그래서 표지를 흐릿하게 줄여놓고
"매끈한 바탕 위에 진한 경계가 몰려 있는가"를 세서 글자 여부를 어림잡는다.
사진은 경계가 화면 전체에 고루 퍼지고 매끈한 데가 거의 없어서 갈린다.

이미 화면에 띄운 썸네일을 다시 쓰므로 추가 요청도 비용도 없다.

실측 표지 17장(글자 7 / 사진 10) 기준으로 **글자 있는 것은 하나도 안 놓쳤고
헛잡은 것은 1건**이었다. 그 1건은 네온 간판 사진인데, 간판에 글자가 진짜로
있어서 픽셀만 봐서는 구분할 방법이 없다. 사진에 찍힌 글자와 편집자가 얹은
글자를 가르지 못하는 것이 이 방법의 한계다.

기준선은 0.010이다. 실측에서 글자 있는 표지의 최저 점수가 0.019였으므로
그 절반 아래에 두었다. **글자 있는 것을 빠뜨리는 쪽이 헛잡는 쪽보다 나쁘기
때문이다.** 표지를 못 읽은 게시물도 같은 이유로 남긴다.

이 필터는 끌 수 없다. 표지에 글자가 없으면 카드뉴스가 아니기 때문이다.

주의: 글자 유무는 **떨어뜨리는 조건이지 붙이는 조건이 아니다.** 짧은 홍보물도
표지에 글자가 큼직하게 박혀 있어서 이 필터를 통과한다. 슬라이드 장수 하한과
같이 써야 짧은 홍보물과 순수 사진이 둘 다 걸린다.

## 처음 쓸 때

"키 설정"을 눌러 Apify API 키를 붙여넣는다. 여러 개를 넣으면 위에서부터
쓰다가 크레딧이 떨어진 키를 건너뛰고 다음 키로 넘어간다. 저장을 눌러도
기존 키는 지워지지 않고 목록에 더해진다. 특정 키만 빼려면 목록에서 그
키의 × 를 누른다.

저장된 키는 화면에 끝 4자리만 보인다(`••••••••1234`). 입력칸은 창을 열 때마다
비어 있으므로 시연 중에 눌러도 키가 노출되지 않는다. 키는 브라우저에만
저장되고 서버로 보내지 않는다.


## 인스타 세션 쿠키 (선택이지만 사실상 필수)

인스타는 해시태그 피드 페이지를 없애고 검색으로 합쳤다. `/explore/tags/아이돌/`
로 들어가면 `/explore/search/keyword/?q=#아이돌` 로 넘어간다. 그리고 그 검색
결과는 **로그인한 계정마다 다르다.**

실측으로 확인한 차이다.

| | 내 화면(로그인) | 액터(쿠키 없음) |
|---|---|---|
| 유형 | 게시물 25건 전부 `/p/`, 릴스 링크 0건 | 릴스 37 · 사진 9 · 캐러셀 3 |
| 겹치는 게시물 | — | 25건 중 3건 (12%) |

쿠키를 넣지 않으면 **내가 인스타에서 보는 것과 다른 목록**이 온다. 그래서
"키 설정"에 인스타 세션 쿠키 칸을 두었다. 넣으면 검색 결과가 내 화면과
같아진다.

**반드시 부계정 쿠키를 쓴다.** 자동화 도구에 쓴 계정은 인스타가 제한하거나
정지시킬 수 있다. 쿠키도 Apify 키와 똑같이 브라우저에만 저장되고 화면에는
끝 4자리만 보인다.

쿠키 꺼내는 법: 부계정으로 로그인한 크롬에서 F12 → Application → Cookies →
`https://www.instagram.com` → `sessionid` 값을 복사해 `sessionid=값` 형태로
붙여넣는다.

## 비용

검색 버튼을 누를 때만 돈이 나간다. 슬라이드 넘기기, 정렬, 필터, 더 보기,
태그 숨기기, 표지 글자 판정은 이미 받아온 데이터로 처리하므로 무료다.

금액은 **Apify 크레딧(달러)** 으로 보여준다. Apify 콘솔이 `$0.00 / $5.00` 로
표시하므로 남은 크레딧과 그대로 대조할 수 있다. 원화로 환산하면 환율을 우리가
정해야 하고 콘솔 숫자와 맞지 않는다.

| 동작 | 크레딧 |
|---|---|
| 25건 탐색 | $0.26 |
| 50건 탐색 | $0.53 |
| 100건 탐색 | $1.05 |
| 계정 더 보기 10건 | $0.03 (같은 계정 재방문 무료) |

가입 크레딧 $5 로 50건 탐색을 9번쯤 돌릴 수 있다.

액터 설명에는 1,000건에 $3.00 이라고 적혀 있지만 **실측은 50건에 $0.5263,
건당 $0.0105 로 3.5배였다.** 표시 금액은 실측값 기준이다.

수집 중에는 경과 시간이 표시되고 "중단"을 누르면 Apify 실행 자체를 세워
더 이상 과금되지 않게 한다.

## 알아둘 것

### 왜 어떤 디자인은 안 보이나 — 그리고 어떻게 고쳤나

인스타 CDN은 **엣지 서버마다 헤더 정책이 다르다.** 같은 인스타 이미지인데
어떤 서버는 브라우저에 내주고 어떤 서버는 막는다. 실측한 13개 호스트가
정확히 둘로 갈렸다.

| | `access-control-allow-origin` | `cross-origin-resource-policy` | 브라우저 |
|---|---|---|---|
| 8개 호스트 | `*` | `cross-origin` | 보인다 |
| 5개 호스트 | 없음 | `same-origin` | **막힌다** |

주소가 만료된 것도, 우리 코드 문제도 아니다. 서버에서 `curl` 로 받으면
5개 다 HTTP 200 에 이미지가 온다. **브라우저만 `same-origin` 정책 때문에
못 싣는다.** 우회할 방법은 없다 — 이 정책은 브라우저가 강제하고 끄는
스위치가 없다. 서버를 두고 중계하면 되지만 그러면 정적 사이트가 아니게 된다.

**그래서 `_worker.js` 가 대신 받아온다.** 브라우저가 인스타에 직접 요청하면
거절당하지만, 우리 서버가 받아서 우리 주소로 내놓으면 같은 출처가 되므로
정책에 걸리지 않는다. 서버 대 서버 요청에는 CORP 가 적용되지 않는다.

실측으로 확인했다. 브라우저가 막던 호스트 6개 중 **5개가 중계로 통과**했다.
나머지 1개(`instagram.fosu2-1...`)는 CORP 문제가 아니라 **호스트 이름 자체가
DNS 에 없다** — 인스타가 내려버린 엣지라 아무도 못 가져온다.

덤으로 두 가지가 같이 해결됐다. 중계를 거친 이미지는 우리 출처이므로
**표지 글자 검사(canvas 픽셀 읽기)** 와 **파일 저장** 도 항상 된다. 막혀서
검사를 못 하던 표지 4장이 되살아났다.

중계가 없는 환경에서도 앱은 그대로 돈다. 시작할 때 `/img?ping=1` 로 한 번
물어보고, 없으면 원래 주소를 쓴다. 그때 실패한 자리는 빈칸 대신 안내와
원본 링크를 보여준다.

중계기는 **인스타 주소만** 받는다(`cdninstagram.com`, `fbcdn.net`). 아무 주소나
받아주면 남이 이 계정으로 트래픽을 쓰는 공개 중계기가 된다.

막히는 이유가 둘인데 해법이 서로 다르다.

**하나. 엣지마다 CORP 정책이 다르다.** 이건 중계기로 푼다. 브라우저가 직접
요청하면 거절당하지만 서버 대 서버 요청에는 CORP 가 적용되지 않는다.
호스트를 바꿔봐야 소용없다 — CORP 딱지는 호스트가 아니라 **경로**에 붙어 있어서
주소를 다른 호스트로 옮겨도 그대로 따라온다(실측: 막힌 5곳을
`scontent.cdninstagram.com` 으로 바꿔도 5곳 다 여전히 `same-origin`).

**둘. 엣지가 아예 사라진다.** 호스트 이름이 DNS 에서 없어진다. 이건 중계기로도
못 받는다. 대신 **서명이 경로에 걸려 있어서 호스트만 살아 있는 곳으로 바꾸면
같은 이미지가 온다.** 실측: 죽은 엣지 주소를 `scontent.cdninstagram.com` 으로
바꾸니 262,542 bytes 동일한 이미지가 왔다.

그래서 두 겹으로 시도한다.

```
중계기 안에서   원래 호스트 → 안 되면 scontent.cdninstagram.com 으로 같은 경로
브라우저 쪽에서  중계 → 원래 주소 → 호스트 바꾼 주소 → 그래도 안 되면 안내
```

실측 결과 — 캐러셀 12개(호스트 12곳)에서 **직접 부르면 4곳만 뜨고, 중계를
거치면 12곳 전부 뜬다.** DNS 가 사라진 엣지도 포함이다.

남는 것은 주소가 만료된 경우뿐이다. 그건 다시 검색해 새 주소를 받아야 한다.

인스타그램 이미지 주소는 며칠이면 만료된다. 오래 보관하려면 뷰어 창의
**전체 저장**을 누른다. 슬라이드를 모아 **zip 파일 하나**로 내려받는다
(`캡션 앞부분 - 계정.zip`, 안에는 `01.jpg`, `02.jpg` …). 압축은 하지 않는다 —
JPEG 는 이미 압축돼 있어 다시 압축해봐야 줄지 않고 시간만 든다. 라이브러리를
쓰지 않고 직접 만들며, 실제 압축 프로그램이 풀 수 있는지 테스트로 확인한다.

## 공동 목록

검색 결과 카드의 하트를 누르면 슬라이드 전부가 우리 서버에 복사되고, 같은 암호로
들어온 사람 모두에게 같은 목록이 보인다. 인스타 주소가 만료돼도 그림이 남는다.

- 설계: `docs/superpowers/specs/2026-08-16-cardnews-board-design.md`
- 표(D1) `picks` · 창고(R2) `cardnews-shots` · 암호는 `BOARD_PASSWORD` 시크릿
- 서버 코드는 `web/server/` 에 둔다. **`web/lib/` 는 브라우저로 그대로 내려간다.**
- 공동 목록을 만질 때는 `npm run dev` 가 아니라 `npm run dev:cf`(=`wrangler dev`) 를 쓴다.
  `dev-server.mjs` 에는 표도 창고도 없다. **`wrangler dev` 는 `web/` 이 아니라 `dist/` 를
  서빙하므로, 화면을 고친 뒤에는 `npm run build` 를 먼저 돌려야 바뀐 것이 보인다.**
- 2단계 분석으로 넘길 때: `python analyze/fetch_board.py`
  (`analyze/config.py` 가 아직 없다면 `ImportError` 만 난다. 2단계 계획
  `docs/superpowers/plans/2026-08-16-cardnews-analyze.md` 의 Task 1 을 먼저 끝내야
  그 파일이 생긴다.)
