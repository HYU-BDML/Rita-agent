# Cora

**Content Operations Run by Agents** — 추후 변경 가능한 제품명.

Cora 전용 개발 공간이다. **1~2일 집중 구현을 목표로 먼저 통합 작업본을 만들고, 유경이가 사용·수정하면서 개선한다.** 12주는 이후 검증·개선 일정이다. 본인·학생·AI가 합의한 범위의 90% 이상을 구현하는 것이 목표이며 완료율을 보장하는 숫자는 아니다.

현재 개발 현황은 `docs/Cora_집중구현_2026-09-30/00_지금만들_제품범위.md`와 `기능별_개발원장.csv`를 따른다. Mirr 109개 기능 + 추가 10개 기능을 유지한다. 부분 구현과 실제 외부 운영 검증을 구분한다.

## 폴더

- `apps/trend-hub/`: 기존 Trend ZIP을 독립 복사한 앱과 새 Cora 제작실(`/studio`). 로컬 계정·자료 구성·카드 편집·저장·PNG 내보내기를 구현했다.
- `integrations/publishing/`: Sabrina의 n8n+Blotato 계정 연결·즉시/예약 게시 통합 계획.
- `integrations/cardnews/`: 배포 링크와 코드 입수 후 통합할 자리.
- `docs/제품개발_마스터플랜_2026-09-29/00_여기부터.md`: 현재 사업·제품·12주 개발계획.
- `docs/`: Mirr 분석, 국내외 벤치마크, 연구 및 사업계획. 과거 전략 문서는 당시 기록이며 현재12주·90% 구현 원칙이 우선한다.
- `research/`: 조사 메모·공개 페이지 캡처·문서 생성/검증 스크립트의 보관본. 과거 생성 스크립트에는 기존 로컬 경로가 있어 실행 전 경로를 조정해야 한다.
- `references/trend-hub/`: 가져온 앱의 과거 설계·지시서. 현 프로젝트 실행 지침이 아닌 참고 자료다.
- `PROVENANCE.json`: 복사 원본·커밋·파일 해시.
- `CHANGELOG.md`: Cora의 변경 이력.

## 작업 방식

원래 Rita-agent의 Trend/cardnews/Smartstore/숏폼 폴더는 수정하지 않는다. 재사용하는 코드는 Cora 안으로 복사하고 이곳에서 변경한다. 원본 개선을 가져올 때는 차이를 검토하고 선택적으로 반영한다. 원본으로부터 자동 덮어쓰기는 하지 않는다.

코드·문서의 변경은 작업 브랜치에서 커밋하고 PR로 비교한다. 기존 Google Drive 작업공간은 로컬 보관과 산출물 열람에 계속 사용하며, GitHub의 Cora 폴더에서 버전 이력을 관리한다. Drive outputs로 내보낼 때도 같은 변경을 Cora/docs에 반영한다. 비밀키·고객 파일·운영 DB·생성 결과물은 Git에 넣지 않는다.

## 현재 인계 패키지

`docs/Cora_실행과인계/00_먼저읽기.md`부터 읽는다. 사업·STP·BM·벤치마크·MVP·12주·출시 계획과 유경이의 실행/검수 안내를 통합했다. 새 제작실은 브랜드 설정 재사용, 개인 작업 상태/검토 메모, 필터, 사본, JSON 복원, 삭제를 지원한다. 현재 상태는 고객 승인이나 실제 게시 완료가 아니다.

## 로컬 제작실 실행

Node.js 22.13 이상(권장 22.22)을 설치한 뒤:

```bash
cd Cora/apps/trend-hub
node scripts/run-local.mjs
```

http://127.0.0.1:3210/studio 에 접속한다. 최초 실행은 npm 의존성을 내려받는다. 의존성·빌드는 OS 임시 폴더, 사용자 DB는 앱의 `data/cora`에 보관하며 Git에서 제외한다. 이 실행기는 이 컴퓨터에만 서버를 연다. 소스를 수정한 뒤에는 종료하고 다시 실행한다. 이메일은 로컬 계정 식별용이며 인증 메일을 발송하지 않는다.

자세한 사용·검수·남은 작업은 `docs/Cora_첫작업본_2026-09-29/사용과검수.md`를 참조한다. 공유 Drive의 SQLite를 여러 컴퓨터에서 동시에 열지 않는다. 유경이는 별도 Git 체크아웃에서 실행한다.

## 현재 구현 범위

로컬 계정 → 브랜드 설정 → 자료 입력 또는 공개 URL/RSS 수집 → 실제 AI 카드·블로그·영상 대본·아이디어 생성 → 편집·저장 → PNG/JSON/MP4 내보내기를 연결했다. 카드 비율 3종, 디자인 3종, 서체 2종과 글자 크기 선택을 지원한다. 계정별 소재·글·영상·분석·운영 달력·반복 지시를 보관한다. CSV 진단은 제공한 도달·저장 등의 실제 값으로 계산한다.

실제 AI는 로컬 Python `llmgw`를 사용한다. `CORA_PYTHON`으로 Python 실행 경로를 지정할 수 있다. 해당 환경에 llmgw 설치와 개인별 공급자 설정이 필요하며 키를 저장소에 복사하지 않는다. 기본 시험 모델은 모델 목록과 실제 호출로 확인한 `deepseek-flash`; 실행당 비용은 게이트웨이에 단가 등록 전이므로 미확인이다. 로컬 시험 한도는 사용자당 24시간 10회이며 실패도 포함한다. MP4는 PATH의 `ffmpeg` 또는 `CORA_FFMPEG` 경로가 필요하다. 현재 영상은 카드별 3초인 무음 슬라이드다.

**아직 없는 것:** 실제 SNS 계정 연결·발행·예약 실행, 계정 지표 동기화, 팀 초대/고객 승인, 반복 작업 타이머, 음성/음성 복제, 전체 영상 편집, 결제/API/MCP 등. UI만 있는 항목을 연결 완료로 표시하지 않는다. 원본 카드뉴스 앱은 GitHub에 README만 있어 코드 통합 대기다.

기존 Trend 화면/API는 원본 공용 자료를 다루므로 기본 차단하며, `CORA_LEGACY_OPERATOR_ID`로 지정한 운영자의 유효한 Cora 세션만 허용한다. 일반 고객의 작업은 `/api/cora/*`에서 사용자별로 격리한다. 공개 고객 서비스로 배포하기 전 운영 인증·백업·의존성 보안 검토가 남아 있다. Next를 15.5.26으로 올렸으나 npm audit에 남은 항목이 있어 공개 배포 승인 상태가 아니다. 사용자별 저장은 SQLite이며 여러 컴퓨터가 공유 Drive의 DB를 동시에 열면 안 된다.

## 검증

런타임 복사본에서 `npm run build`, `npm test`를 실행한다. 원본 관측 DB가 제외되어 기존 recipe 시험 하나는 명시적으로 건너뛴다. Cora 브라우저 회귀 시험은 `scripts/cora-proof.mjs`다. Playwright와 Chrome 설치가 필요하고 기본 시험 서버는 3211 포트다. 운영 자료와 분리한 `CORA_DATA_DIR`를 지정해야 한다.

## API 비용 정책 — 2026-09-30

먼저 `python3 scripts/setup-cora-llm.py`를 앱 폴더에서 실행하면 개인 llmgw 설정에 Cora 전용 경로만 추가한다. 기본값은 `cora_test` / `deepseek-flash`다. 중복 요청은 캐시를 사용하고 자동 재시도·고가 모델 자동 전환은 하지 않는다. 사용자가 고품질 운영을 선택할 때 `CORA_LLM_TIER=quality`로 실행한다. 품질용 모델은 개인 llmgw의 `cora_quality` 경로에서 바꾼다. 기존 다른 프로젝트 경로와 키는 변경하지 않는다.
