# 실패 사례 체크리스트

보고·시연 전에 볼 것과, 실제로 겪은 고장의 원인·대처입니다.
**여기 적힌 것은 전부 실제로 한 번씩 터진 것**입니다. 추측이 아닙니다.

---

| | 할 일 | 정상 |
|---|---|---|
| 1 | `https://trend-hub-wesa.onrender.com` 접속 | 50초 안에 뜸 (**첫 접속은 느린 게 정상**) |

한 화면이라도 안 뜨면 아래 B를 보세요.

## B. 증상별 대처 — 실제로 겪은 것

### B-1. 화면은 뜨는데 옛날 것이다

**2026-09-24에 실제로 이랬습니다.** 새 기능이 아무리 올려도 안 보였습니다.

원인은 **브랜치**입니다. 이 저장소의 브랜치는 `master` 인데 Render 기본값은 `main`
입니다. 교수님 저장소에는 옛 `main` 이 따로 있어서, Render 가 그걸 계속 배포했습니다.

**확인** — Render 배포 로그 첫 줄
```
Checking out commit XXXX in branch master   ← master 여야 함
```

**조치** — Settings → Branch 를 `master` 로. 그리고 Auto-Deploy 가 `Yes` 인지 확인.
`No` 면 push 해도 안 올라갑니다.

### B-2. 떴다가 바로 죽고, 계속 재시작한다

로그에 이것이 보이면 메모리 부족입니다.
```
FATAL ERROR: Reached heap limit - JavaScript heap out of memory
Aborted (core dumped)
```

**B-1 과 같은 원인이었습니다.** 옛 `main` 코드가 무거워서 무료 플랜(heap 약 260MB)을
넘겼습니다. 지금 `master` 코드는 같은 조건에서 동시 요청 40개를 받아도 안 죽는 것을
확인했습니다. **브랜치를 고치면 이것도 같이 해결됩니다.**

### B-3. 수집 단추가 잠겨 있다

**고장이 아닙니다.** 하루 한도를 다 쓴 것입니다. 단추 아래에 이유가 적혀 있습니다.

- `이 분야는 오늘 3회를 다 썼습니다 — 다른 축은 아직 N회` → **다른 분야를 누르면 됩니다**
- `오늘 전체 한도를 다 썼습니다` → 한국시간 자정까지 기다리거나
  `설정 → 수집 상한` 에서 숫자를 올립니다

### B-4. 사진이 없는 카드가 많다

틱톡 사진 주소는 **서명이 붙어 있어 며칠이면 전부 만료**됩니다. 깨진 그림 대신
사진 자리를 없애는 게 설계된 동작입니다.

**보고 당일 아침에 `밈 발굴` 을 한 번 돌리면 채워집니다.** 미리 돌려 두면 그때 또
만료돼 있으니 **당일에** 돌리세요.

유튜브 사진은 만료되지 않습니다. 회차를 돌릴수록 사진이 남는 카드가 늘어납니다.

### B-5. 교수님 저장소에 push 가 404 난다

```
remote: Repository not found.
```

저장소가 없는 게 아니라 **자격증명이 다른 계정**입니다. Git 자격증명 관리자가
호스트 단위로 계정을 기억해서, 사장님 계정으로 비공개 저장소를 보려 하기 때문입니다.

**조치** — 명령마다 플래그를 붙입니다.
```powershell
git -c credential.useHttpPath=true push prof master
git -c credential.useHttpPath=true ls-remote prof master
```
이 설정을 저장소에 박으면 **`origin` 접근이 깨집니다.** 명령 한 번에만 붙이세요.

### B-6. 소급 스크립트가 "0장 판정" 으로 끝난다

`tests/_*.ts` 는 Next 를 거치지 않아 **`.env.local` 이 저절로 안 읽힙니다.**
API 키가 없으니 인증 오류가 나는데, `scoreThumbs` 가 그 오류를 삼켜서
"한 장도 판정 못 함" 으로만 보입니다. CDN 만료로 오해하기 쉽습니다.

**조치**
```powershell
npx tsx --env-file=.env.local tests/이름.ts --go
```

### B-7. 로컬에서 `npm start` 가 안 뜬다

`next start` 는 `PORT` 를 읽습니다. 로컬에서 3100 으로 띄우시려면
```powershell
npm.cmd run start:local
```

## C. 이미 고쳤지만 원리를 알아두실 것

| 무엇 | 왜 생겼나 |
|---|---|
| **유튜브 썸네일 229장이 404** | API 가 주는 `fhd` 단을 믿고 골랐는데 그 주소가 서지 않았습니다. 표본 40장 전수 404. `maxres` 로 갈아 끼웠습니다 |
| **재정규화가 추적 근거를 지움** | `다시 판정` 을 누르면 저장된 원본으로 후보를 새로 세우는데, 추적이 주워 온 기사는 원본에 없어 사라졌습니다. 칸라이언즈 근거가 13건 → 8건이 됐었습니다 |
| **같은 유행이 두 줄로** | `BAD 챌린지` 와 `배드 챌린지` 가 따로 앉았습니다. 회차를 건너뛰며 생겨서, 이제 표에 있는 이름까지 같이 보고 묶습니다 |
| **사진이 전부 잘림** | 틀 높이가 126px 로 박혀 있어 2.78:1 이었는데 들어오는 사진이 전부 그보다 세로로 길었습니다. 16:9 로 바꾸고 안 자르게 했습니다 |

## D. 아직 안 고친 것 — 물어보시면 이렇게 답하세요

### D-1. 자동 수집이 한 번도 안 돌았습니다

회차 31건 중 `automatic` 이 **0건**입니다. 워크플로우와 일정 화면과 자동 상한까지
다 있는데 실제로 돈 적이 없습니다.

원인은 셋 중 하나입니다. GitHub → Actions 탭을 보면 나옵니다.
- GitHub Secrets 에 `TREND_HUB_URL` · `CRON_SECRET` 이 없음
- 배포본이 옛 코드라 30분마다 실패하고 있었음 (**B-1 때문일 가능성이 큽니다**)
- 워크플로우가 꺼져 있음

**말씀드릴 때** — "수동 수집은 검증됐고, 자동 수집 배선은 배포가 정상화된 다음
확인합니다" 가 사실에 맞습니다.

### D-2. 눌러 본 것이 재배포하면 사라집니다

무료 플랜은 디스크를 못 붙여서 `data/db.json` 을 저장소에 담아 들고 갑니다.
**재배포하면 커밋된 상태로 돌아갑니다.** 교수님이 눌러 두신 `추적 중` 이 사라집니다.

유료 플랜 + 영속 디스크로 옮기거나, "배포본은 읽기 중심 데모" 로 선을 긋거나
둘 중 하나를 정해야 합니다. **피드백 받으며 고도화하려면 먼저 정해야 합니다.**

### D-3. 인스타 수집량이 적습니다

TikHub 의 인스타 검색이 **호출당 12건에서 고정**입니다. 20건을 달라 해도 12건입니다.
틱톡은 같은 조건에서 17~20건입니다. 우리 코드 문제가 아니라 그쪽 한계입니다.

### D-4. 권리 판정에 오판이 있습니다

`권리 분쟁 2건` 중 `C.C.`(코드기아스)는 실은 기업 IP 입니다. 근거가 된 게시물 하나가
다이소 콜라보 굿즈와 무관한 다른 창작자 영상을 같이 다뤄서, 판정기가 둘을 섞어
읽었습니다. **안전한 쪽으로 틀린 오판**이라 제작으로 넘어가지는 않습니다.

### D-5. 레이더가 배포본에 없습니다

별도 파이썬 앱이 남긴 파일을 읽는 판정기라 이 서버에는 폴더가 없습니다.
**쌓인 레이더 후보 6건은 목록에 그대로 보입니다.** 새 회차만 못 돌립니다.
레이더를 어딘가 띄우고 `RADAR_BASE` 를 넣으면 살아납니다.

## E. 검증 명령

```powershell
npm.cmd test                                   # 252개 통과
npx.cmd tsc --noEmit --incremental false       # 타입 검사
npm.cmd run build                              # 프로덕션 빌드 (개발 서버 내리고)
```

빌드는 개발 서버와 `.next` 를 공유합니다. **개발 서버를 내리고** 돌리세요.
