## 1. 방향 전환 요약

기존: 캐릭터 발굴 + 권리 판정 + 카드뉴스/포스터 생성을 한 앱에서.
변경: **트렌드 분석기로 역할을 축소하고, 카드뉴스 생성은 별도 에이전트에 넘긴다.**

```
사용자 ↔ 카드뉴스 Agent (타인 개발, 채팅형)
          └─ 내부적으로 트렌드 분석기 호출
              └─ 이미지 + 내용 반환 → 상대가 대본·템플릿 처리
```

트렌드 분석기의 역할은 둘뿐이다.

- 다른 에이전트의 **앞 퍼널** (계약 JSON 반환)
- **트렌드 자체 분석** (사람이 읽는 줄글)

두 출구가 같은 재료를 쓴다. 줄글은 수집한 본문의 요약이다.

### 범위 변경

| 항목 | 변경 |
|---|---|
| 대상 | 캐릭터 · 밈(그림/글자)으로 좁힘 |
| 소스 축 | **YouTube 중심.** TikTok·쇼츠는 활용 사례로 |

## P1. 계약 JSON 정의 (최우선)

카드뉴스 Agent 개발자가 이것 없이는 작업을 시작할 수 없다.
**내용이 비어 있어도 형식만 먼저 고정하면 상대가 병렬로 개발한다.**

### 상대 개발자의 요구사항 (원문)

> 트렌드분석으로 받을 거는 이미지랑 관련 내용입니다. 그걸 받으면 제가 내부적으로 대본 짜고 템플릿에서 정해진 자리에 이미지 넣고 할 거 같아요.

→ **대본은 상대가 쓴다.** 우리는 원재료만 넘긴다. 카드 문구를 만들지 말 것.

### 초안

```json
{
  "scope": "issue | character | meme",
  "query": { "field": "사용자가 고른 분야", "sources": ["youtube", "news"] },
  "topics": [
    {
      "title": "...",
      "summary": "수집한 본문들의 요약 (줄글 출력과 같은 값)",
      "why_now": "CU 편의점 신상 별사탕 2탄 출시",
      "images": [
        { "role": "evidence", "type": "thumbnail", "url": "", "source_url": "", "platform": "youtube" },
        { "role": "material", "type": "generated", "url": "", "prompt": "" }
      ],
      "metrics": { "views": 0, "trend": [] }
    }
  ],
  "note": ""
}
```

- `role`: `evidence`는 실제 원본(증거), `material`은 생성물(카드에 얹을 소재). 상대가 템플릿 배치를 판단하는 데 필요하다
- `summary`: 줄글 출력과 같은 값. 재료 하나에 출구 둘
- `topics` 개수는 **0~3 가변**. 범위 밖이거나 근거가 부족하면 적게 반환하고 `note`에 이유를 쓴다. 3안을 억지로 채우지 않는다

- 저장은 `public/` 아래 등 정적 서빙 경로에. 계약 JSON에는 URL을 싣는다 (base64 금지, 로컬 절대경로 금지)
- API 키는 환경변수. 학생 개별 발급 예정

**논의 체크포인트:** 4-1 후 프롬프트가 실제로 채워지는지 확인하고 보고. 4-2가 3100 밖이면 반드시 멈춘다.

## P5. 시간축 — YouTube 소급 백필

YouTube는 영상에 게시일이 박혀 있고 과거 검색이 된다.
**후보를 오늘 처음 발견해도 6개월치 곡선이 즉시 나온다.** 회차 누적을 기다릴 필요가 없다.

```
후보 이름 → YouTube 과거 검색 → 영상별 게시일 + 조회수 → 시점 분포
```

- P0-6에서 과거 검색이 불가하면 멈추고 논의
- 소급으로 만든 선은 관측한 선이 아니다. **추정 구간과 실측 구간을 시각적으로 구분**할 것 (점선/실선). 나중에 실측이 붙을 때 선이 튀는 것을 막는다
- `lib/core/trend.ts`의 기존 시계열 로직을 대체하지 말고, 백필 결과를 추가 입력으로 넣는다

**논의 체크포인트:** 백필 쿼리 방식과 기존 trend.ts와의 결합 방식을 먼저 제안.

## P6. 이슈 / 캐릭터·밈 분기

### 6-1. 파이프라인 분리

> **[코드 확인] 3100 에서는 이미 분리돼 있다.** RSS 수집은 `lib/discoveries/news.ts` 전용이고
> 캐릭터 경로(`character-native.ts`)와 코드를 공유하지 않는다. 떼어낼 것이 없다.
> 아래에서 예상한 부수 효과도 3100 에는 해당하지 않는다 — 그 노이즈('한동훈' 등)는 8420 에서
> 관측된 것이고 8420 은 이번 범위 밖이다. **6-2 만 남는다.**

저널 채널 8개를 캐릭터·밈 경로에서 떼어낸다.

부수 효과: 8420에서 관측된 노이즈('한동훈', 'l을가져가' 등이 캐릭터 카드로 올라온 문제)가 이 분리로 상당 부분 해소될 가능성이 있다. 저널 소스가 캐릭터 경로로 흘러들고 있었다면 그 자체가 원인이다. P0-3에서 확인할 것.

### 6-2. 입력 분류

사용자가 소스를 직접 고르면 그것을 따른다. 고르지 않았거나 채팅 문장으로 들어오면 분류한다.

```
입력 → 분류 → issue      (저널 8채널)
            → character  (YouTube 중심 + TikTok·쇼츠 사례)
            → meme
            → 복수 가능
```

- LLM 호출 1회로 충분하다. 무겁게 만들지 말 것
- **출력에 어느 쪽이 돌았는지 표시**한다 (`scope`). 분류가 틀렸을 때 사용자가 알아채고 다시 물을 수 있어야 한다
- **배타 선택을 강제하지 말 것.** "요즘 뜨는 밈 이슈" 같은 입력은 양쪽에 걸린다

**논의 체크포인트:** 분류 기준과 프롬프트를 먼저 제안.

## 3. 진행 순서

```
P0  조사 (수정 없음)          ← 전부의 선행
P1  계약 JSON                 ← 상대 개발자를 막고 있음. 최우선
P2  레코드 분리               ← P3·P5 의 전제
P3  held 해제 + 표시 정리
P4  생성 이미지 (4-1 → 4-2 → 4-3 순서 엄수)
P5  시간축 백필
P6  이슈/캐릭터 분기
```

각 단계 종료 시 보고하고 멈춘다.

> **[코드 확인]** 순서는 그대로다. 단 P0 는 끝났고, P3·P4·P6 의 **내용**이 0-1장에서 바뀌었다.
> 특히 **P4 는 4-1 만 남는다** (4-2 는 할 일 없음, 4-3 은 결정 사항).

## 4. 완료 기준

- 계약 JSON으로 이미지(원본+생성)와 본문 요약이 반환된다
- 같은 재료로 사람이 읽는 줄글이 나온다
- 카드뉴스·포스터가 held가 아니다
- 후보 하나에 시간 변화가 그려진다
- 이슈와 캐릭터·밈이 각각 실행된다

## 5. 판단이 필요한 미해결 항목

구현하지 말고, 해당 지점에 오면 보고할 것.

### `visual_grounded` 게이트

현재 `source_grounded`이지만 `visual_grounded`가 아니면 `none`으로 떨어진다. 개인 창작자 5명이 여기 걸려 있다.

이것은 **저작권 장치가 아니라 근거 부족 장치다.** 캡션에 색·형태·비율이 없을 때 AI가 외형을 지어내지 않게 막는다. 교육 목적이어도 없는 정보를 만들어내는 문제는 그대로 남는다.

- 게이트를 없애는 것이 아니라 **입력을 넓히는 쪽**을 검토한다. YouTube 썸네일·영상 설명이 들어오면 캡션보다 외형 단서가 많을 수 있다
- 자동으로 완화하지 말 것

### 트렌드 레이더 형식

P1의 계약 JSON 필드명이 여기 맞춰져야 한다. 형식 확보 전까지 필드명 확정 보류.

### 저널 채널 8개의 위치

P0-3의 결과에 따라 P6-1의 작업 형태가 달라진다.
