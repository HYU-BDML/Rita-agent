## 2. 무엇을 만드나

**한 문장** — 뜨는 소재가 아니라, 그 소재들이 공통으로 쓰는 **방식**을 보여준다.

이유: 캐릭터 73건 중 52건(71%)이 기업 IP다. 소재를 보여주면 "이건 못 씁니다"로 끝난다.
형식·아이디어는 저작권 보호 대상이 아니므로 **방식은 그대로 쓸 수 있다.** 막다른 길이 출구가 된다.

**출력 단위** 후보 188건 목록 → 방식 12개
**입력** 사용자가 가진 것 3개 토글 (실물 / 영상 / 오프라인) — LLM 호출 없는 결정적 필터
**한 방식이 주는 것** 이름 · 한 줄 설명 · 근거 소재(원문 링크) · 만드는 순서 · 사용 범위 3단

방식 12개의 확정 목록·근거·분류 규칙은 **`docs/grammars.md`** 에 있다. 여기 옮겨 적지 않는다.

## 3. 하면 안 되는 것

1. **판정기 메모를 사용자에게 보여주지 않는다.** `"공식 레퍼런스 확보 후"`, `"제작 보류"`, `"독립 출처가 부족함"` 류는 내부용이다. 화면에 낼 문장이 없으면 그 카드를 빼는 게 맞다.
2. **"안전합니다"라고 쓰지 않는다.** 권리자·문의처·확인이 필요한 구간까지만 말한다. 법률 자문이 아니다.
3. **조회당 LLM 호출을 만들지 않는다.** 배포본에 로그인이 없어 비용 천장이 사라진다(`render.yaml` 주석 참고). 토글 필터는 순수 계산으로 한다.
4. **근거 2건은 서로 다른 게시물 2건을 뜻한다.** 후보 2건이 아니다. 한 게시물에서 캐릭터 여러 개를 뽑으면 후보는 늘지만 근거는 하나다. (`이름 놀이`가 이렇게 잘못 만들어져 탈락했다.)
5. 수집·설정·회차 UI를 첫 화면에 두지 않는다.
6. 수집 파이프라인(`lib/collect/*`, `lib/discoveries/*`)은 건드리지 않는다. 이번 작업은 **읽기 쪽만**이다.

## 4. 작업 단위

### 세션 1 — 신선도 계산

`lib/core/series.ts` 에 함수 하나 추가.

```
freshness(posts, asOf) → number | null
  postedAt 이 최근 30일 이내인 게시물의 비중(%)
  게시물 10건 미만이면 null (모른다는 뜻, 0 이 아니다)
```

왜 필요한가: 지금 캐릭터 축에는 급등 신호가 없다. `구간·규모·기울기`는 radar 12건에만 있고,
캐릭터는 관측일 수로 대체돼 있는데 그건 **유명도 대리지표**다(코난 5일 관측·신선도 34%,
짱구 5일 관측·신선도 92%). 신선도를 넣어야 둘이 갈린다.

**수용 문장** — `freshness()` 가 짱구 92%, 코난 34%, 리락쿠마 33% 를 낸다. 게시물 10건 미만인 후보는 null 을 낸다.

### 세션 2 — 방식 정의와 근거 결박

`lib/core/grammar.ts` 신설. 방식은 느리게 변하므로 **정적 정의**로 둔다.

```ts
interface Grammar {
  id: string
  name: string                                  // 짧게. docs/grammars.md 참고
  kind: 'video' | 'copy' | 'info' | 'compare'   // 산출 틀을 결정
  need: { physical: boolean; video: boolean; offline: boolean }
  desc: string
  match: RegExp                                 // candidate.hint.angle / subject 대조
}
```

근거는 런타임에 후보를 `match` 해서 붙인다. 붙일 때 규칙:
- 같은 게시물 URL은 1건으로 센다
- **고유 출처 2건 미만이면 그 방식은 화면에서 뺀다**
- `angle` 이 판정 메모뿐인 후보는 근거에서 제외한다 (3절 1번)

12개의 이름·kind·need·match 규칙은 `docs/grammars.md` 에 있다.

**수용 문장** — `grammarsWithEvidence()` 가 12개를 내고, 각각 고유 출처가 2건 이상이며,
근거에 판정 메모 문장이 하나도 섞이지 않는다.

### 세션 3 — 첫 화면

`app/page.tsx` 를 방식 중심으로 바꾼다. **지금 UI 톤(남색 `#1B1B3A` / 보라 `#6C5CE0` / 흰 카드)을 그대로 쓴다.**

**먼저 `docs/ui/01-home-default.png` 과 `docs/ui/01-home-default.html` 을 본다** (4.5절).

구성, 위에서 아래로:
1. 한 문장 + 한 줄 부연
2. 핵심 흐름 3칸 — ① 가진 것을 켠다 ② 방식을 고른다 ③ 그대로 만든다 (각 칸에 한 줄 설명)
3. 가진 것 토글 3개
4. 지금 할 수 있는 방식 **카드 3장** — 이름을 카드에서 제일 크게. 근거는 1건만
5. 다른 방식은 **이름 칩**으로 한 줄에. 못 하는 건 흐리게 + `실물 필요` 같은 이유
6. 전체 보기 링크

카드 높이는 고정한다(지금 그리드가 어긋나는 원인).
기존 목록 화면은 지우지 말고 `/explore` 로 옮긴다.

**수용 문장** — 처음 연 사람이 스크롤 없이 한 문장·흐름 3칸·방식 3장을 보고, 토글을 눌러
카드가 바뀌는 것을 확인할 수 있다. 판정기 버튼과 설정은 첫 화면에 없다.

### 세션 4 — 방식 상세

**먼저 `docs/ui/03-grammar-detail.png` 과 같은 이름의 `.html` 을 본다** (4.5절).

`app/grammars/[id]/page.tsx` 신설. **화면은 하나, `kind` 에 따라 산출 틀 블록만 바뀐다.**
(화면을 4개 만들지 않는다 — 지금 라우트가 이미 8개고 그게 복잡함의 원인이다.)

```
video   → 첫 3초 / 장면 흐름 / 길이      (brief.ts 의 BriefVideoAnalysis 활용)
copy    → 문구 골격 / 피할 표현
info    → 채울 항목 체크리스트
compare → 비교축 / 항목 수
```

그리고 **사용 범위 3단**을 함께 낸다.
```
방식 자체        형식은 저작권 보호 대상이 아님 — 그대로 사용 가능
근거 소재를 쓸 때  과제·발표        저작권법 제25조로 대체로 가능(학교가 수업목적 보상금 납부, 일부만)
                개인 공개 계정   공중송신이라 예외 밖 — 권리자 확인 필요
                브랜드·상업      라이선스 필요
```

**수용 문장** — `kind` 가 다른 방식 두 개를 열면 산출 틀 블록의 내용이 서로 다르고,
사용 범위 3단이 두 화면 모두에 나온다.

### 이번 UI 변경에서 **꼭** 지켜야 하는 것

1. **방식 이름이 카드에서 제일 크다** (30px / 700 / letter-spacing -0.8px).
   이름이 이 제품의 상품이다. 지금 배포본처럼 세 번째로 큰 요소가 되면 안 된다.
2. **카드 높이를 고정한다** (300px). 지금 배포본은 썸네일 없는 카드에 빈 공간이 생겨 그리드가 어긋난다.
3. **못 하는 방식도 이름 칩으로 보여준다.** 흐리게 + `실물 필요` 같은 이유를 붙인다.
   숨기면 범위가 안 보여서 토글을 누를 이유가 생기지 않는다.
4. 카드 본문은 **사람 말**로 쓴다. `계정 17곳이 따라 했습니다` 처럼.
   판정기 문장(`독립 출처가 부족함`)을 그대로 내보내지 않는다.
5. 상단바는 `이번 주 방식 · 담은 것 · 지난 주` 세 개로 줄인다. 설정·회차는 첫 화면에서 내린다.

### 그림 속 문구는 확정이 아니다

히어로 한 문장, 흐름 3칸 설명, 방식 이름과 한 줄 설명 — 전부 초안이다. 6절을 따른다.
**구조와 위계는 그대로 가져가고, 문구는 자리만 잡은 뒤 사용자 확인을 받는다.**

## 6. 미확정 — 사람이 정할 것 (임의로 확정하지 말 것)

1. **화면 문구 전부.** 히어로 한 문장, 흐름 3칸 설명, 방식 12개의 이름과 한 줄 설명.
   지금 문서·목업에 있는 문구는 **초안이고 확정이 아니다.** 구현할 때 자리만 잡고,
   문구는 사용자 확인을 받는다.
2. `2차 창작` 방식을 남길지. 고유 출처 3건 중 둘이 판정 메모에서 나왔다. 뺄 수도 있다(그러면 11개).
3. 정렬 기준. 신선도 단독으로 하면 `자캐 공개`(신선도 22%, 권리 걸림이 없는 유일한 방식)가
   맨 아래로 간다. 실행 가능한 것 우선 → 그 안에서 신선도, 를 임시안으로 둔다.

## 7. 이번 작업 범위 밖 (알고만 있을 것)

- **Render 무료 플랜은 디스크를 못 붙인다. 재배포하면 db.json 이 커밋된 상태로 되돌아간다.**
  자동 수집이 돌아도 남지 않는다. 별도 작업으로 고쳐야 한다(수집을 CI 로 옮기고 db.json 을 커밋).
- `snapshots` 가 db.json 의 55%다. `data/snapshots/<runId>.json` 으로 분리하면 db.json 이 4.3MB 로 준다.
- GitHub Actions 가 30분마다 돈다. 방식은 느리게 변하므로 주 1회로 충분하다.
