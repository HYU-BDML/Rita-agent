# Trend Hub 개발 인수인계 프롬프트 (2026-09-22)

아래 내용을 다음 코딩 에이전트에게 그대로 전달한다.

---

이 프로젝트는 GitHub Copilot Agent에서 Codex로 이어서 개발한 Trend Hub다. 현재 작업물을 섣불리 다시 작성하거나 초기화하지 말고, 먼저 `git status`, `git diff`, 디렉터리 구조와 아래 파일을 읽어 현재 구현을 역추적하라. 작업 트리는 의도적으로 많은 수정·미추적 파일과 실제 수집 데이터 변경을 포함한다. **`git reset --hard`, `git checkout --`, 광범위한 되돌리기, 기존 변경 덮어쓰기를 하지 마라.**

## 1. 현재 제품 방향

제품의 메인 진입점을 기존의 단순 리다이렉트에서 **검색 중심 탐색 화면**으로 바꾸는 방향이다.

- 사용자는 홈에서 직접 후보를 검색한다.
- 홈에는 자동 수집된 추천 후보도 함께 표시한다.
- 후보를 `보관하고 추적하기` 하면 주 추적 대상이 된다.
- 기존 `오늘의 소재`는 사라지는 것이 아니라 탐색 화면에서 연결되는 하위 축/탭으로 유지한다.
- 상단 정보 구조의 목표는 `탐색 / 추적 중 / 수집 기록 / 설정`이다.
- 현재의 짧은 일정에서는 외부 플랫폼 실시간 검색까지 만들지 않고, 이미 수집된 데이터에 대한 로컬 검색과 추천으로 MVP를 구성했다.

중요한 제품 원칙:

- 검색 입력 때마다 유료 외부 수집 API를 호출하지 않는다.
- 로컬 결과를 먼저 보여주고, 이후 별도 버튼으로 외부 확장 검색을 명시적으로 실행하는 2단 구조가 적합하다.
- 외부 검색은 비동기 작업으로 만들고 진행 상태, 예상 비용/호출량, 실패 이유를 보여줘야 한다.
- 추천은 자동 수집 파이프라인의 기존 후보를 사용하고, 검색 결과와 자동 추천을 시각적으로 구분한다.
- `보관`의 의미는 단순 즐겨찾기가 아니라 지속 추적 등록이다.

## 2. 이번 작업에서 구현한 것

### 검색 중심 홈 MVP

- `app/page.tsx`
  - `/`를 더 이상 `/issues`로 리다이렉트하지 않는다.
  - `q` GET 파라미터로 저장된 후보를 검색한다.
  - 검색 대상은 제목, 지금 뜨는 이유, 요약, 근거 제목/본문이다.
  - `axis=all|issue|character|meme` 필터를 지원한다.
  - 검색어가 없으면 최신 후보를 축별로 번갈아 섞어 최대 12개 추천한다.
  - 검색어가 있으면 관련도와 최신순으로 정렬해 최대 24개를 보여준다.
  - 외부 실시간 검색이 아니라 현재 수집 데이터 검색임을 화면에 명시했다.
  - 기존 `오늘의 소재`, 캐릭터, 유형/포맷 페이지 링크를 유지했다.

### 탐색 → 추적 UX 연결

- `components/nav.tsx`
  - 첫 메뉴를 `탐색`(`/`)으로 변경했다.
  - `보관함` 명칭을 `추적 중`으로 변경했다.
- `components/archive-button.tsx`
  - 활성 후보 버튼 문구를 `보관하고 추적하기`로 변경했다.
  - 보관 후보 버튼 문구를 `추적 중지`로 변경했다.
  - 확인 모달 문구도 추적 의미에 맞췄다.
- `lib/core/store.ts`
  - 후보를 archived로 전환할 때 `tracking.enabled = true`가 되도록 연결했다.
  - 기존 tracking query가 있으면 보존하고, 없으면 후보 제목을 기본 query로 사용한다.
- `app/library/page.tsx`, `components/library-list.tsx`
  - 화면 명칭과 빈 상태 문구를 `추적 중` 관점으로 정리했다.
  - 빈 목록의 CTA는 홈 탐색으로 이동한다.
- `app/characters/page.tsx`
  - archived 캐릭터가 활성 목록에도 중복 표시되던 문제를 수정했다.

현재 의미상 `archived`가 곧 추적 목록이다. 추후에는 lifecycle과 tracking 상태를 분리하는 모델 개선을 검토해야 한다. 현재 추적 cron이 archived 후보만 처리하므로, 추적 중지를 위해 active로 복구하면 cron 대상에서도 빠진다.

### 이미지 UX

- `lib/core/candidate-images.ts`
  - 뉴스: 근거 기사 대표 이미지 1장.
  - 캐릭터: `charShot` 점수가 가장 높은 대표 이미지 1장. 동점이면 최신 게시물 우선.
  - 유형/포맷: 최신 실제 게시물 썸네일 최대 3장.
- `components/linked-image-grid.tsx`
  - 이미지를 누르면 원본 게시물/기사로 이동한다.
  - 외부 이미지 로딩 실패 시 해당 이미지 영역을 제거해 기존 텍스트 UI로 자연스럽게 폴백한다.
  - hydration 이전에 실패한 이미지도 `naturalWidth`로 감지한다.
- `components/card.tsx`
  - 뉴스와 캐릭터 대표 이미지를 같은 풀폭 상단 비율 구조로 표시한다.
  - 이미지가 없는 기존 데이터는 종전 텍스트 카드 구조를 유지한다.
- `components/thumb-card.tsx`, `app/candidates/[id]/page.tsx`, `app/characters/page.tsx`, `app/memes/page.tsx`
  - 목록/상세 이미지 표시와 원문 링크를 연결했다.
- `tests/candidate-images.test.ts`
  - 뉴스 1장, 캐릭터 charShot 최고점 1장, 포맷 최신 3장 선택을 검증한다.

## 3. 현재 데이터와 수집 상태

최근 확인 기준 `data/db.json`에는 대략 다음이 들어 있다.

- candidates 176
- products 15
- runs 27
- snapshots 27
- posts 1713
- news active 77 / archived 1
- radar active 6
- meme-native active 24
- character-native active 66 / archived 2

뉴스 수집과 썸네일 저장은 실제로 동작했다. 샌드박스 내부 서버에서는 외부 RSS 접근이 막혀 한 차례 0건으로 끝났지만, 네트워크 접근 가능한 로컬 프로세스로 다시 띄운 뒤 성공했다. 성공한 예시 실행 `news-20260921T220240`은 12개 후보(11 추가, 1 갱신)를 만들었고 12개 중 9개 후보에 썸네일이 있었다.

현재 로컬 서버는 Windows에서 Next 개발 서버를 3100 포트로 띄우는 방식이다. PowerShell 실행 정책 때문에 `npm` 대신 `npm.cmd`를 사용한다.

```powershell
npm.cmd run dev
```

Codex 샌드박스에서 실행하면 RSS 외부 연결이 실패할 수 있다. 수집을 검증할 때는 네트워크 가능한 로컬 환경에서 실행해야 한다.

## 4. 검증 상태

이번 MVP 반영 후 확인한 결과:

- `npm.cmd test`: **211개 통과, 실패 0**
- `npx.cmd tsc --noEmit --incremental false`: 통과
- `git diff --check`: 오류 없음. LF/CRLF 경고만 있음.
- HTTP 확인:
  - `/`: 200, 탐색/추천/추적 UI 확인
  - `/?q=치이카와`: 200, 검색 결과 확인
- 이미지 UX 작업 직후 `npm.cmd run build`도 통과했으나, 검색 홈 MVP 변경 후에는 실행 중 개발 서버와 `.next` 충돌을 피하려고 전체 build를 다시 돌리지 않았다. 다음 안전한 시점에 개발 서버를 내리고 build를 한 번 더 확인할 것.

권장 검증 명령:

```powershell
npm.cmd test
npx.cmd tsc --noEmit --incremental false
npm.cmd run build
```

## 6. 보고 직전 우선순위

### P0: 데모 안정화

1. 홈 검색, 축 필터, 추천 카드, 상세 이동을 브라우저에서 확인한다.
2. 후보 하나를 `보관하고 추적하기` → `/library`에 나타남 → `추적 중지`까지 왕복 확인한다.
3. 뉴스/캐릭터/포맷 각각 이미지가 있는 카드와 이미지가 없는 카드의 폴백을 확인한다.
4. 외부 이미지 URL 만료 때문에 포맷 썸네일이 깨질 수 있다. 보고 직전에 새 수집을 돌리거나, 폴백이 정상인지 확인한다.
5. 개발 서버를 내릴 수 있는 시점에 `npm.cmd run build`를 최종 1회 실행한다.

보고할 때는 다음처럼 설명하면 된다.

> 메인 화면을 수동 검색과 자동 추천이 공존하는 탐색 허브로 전환했습니다. 지금은 이미 수집된 후보를 빠르게 검색하고, 선택한 후보를 바로 지속 추적 대상으로 등록할 수 있습니다. 뉴스·캐릭터·유형별 대표 이미지 규칙도 통일했고, 이미지가 없는 과거 데이터는 기존 UI를 유지합니다. 외부 플랫폼 실시간 검색과 추적 변화 알림은 다음 단계입니다.

## 7. 보고 후 개발 계획

### P1: 실제 외부 검색

1. 검색창 입력 중에는 로컬 검색만 수행한다.
2. 로컬 결과 하단에 `외부에서 더 찾기` 버튼을 둔다.
3. 버튼을 눌렀을 때만 검색 job을 만든다.
4. 서버는 검색어를 뉴스/캐릭터/포맷용 query로 확장한다.
5. 진행률, 플랫폼별 상태, 실패 원인, 예상/실제 호출량을 저장한다.
6. 새 후보는 기존 후보와 중복 제거 후 같은 카드 계약으로 반환한다.
7. 완료된 검색은 재사용하고 동일 query의 짧은 시간 내 재호출을 막는다.

### P1: 추적 기능 고도화

- 추적 대상별 마지막 확인 시각, 새 근거 수, 변화량, 상태를 보여준다.
- 신규 게시물/기사, 확산 속도 변화, 안전/권리 상태 변경을 이벤트로 기록한다.
- 사용자가 추적 주기와 검색 query를 편집할 수 있게 한다.
- 단순 archived lifecycle과 tracking subscription을 별도 필드/상태로 분리한다.
- 추적 결과의 `새 소식 있음` 배지와 변화 요약을 `/library`에 추가한다.

### P1: 이미지 신뢰성

- 캐릭터 자동 수집 단계에서 `charShot`을 자동 계산/저장한다. 현재는 과거 backfill 스크립트 의존 부분이 있다.
- TikTok/Instagram/X의 서명된 썸네일 URL은 만료된다. 장기적으로는 허용 범위 내 미디어 프록시/캐시 또는 재수집 전략이 필요하다.
- 추적 cron에서 RSS로 새로 붙이는 근거의 `thumbnailUrl`이 유실되지 않게 보존한다.

### P2: 배포/운영 안정성

- `.github/workflows/trend-hub-collect.yml`을 고친다.
  - 중복된 `run: |`가 있다.
  - 바깥쪽 shell `if`가 닫히지 않은 것으로 보인다.
  - 일요일 비교에서 `date +%u`는 7인데 조건은 0을 쓰는 문제가 있다.
- `/api/discover` 직접 호출 인증을 추가한다. cron wrapper에 secret이 있어도 직접 endpoint를 열어두면 유료 수집이 노출된다.
- `upsertCandidate`/재정규화에서 기존 `tracking` 필드가 유실되지 않게 한다. 현재 review 계열은 보존하지만 tracking 보존이 불완전할 가능성이 있다.
- Render의 파일 기반 `data/db.json`은 재배포 시 유실될 수 있다. 운영 DB 또는 영속 디스크로 옮긴다.
- `render.yaml` 및 배포 환경 예시에 `CRON_SECRET`을 명시한다.
- `package.json`의 Windows용 `start` 명령에서 `${PORT:-3100}` 문법이 그대로 전달되는 문제를 고친다.
- README가 현재 화면/라우트/수집 구조와 어긋난 부분을 갱신한다.
- 사용되지 않는 pick 계열 컴포넌트와 오래된 코드의 실제 참조 여부를 확인한 뒤 정리한다.

## 8. 데이터 흐름 요약

```text
수동 실행/cron
  → /api/discover 또는 cron route
  → discovery별 수집기(news / character / meme / radar)
  → 외부 원문·게시물 수집
  → 이름/주제 추출 및 재검색
  → 계정 수·기간·원문 대조 검증
  → 요약·권리·안전 판정
  → 공통 Candidate/Post 모델로 정규화
  → data/db.json 저장
  → 홈 탐색·축별 목록·상세 화면
  → 보관하고 추적하기
  → archived + tracking.enabled
  → 추적 cron이 후속 근거 수집
```

유행 포맷 수집의 가장 큰 시간 병목은 후보별 TikTok 재검색을 순차 실행하는 부분이다. 현재 설명된 최적화 방향은 정확도를 유지하면서 재검색을 제한된 동시성으로 병렬화하고, 최대 후보 수를 줄이며, 이미 분석한 query를 캐시하고, 요약·안전 판정을 batch하는 것이다. 무제한 병렬화는 rate limit과 비용 문제가 있으므로 3~5개 정도의 제한된 동시성이 적절하다.

## 9. 다음 에이전트의 시작 절차

1. `git status --short`, `git diff --stat`, 주요 diff를 확인한다.
2. 변경 파일을 기존 작업과 이번 MVP 작업으로 구분하되 임의로 되돌리지 않는다.
3. 211개 테스트와 타입체크를 재확인한다.
4. 로컬 서버와 브라우저로 P0 데모 동선을 확인한다.
5. 사용자에게 `현재 상태 / 이미 구현된 것 / 미완성 / 문제점 / 다음 작업` 순서로 짧게 보고한다.
6. 보고 일정 전에는 외부 검색 같은 큰 기능을 새로 벌이지 말고 데모 안정성만 높인다.
7. 보고가 끝난 뒤 P1 외부 검색을 별도 설계·구현한다.

코드를 수정하기 전, 기존 구현을 존중하고 사용자가 요청한 범위만 변경하라.
