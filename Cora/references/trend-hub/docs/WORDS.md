## 4. 질문 두 개

```
1  뭘로 만들 거예요?              [ 영상 ]  [ 사진·카드뉴스 ]  [ 글만 ]
     안 고른 상태 오른쪽 : 고르지 않으면 전부 보여드립니다

2  소개할 물건이나 가게가 있나요?    [ 있어요 ]  [ 없어요 ]
     답하기 전 오른쪽 : N개 방식이 여기에 걸립니다
```

"가진 것" 이라는 말을 쓰지 않는다.

**카드 묶음 제목** — 질문 1의 답에 따라 바뀐다
```
안 고름          지금 할 수 있는 방식              12개 중 3개
영상             영상으로 만들 수 있는 방식          6개 중 3개
사진·카드뉴스      사진·카드뉴스로 만들 수 있는 방식    4개 중 3개
글만             글로 만들 수 있는 방식              2개 중 2개
```
`글만` 은 제목에서 `글` 로 쓴다. 개수는 데이터에서 채운다.

**질문 1을 바꾸면 질문 2의 답을 지운다.**
걸리는 방식 수가 kind 마다 달라서(영상 2개 · 글만 1개), 답이 남아 있으면
"N개 방식이 여기에 걸립니다" 를 못 보고 지나간다. 답한 적 없는 질문에 답이 들어가 있게 된다.

**고른 답을 다시 누르면 지워진다.** 되돌릴 길이 없으면 전체로 못 돌아간다. 문구는 늘지 않는다.

**"없어요" 안내 박스**
```
물건 없이 할 수 있는 {영상} 방식 {N}개를 골랐습니다
물건이 생기면 {굿즈깡 · 손 클로즈업} 도 열립니다.
```
중괄호는 데이터에서 채운다. 두 번째 줄에 훈계를 덧붙이지 않는다.

## 7. 브리프 구성

브리프는 **방식 하나 + 근거 한 건 + 숫자 두 줄**이다. 묶음을 나누지 않는다.

```
히어로                 §3 그대로
기준 줄                §18
이번 주 방식 하나        근거가 가장 많은 것. 동점이면 신선도 높은 쪽
그 방식의 근거 한 건      §19 컴포넌트. 최고 조회
숫자 두 줄              §18
이어 주는 한 줄 + 버튼    §18 · §10
```

전에 여기에 「지금 들어갈 것 / 지금 들어가면 늦은 것 / 안 건드리는 게 나은 것」 세 묶음이
있었다. 묶음을 셋으로 나누면 항목이 다섯 개 안팎 필요한데, 정점을 판정할 신호(매스미디어
등장·부정 반응)가 데이터에 없다. 없는 판정으로 묶음을 만들면 「안 건드리는 게 나은 것」에
무엇을 넣을지 사람이 정하게 된다.

## 11. 하단 한 줄

```
근거 {N}건 · 모두 서로 다른 출처 · {YYYY-MM-DD} 기준 · 관측 {N}일
```
중괄호는 데이터에서 채운다. **이 문서에 실제 수치를 적지 않는다** (§19 의 규칙과 같다).
**기준일을 빼지 않는다** — 최근 한 달 % 가 언제를 기준으로 잰 값인지 없으면 오늘 기준으로
읽힌다. 기준일은 `freshness` 에 넘긴 `asOf` 와 같은 날이다.

## 13-1. 상단바 라벨과 화면 제목은 같다

한 화면의 `h1` 은 상단바에 적힌 말과 글자까지 같아야 한다. 다르면 같은 곳인지 알 수 없다.

```
/library  상단바 담은 것   → h1 담은 것    (지금 '추적 중' 이다. 고친다)
/runs     상단바 지난 기록  → h1 지난 기록   (지금 '회차' 다. 고친다)
/explore  상단바 탐색      → h1 소재 전체 보기
          예외. 상단바는 짧게, 제목은 무엇을 보는 곳인지 풀어 쓴다
/grammars 상단바 방식      → h1 방식
```

## 16. 이 문서가 덮지 않는 것

아래는 그대로 둔다. 사용자 눈에 거의 닿지 않거나, 이번 작업 범위 밖이다.

```
API 오류 메시지            잘못된 요청입니다 / 판정기를 찾을 수 없습니다 …
설정 화면 (/settings)      키 넣는 법 · 연결 상태 …
축별 화면 내부 설명문        /issues /characters /memes 의 도움말 문단
카드뉴스 편집기             짜임 · 표지 · 인용 …
접근성 라벨                aria-label

지난 기록 (/runs) 본문      트렌드 레이더는 무엇을 하나요? · 저장된 원본으로 다시 판정 …
                          h1 만 §13-1 대로 고치고 본문은 그대로 둔다
운영자 컨트롤               find-button(판정기당 N회) · review-actions(이 후보를 어떻게 할까요)
                          archive-button(탐색 후보로 돌려놓습니다)
```

**§1 의 금지어는 사용자 화면에만 적용된다.** 운영자가 보는 자리에서는 `회차` `판정기`
`재판정` 이 오히려 정확한 말이다. 바꾸면 운영이 헷갈린다.

이 영역의 문구를 바꾸려면 따로 요청을 받는다. 임의로 손대지 않는다.

## 17. 소재 상세 — 세션 6 에서 쓸 문구 전부

### 머리

```
{소재 이름}                                      제일 큰 글자
{방식 이름}                                      칩
{플랫폼 목록} {N}건 · 계정 {N}곳 · 최근 한 달 {N}%
← {방식 이름}                                    되돌아가기
```
예 — `늙크크` `말투·유행어` `유튜브·틱톡·인스타·X 30건 · 계정 17곳 · 최근 한 달 100%`

### 지금 들어가면 늦습니다 (해당될 때만)

본문은 데이터에서 쓴다. 매스미디어 등장일, 부정 반응 인용, 각각 원문 링크.
**해당 없으면 섹션 자체를 내린다.** `아직 정점이 아닙니다` 같은 반대 문구를 만들지 않는다.
링크 이름: `라디오 원문` `반응 원문` — 무엇의 원문인지 한 낱말로 붙인다.

## 18. 브리프 (`/`) — 쓸 문구 전부

구성은 §7. 여기 있는 말이 그 화면에 나오는 전부다. 나머지는 데이터에서 나온다.

### 히어로 — §3 그대로

주차 · 한 문장 · 부연. **흐름 3칸은 여기 두지 않는다** — §3 이 그것을 「질문 위」에
두라고 했고 질문은 `/grammars` 에 있다. 질문 없는 화면에 흐름만 놓으면 다음에 무엇을
누를지 가리키지 않는다.

### 기준 줄 — 히어로 바로 아래

```
{기준일} 기준 · 관측 {N}일 · 근거 {M}건
```
§11 하단 한 줄과 같은 값을 맨 위에도 놓는다. 「최근 한 달 %」가 언제를 기준으로 잰
값인지 먼저 보이게 한다.

### 이번 주 방식 하나

```
{방식 이름}      제일 크게
{kind 배지}      §6
{한 줄}          §5
```
고르는 규칙은 근거 수, 동점이면 신선도 높은 쪽. **「이번 주 뜨는」·「추천」·「곧 뜰」을
쓰지 않는다** — 관측 기간이 예측을 말할 만큼 길지 않다.

### 그 방식의 근거 한 건 — §19 그대로

그 방식의 근거 중 최고 조회 한 건. 컴포넌트를 새로 만들지 않는다.

### 숫자 두 줄

```
이 방식 전체로는 계정 {N}곳이 같은 형식으로 올렸습니다
넷 중 하나는 {N}회를 넘지 못했습니다
```
앞줄에 **「이 방식 전체로는」을 붙인다.** 바로 위 근거 카드에도 「계정 {N}곳」이 있어서
그냥 두면 같은 낱말의 다른 값이 두 줄에 붙는다 — 카드는 그 소재 하나, 이 줄은 방식
전체다.

뒷줄은 그 방식 게시물 조회수의 하위 25% 다. 최고 조회 한 건만 보면 "이 방식은 천만이
나온다"로 읽히는데, 같은 방식으로 올린 넷 중 하나는 그 값을 넘지 못했다. **조회수가
붙은 게시물이 10건 미만이면 그 줄을 내린다** — 표본이 적을 때 나오는 사분위는 한 건만
달라도 크게 튄다.

### 이어 주는 한 줄과 버튼

```
넓게 퍼졌다는 건 경쟁자가 많다는 뜻이기도 합니다.
무엇으로 만들 수 있는지 골라 보세요

[ 방식 고르기 ]      → /grammars. §10
```

### 넣지 않는 것

```
방식 12개 목록          /grammars 의 것이다
만드는 순서             방식 상세의 것이다
주별 추이·기울기·상승/하락  수집이 과거 2주까지만 닿아 오래된 주가 무조건 낮게 나온다.
                       그리면 무엇이든 전부 상승으로 보인다
```

### 실을 것이 없을 때

근거가 하나도 없으면 §12 의 `근거가 아직 얇습니다` 만 낸다. 억지로 채우거나 얇은 방식을
끌어올리지 않는다.

## 19. 근거 카드 — 방식 상세의 「지금 이걸 하고 있는 것」

지금은 `{이름} / 계정 N곳이 따라 했습니다` 한 줄뿐이라, 읽어도 그게 뭔지 모른다.
**데이터에 썸네일과 캡션과 조회수가 다 있는데 쓰지 않고 있다.**

```
{소재 이름}                         최고 {조회} · 계정 {N}곳        [원문]
[썸네일 3장 가로]
"{대표 캡션}"
```

자리 표시만 둔다. **이 문서에 실제 수치를 적지 않는다** — db 가 계속 바뀐다.
권루트챌린지는 하룻밤에 게시물이 34건에서 48건으로 늘었고 최고 조회와 계정 수가 함께
움직였다. 문서에 숫자를 박아 두면 그 다음 날부터 문서가 틀린 값을 가리키고, 그걸 기준으로
맞춘 코드가 같이 틀린다. 값을 확인할 일이 있으면 `node -e` 로 db 를 조회한다.

### 규칙

1. **조회수를 뺐다가 다시 넣는다.** `계정 16곳` 보다 `최고 251만` 이 규모를 더 잘 말한다.
   둘은 다른 정보다. 둘 다 적는다. 조회수는 만 단위로 줄여 쓴다 (2,510,234 → 251만).
2. **썸네일을 쓴다.** 영상 첫 화면이라 한 장만 봐도 무엇인지 안다. 세 장까지.
   썸네일이 없는 소재는 그 줄을 비운다. 자리를 남기지 않는다.
3. **캡션은 소재 이름을 온전히 포함한 것 중에서 고른다.** 조회 상위 하나.
   느슨하게 찾으면 관계없는 글이 딸려온다 — `틱톡 성장 챌린지` 를 느슨하게 찾았더니
   "2022년 뇌절 밈 모음", "절대 잊을 수 없는 고양이들" 이 나왔다.
   온전히 포함한 캡션이 없으면 **캡션 줄을 비운다.** 지어내지 않는다.
4. 카드에 들어가는 모든 것이 데이터에서 나온다. 설명을 지어내지 않는다.
5. **저장된 게시물이 0건인 소재는 카드를 만들지 않고, 근거 수에도 세지 않는다.**
   원문 링크만 있고 게시물 레코드가 없으면 조회도 썸네일도 캡션도 못 낸다 — 「지금 이걸
   하고 있는 것」에 `계정 0곳` 이 앉아 뜻이 거꾸로 읽힌다. 하단 「근거 N건」이 화면의
   카드 수와 같아야 한다.
6. **이 문서에 실제 수치를 적지 않는다.** db 가 계속 바뀐다. 자리 표시만 둔다.

### 적용 범위

방식 상세(`/grammars/[id]`)의 근거 목록과, 브리프 항목의 근거 한 건에 같은 꼴을 쓴다.
소재 상세(§17)의 「어느 형식으로 갈까」 행에도 조회수를 같은 방식으로 줄여 쓴다.
