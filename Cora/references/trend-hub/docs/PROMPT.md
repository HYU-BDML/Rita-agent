## 0. 대전제 — 아무것도 버리지 않는다

지금 있는 화면과 기능은 **하나도 삭제하지 않는다.** 브리프는 위에 얹는 층이지 대체가 아니다.
기존 목록·축별 화면·소재 상세·계약 JSON·카드뉴스 생성기는 전부 자리를 유지한 채 정리만 한다.
"이건 버리고 다시"는 이 작업에서 금지다.

## 1. 층 구조

```
층 0  브리프 한 장     열면 이번 주가 파악된다. 요약과 추천        ← 새로 만든다
층 1  탐색            찾아보는 워크플로우. 축별 / 방식별 / 검색
층 2  소재 상세        어원·형식·만드는 순서·사용 범위
층 3  원문            외부 링크
```

각 층은 서로를 대체하지 않는다. 브리프에서 "이번 주엔 이거"를 받고, 더 보고 싶으면 탐색으로,
깊이 보고 싶으면 상세로, 확인하려면 원문으로 내려간다.

## 2. 라우트 — 삭제 0건

| 지금 | 어떻게 되나 |
|---|---|
| `app/page.tsx` 목록 | **`/explore` 로 옮겼다.** 내용 그대로. 지우지 않았다 |
| `/characters` `/issues` `/memes` | 그대로 유지. 축별 탐색 |
| `/candidates/[id]` | 그대로 유지 + 5절대로 강화 |
| `/library` `/runs` `/settings` | 그대로 유지 |
| 계약 JSON · 카드뉴스 생성기 | 그대로. 소재 상세에서 호출 |
| **`/` (새로)** | 브리프 한 장 |
| **`/grammars`, `/grammars/[id]` (새로)** | 방식별 탐색 |

상단바: `브리프 | 탐색 | 방식 | 담은 것 | 지난 기록 | 설정`

**설정을 상단바에서 지우지 마라.** 이전 안에서 지워졌는데 그건 잘못이었다.
운영자가 수집 일정·상한·기한을 바꿀 자리가 없어진다. 첫 화면에 안 보이는 것과 없애는 것은 다르다.

## 3. 브리프 (`/`) — 새로 만드는 화면

열면 스크롤만으로 이번 주가 파악되어야 한다. **들어가지 않아도 읽힌다.**

```
이번 주 트렌드 허브                        2026년 9월 넷째 주

⚠ 지금 들어가면 늦은 것          1~2개
✓ 지금 들어갈 것                3~4개
    이름 (제일 크게)  ·  방식 라벨  ·  확산 숫자
    한 줄 요약
    만드는 법 3줄        ← 여기서 바로 읽힌다. 들어가지 않아도 된다
    어디까지 써도 되나 한 줄
    [자세히]  [원문]
✗ 안 건드리는 게 나은 것         1~2개
```

- **방식 하나.** 근거가 가장 많은 것, 동점이면 신선도 높은 쪽. 억지로 채우지 마라
  (전에 「총 5개 안팎」이었는데, 묶음 셋을 채우려면 정점 판정 신호가 필요하고 그게 데이터에 없다)
- **깊이가 얇은 소재는 브리프에 싣지 않는다.** 원문이 두꺼운 것만 고른다.
  자캐 공개처럼 소재마다 한 줄뿐인 것은 탐색에는 남기고 브리프에서는 뺀다
- 각 항목의 "만드는 법 3줄"은 소재 상세의 만드는 순서를 줄인 것이다. 따로 지어내지 마라

## 4. 탐색 (`/explore`, `/grammars`)

목록·검색·필터는 `/explore` 로 옮겨져 있다.
판정기 버튼·남은 횟수는 여기에 둔다(첫 화면이 아니라).

`/grammars` 는 새 축이다. 방식 12개를 나열하고, 누르면 그 방식의 소재 목록을 낸다.

### 방식 화면의 질문 흐름

```
질문 1  "뭘로 만들 거예요?"   [영상] [사진·카드뉴스] [글만]
  - 방식의 kind 로 거른다. 고르지 않아도 된다
  - 안 고르면 "고르지 않으면 전부 보여드립니다" 를 오른쪽에 띄우고 12개를 다 낸다
  - 첫 화면이 절대 비어 있으면 안 된다

질문 2  "소개할 물건이나 가게가 있나요?"   [있어요] [없어요]
  - 질문 1을 고른 뒤에만, 그리고 그 kind 안에 물건이 필요한 방식이 실제로 있을 때만 나타난다
  - 답하기 전에는 "N개 방식이 여기에 걸립니다" 로 영향 범위를 미리 알린다

"없어요" 는 막다른 길이 아니다. 안내 박스로 이어진다:
    물건 없이 할 수 있는 {영상} 방식 {N}개를 골랐습니다
    물건이 생기면 {굿즈깡 · 손 클로즈업} 도 열립니다.
  - 열리는 방식 이름은 데이터에서 뽑는다. 하드코딩 금지
  - 걸린 방식을 목록에서 없애지 않는다. 칩에 "물건 필요" 를 달아 남긴다.
    없애면 "나중에 열릴 것" 이 안 보여 다시 올 이유가 사라진다
```

**"가진 것" 이라는 말을 쓰지 마라.** 이전 안이 그렇게 썼다가 무슨 뜻인지 아무도 몰랐다.
사용자가 자기를 설명하는 말로 묻는다.

### 아직 답 없는 것 — 브리프가 고를 수 있는 풀

신선도를 잴 수 있는 후보는 196건 중 58건뿐이다(나머지는 게시물 10건 미만).
브리프가 고를 수 있는 풀이 58건이라는 뜻이다.
매주 새로운 5개가 나오려면 이 풀이 얼마나 커야 하는지, 그러려면 수집을 어떤 주기로
얼마나 깊게 돌려야 하는지는 아직 답이 없다.

## 5. 소재 상세 (`/candidates/[id]`) — 강화

**일반론을 쓰지 마라.** 이전 안이 "말하려는 것을 한 문장으로 줄입니다" 같은 글쓰기 조언을
넣었는데, 그건 데이터가 없어도 쓸 수 있는 말이라 9,659건을 훑은 의미가 사라진다.
**모든 문장이 수집 원문에서 나와야 하고, 줄마다 숫자나 원문 링크가 붙어야 한다.**

구성 (`늙크크` 기준. 실제 화면은 `docs/ui/topic-detail.png` 참고):

```
[정점 경고]   지금 들어가면 늦은가
              예: 9/21 TBS eFM 라디오가 다뤘다 + X에 "사망선고 받은 밈" 반응
              매스미디어 등장 · 부정 반응은 정점 신호다

[이게 뭔가]   어원과 정의. 모르면 못 만든다
              예: 코르티스 〈영 크리에이터 크루〉 → 영크크 → 반대말 늙크크
              주의사항도 여기: "남한테 붙이면 분위기가 미묘해진다"

[어느 형식으로 갈까]  실제로 갈린 갈래를 실적순으로
              예: 말투 특징 나열 10건 18.9만 / 상황극 3건 8.0만 / 자조 5건 3.6만

[만드는 순서]  고른 갈래를 실제로 만드는 3~5단계. 줄마다 근거 숫자
              예: ① 제목을 「말투 특」으로 연다 — 이 제목 10건 조회 합계 18.9만
                  ② 항목으로 끊어 나열 — 랭킹의민족은 10가지
                  ③ ~~ 와 ^^; 를 실제로 띄운다 — 4건이 본문에 그대로 씀
                  ④ #늙크크 와 #영크크 를 같이 — 6건 중 4건이 함께 달았다
              피할 것도 데이터로: 「따라하기」 제목 3건 합계 2,594 (70분의 1)

[브랜드가 쓴 사례]  남이 이미 이걸로 마케팅한 것
              예: 롯데하이마트 대구율하점 9/11~13 행사 홍보

[어디까지 써도 되나]  3단
```

**만드는 순서 블록은 `frame` 으로 갈린다. `kind` 가 아니다.** `kind` 는 사용자에게 묻는
입력 축이라 셋이고, 만드는 순서는 출력 축이라 넷이다(§6). 입고 정보와 비교·투표는 둘 다
`사진·카드뉴스` 지만 만드는 순서가 다르다 — 묻는 단위를 줄였다고 순서까지 뭉개면 이 절이
금지하는 일반론이 된다. 부제 넷은 `docs/WORDS.md` §8 에 있다.

**카드가 교훈을 품어야 한다.** 근거를 한 줄로 늘어놓고 "원문 보기" 로 넘기지 마라.
무엇을 알려주려는 사례인지 카드 안에서 읽혀야 한다.

**데이터가 얕은 소재는 이 화면을 열지 않는다.** 한 줄짜리 각도밖에 없으면
"근거가 아직 얇습니다" 로 정직하게 표시하고 원문 링크만 준다.

## 6. 방식 정의와 근거 규칙

`lib/core/grammar.ts` 를 새로 만든다. 방식은 느리게 변하므로 정적 정의, 근거만 런타임에 붙인다.

```ts
interface Grammar {
  id: string
  name: string                                   // 짧게
  kind: 'video' | 'photo' | 'copy'               // 질문 1과 1:1
  need: { item: boolean }                        // 소개할 물건·가게가 필요한가
  desc: string
  match: RegExp
}
```

**`kind` 와 `frame` 은 다른 축이다 (2026-09-27 사양 수정).**

```
kind    사용자에게 묻는 말 — 영상 / 사진·카드뉴스 / 글만.  질문 1 과 1:1 (입력 축)
frame   만드는 순서 블록의 모양 — video / copy / info / compare (출력 축)
```

이 절이 처음에 둘을 하나로 뭉갰는데 그게 잘못이었다. 합치면 `사진·카드뉴스` 안의
**입고 정보와 비교·투표가 같은 만드는 순서를 달게 되고**, 그건 §5 가 금지하는 일반론이다.
「채울 항목을 채우는 것」과 「비교축을 정하는 것」은 사용자에게 묻는 말이 같아도 만드는
순서가 다르다. `frame` 은 `lib/core/recipe.ts` 의 `frameOf()` 가 정한다.

12개의 이름·한 줄·kind·frame·물건은 `docs/WORDS.md` §5 에 있다. `match` 는 `docs/grammars.md`.
그 문서의 **"정정 (2026-09-27, 재검증)"** 절을 반드시 반영하라 — `이름 놀이` 는 탈락했다.

`grammarsWithEvidence()`:
- **같은 게시물 URL 은 1건으로 센다.** 근거 2건은 후보 2건이 아니라 **서로 다른 게시물 2건**이다
  (`이름 놀이` 가 한 영상에서 캐릭터 3개를 뽑아 "근거 5건" 이 됐다가 탈락했다)
- 고유 출처 2건 미만이면 그 방식을 결과에서 뺀다
- angle 이 판정 메모뿐인 후보는 근거에서 제외한다
- 방식별 freshness 중앙값을 붙인다

## 7. 신선도 (`lib/core/series.ts`)

```
freshness(posts, asOf) : number | null
  postedAt 이 asOf 로부터 최근 30일 이내인 비중(정수 %). KST(observedDay) 기준
  postedAt 이 있는 게시물 10건 미만이면 null (0 이 아니다. "모른다")
```

**`asOf` 기본값은 오늘이 아니라 마지막 회차 시각이다** (`db.runs` 의 `at` 최댓값 = 2026-09-24).
오늘로 잡으면 수집이 멈춘 동안 경계가 계속 밀려 같은 데이터에서 숫자가 달라지고,
주간 비교가 성립하지 않는다.

필요한 이유: 급등 신호가 radar 12건에만 있고 캐릭터는 관측일 수로 대체돼 있는데,
그건 유명도 대리지표다. 코난도 짱구도 5일 관측인데 신선도는 34% 대 92% 로 갈린다.

### 검증 — 이 명령을 그대로 돌려라

`data/db.json` 은 11.6MB 다. **절대 Read 로 열지 마라.** 아래를 실행해 숫자만 확인한다.

```bash
node -e "
const d=require('./data/db.json');
const kst=s=>new Date(new Date(s).getTime()+324e5).toISOString().slice(0,10);
const asOf=d.runs.map(r=>r.at).sort().pop();
const cut=kst(new Date(asOf).getTime()-30*864e5);
const by={}; for(const p of d.posts){ if(p.candidateId) (by[p.candidateId]=by[p.candidateId]||[]).push(p); }
for(const n of ['짱구','코난','리락쿠마','치이카와']){
  const c=d.candidates.find(x=>x.subject===n);
  const days=(by[c.id]||[]).map(p=>p.postedAt).filter(Boolean).map(kst);
  console.log(n, days.length<10?'null':Math.round(days.filter(x=>x>=cut).length/days.length*100)+'%');
}"
```

기대값 — 마지막 회차 `2026-09-24`, 30일 경계 `2026-08-25`
```
짱구 92%   코난 34%   리락쿠마 33%   치이카와 72%
(참고) 하치와레 36%   우사기 45%
```

위 명령의 결과와 `freshness()` 의 결과가 같으면 끝이다.

## 8. 개인화 — 로그인 없이

```
소재별   담은 소재를 다음 브리프에 이어 붙인다
         "담아둔 치이카와가 이번 주 이렇게 됐습니다"
         이미 /library 와 components/pick.tsx(localStorage) 가 있다. 화면에 붙이기만 하면 된다

방식별   자주 여는 방식을 브리프 위로 올린다
         영상만 만드는 사람에게 카피형이 계속 1등이면 안 된다
```

상태는 **URL 쿼리 + localStorage**. 서버에 쓰지 않는다. 로그인을 만들지 마라.
질문 1·2의 답도 URL 에 남긴다(`?form=video&item=no`) — 북마크하면 그 상태로 열린다.

```
docs/ui/home-3-no-item.*      "없어요" 후
docs/ui/home-4-has-item.*     "있어요" 후
docs/ui/topic-detail.*        소재 상세
```

### 꼭 지킬 것

1. **이름이 카드에서 제일 크다** (30px / 700 / letter-spacing -0.8px). 이름이 이 제품의 상품이다
2. **카드 높이 고정** (300px). 지금 배포본은 썸네일 없는 카드에 빈 공간이 생겨 그리드가 어긋난다
3. **한 번에 파악할 것을 늘리지 마라.** 첫 화면에서 읽어야 할 덩어리는 5개 이하
4. 카드 본문은 사람 말로 쓴다 ("계정 17곳이 따라 했습니다")
5. 칩에는 왜 지금 못 하는지를 붙인다 ("물건 필요")

## 10. 금지

1. **판정기 메모를 사용자 화면에 내보내지 않는다** — "독립 출처가 부족함", "제작 보류",
   "공식 레퍼런스 필요". 지금 배포본은 서로 다른 카드 두 장이 같은 실패 메시지를 달고 있다
2. **"안전합니다" 라고 쓰지 않는다.** 권리자·문의처·확인이 필요한 구간까지만
3. **조회당 LLM 호출 금지.** 배포본에 로그인이 없어 비용 천장이 사라진다
4. **내부 로드맵을 화면에 쓰지 않는다** — "다음 단계에서 연결합니다"
5. **내부 용어를 라벨로 쓰지 않는다** — 레이더 / 확정 / 잠정 / 단일 출처 / 2곳 이상
6. 수집 파이프라인(`lib/collect/*`, `lib/discoveries/*`)은 건드리지 않는다. 읽기 쪽만이다
7. 화면을 kind 마다 따로 만들지 마라. 하나의 상세 화면에서 블록만 바뀐다

## 13. 작업 순서

세션당 하나씩. 각 수용 문장을 만족하면 끝이다.

**1 — 신선도** (`lib/core/series.ts`) — **끝났다**
　끝: 7절 검증 명령의 결과와 `freshness()` 결과가 같고, 게시물 10건 미만은 null 이 나온다
　　　— 충족. 네 검증값이 맞고, `asOf` 는 필수로 두었다(기본값을 오늘로 두면 수집이 멈춘
　　　동안 경계가 매일 밀려 주간 비교가 깨진다)

**2 — 방식 정의 + 근거 결박** (`lib/core/grammar.ts`) — **끝났다**
　끝: 12개가 나오고 각각 고유 출처 2건 이상, 근거에 판정 메모가 안 섞인다 — 충족.
　　　`kind` 는 video 6 · photo 4 · copy 2, `need.item` 은 다섯이다. 저장된 게시물이
　　　0건인 소재는 카드를 만들지 않고 근거 수에도 세지 않는다(§19-5)

**3 — 라우트 정리** (삭제 0건) — **끝났다**
　끝: 지금 `/` 의 목록이 `/explore` 에서 그대로 동작하고, 기존 화면이 전부 살아 있으며,
　　　상단바에 설정이 있다 — 충족. 여덟 개 라우트가 전부 동작하고 설정이 상단바에 있다

**3.5 — 담기를 브라우저로** (`/library`) — **끝났다**
　끝: 방식 카드와 소재 상세에서 담기가 눌리고 `/library` 에 뜬다. localStorage 에만
　　　저장된다 — 충족. 서버 추적(`lifecycle: 'archived'`)은 지우지 않고
　　　`/settings/tracking` 으로 내렸다

**4 — 브리프** (`/`) — **끝났다**
　끝: `/` 를 열면 히어로 → 기준 줄 → 방식 하나 → 근거 한 건 → 숫자 두 줄 →
　　　[방식 고르기] 순으로 읽힌다. 12개 목록과 만드는 순서는 이 화면에 없다.
　　　화면의 수치는 전부 db 에서 계산되고 문자열 리터럴이 없다 — 충족

**5 — 방식 탐색** (`/grammars`) — **끝났다**
　끝: 질문 1을 고르면 질문 2가 나타나고, "없어요" 에 안내 박스가 뜨며,
　　　걸린 방식은 칩에 "물건 필요" 를 달고 남는다. 새로고침해도 URL 로 복원된다 — 충족.
　　　카드 묶음 제목이 답에 따라 바뀌고(§4), 종류를 바꾸면 물건 답이 지워진다

**5.5 — 만드는 순서와 근거 카드** — **끝났다**
　끝: `frame` 별 템플릿으로 만든 일반론을 걷어내고 방식 12개가 저마다 단계를 갖는다
　　　(`lib/core/grammar-steps.ts`). 줄마다 근거 번호가 붙고, 근거 카드가 §19 모양이다
　　　— 충족. 단계 36줄이 전부 캡션·숫자·해시태그를 근거에서 인용한다

**6 — 소재 상세 강화** (`/candidates/[id]`) — **아직 안 했다**
　끝: 늙크크를 열면 정점 경고·어원·형식 갈래·만드는 순서(줄마다 근거)·브랜드 사례·사용 범위가
　　　나오고, 지어낸 문장이 하나도 없다. 데이터가 얕은 소재는 "근거가 아직 얇습니다" 로 표시된다

　**남은 것 — 데이터가 먼저 필요하다.**
　이 화면의 문장은 전부 게시물 레코드에서 나와야 한다(§5). 그런데 **탐색기 다섯이 게시물을
　저장하지 않는다** — `news` · `radar` · `character` · `material` · `benchmark` 가
　`upsertPosts` 를 부르지 않는다. 그래서 news 78건과 radar 12건은 게시물이 0 이고,
　그 소재의 상세를 열면 형식 갈래도 만드는 순서의 근거 숫자도 채울 것이 없다.
　`늙크크` 처럼 meme 축에서 온 소재만 채워진다.

　또 **정점 경고의 신호가 데이터에 없다.** 매스미디어 등장과 부정 반응을 판정할 칸이
　없다(§5 의 예시는 사람이 눈으로 찾은 것이다). 해당 없으면 섹션을 내리는 것이 §17 의
　규칙이므로, 지금 상태로는 그 섹션이 거의 항상 내려간다.

　순서: ① 탐색기 다섯이 게시물을 저장하게 고친다(수집 쪽이라 §10-6 의 범위 밖 — 따로
　요청을 받는다) ② 그 뒤에 이 화면을 채운다. ①을 건너뛰고 ②를 하면 뉴스 소재 90건이
　빈 화면을 연다.
