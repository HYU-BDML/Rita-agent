## 2. 개발자 컴퓨터 실행 (macOS/Linux shell 예시)

Node22.13+와 Git 준비. 영상 검수 때만 FFmpeg 필요. 첫 검수는 합성 자료·독립 DB·키 없이 진행한다. 교수의 실행 DB·.env·개인 llmgw 설정을 복사하지 않는다. 아래 clone 경로가 이미 있으면 기존 상태를 확인하고 다시 덮어쓰지 않는다.

```sh
mkdir -p ~/Projects
git clone --branch cora/project-bootstrap https://github.com/HYU-BDML/Rita-agent.git ~/Projects/rita-agent-cora
cd ~/Projects/rita-agent-cora
git switch -c cora/dev-initial-review
cd Cora/apps/trend-hub
mkdir -p data/developer-synthetic
CORA_PRODUCT_MODE=focused CORA_SCHEDULER=0 CORA_SCHEDULER_AI=0 CORA_DATA_DIR="$PWD/data/developer-synthetic" node scripts/run-local.mjs
```

http://127.0.0.1:3210/studio . 가상 Cora 계정/고객사2개를 만들고 자료→주간 선택→카드→저장/재열기를 먼저 사용한다. Instagram 계정이나 생성 API는 이 시작 흐름에 필수가 아니다. 이 URL은 개발자 컴퓨터에만 열린다. 다른 사람에게 보내도 원격 앱이 열리지 않는다. Windows에서는 Node SQLite/실행 스크립트를 먼저 검수하고 자신의 환경 절차/오류를 기록한다. 이번 인계에서 Windows 실행을 검증했다고 주장하지 않는다.

runner는 소스를 임시 runtime으로 복사하므로 **소스 수정 후 재시작**해야 반영된다. 자신이 시작한 서버만 종료한다. 기존 개인 secrets 파일이 있으면 runner가 읽을 수 있다. 첫 검수에서 실AI 버튼/공급자 작업을 실행하지 말고 설정과 요청 경계를 확인한다.

시험 명령(동기화되지 않는 본인 clone):

```sh
npm ci --ignore-scripts
npm run typecheck
CORA_DATA_DIR="$PWD/data/developer-synthetic" npm test
CORA_DATA_DIR="$PWD/data/developer-synthetic" NEXT_TELEMETRY_DISABLED=1 npm run build
```

타입과 빌드를 같은 .next에서 동시에 돌리지 않는다. 저장소의 Playwright 스크립트는 코드에서 유료AI 여부를 읽고 기능별로 선택한다. scripts/cora-*-proof.mjs 전부를 무작정 실행하지 않는다. 실제 생성은 기본 cora_test/deepseek-flash·캐시·고급 자동전환/재시도 없이 실행당최대3건; 준비 전0건으로 검수한다. 실패한 시험을 모델 교체로 우회하지 않는다.

## 3. 첫 작업: 독립 검수와 우선 수정안

초기4~6시간 정도의 방향 제안이며 전체 보안/출시 검수 완료 시간 보장이 아니다. 아래를 전부 한 번에 고치기보다 정확한 반례와 담당 작업을 만든다.

| 순서 | 실제 할 일 | 제출/판정 기준 |
|---|---|---|
| 1 | 실행/소스 파악·본인 환경 시험 | OS/Node/commit/명령/통과·실패·제외 이유. 성공 로그 또는 구체 실패 재현 |
| 2 | 고객사A/B·동명 고객사·소유자/편집자/검토자·권한회수 | 읽기/저장/내보내기/승인/늦은 응답 반례. API 상태·DB/자료 범위. 실제 유출 없으면 위험으로 표시 |
| 3 | 미저장 복구·오래된 버전 저장·같은 브라우저 계정 전환 | 기존 창에서 저장 실패 안내/초안 보존 재현. 유경W01 관찰을 확정/기각. 계정 공유쿠키는 정상이어도 UX 회복 필요 |

결과는 **1개의 개발자 검수 보고서**에 정리한다. 공개 가능한 기술 보고는 PR/Cora/docs, 비공개 캡처·실사용 자료는 공유 Drive의 Cora_팀협업/개발자_제출/시험일_이름/에 둔다. 실제 재현·코드상 위험·추정·미실행을 구분한다. 테스트 로그에 비밀값/원본 고객 콘텐츠가 있으면 공개 PR에 올리지 않는다.

## 4. 브랜치/PR와 넘기는 법

변경 단위마다 작업 브랜치를 만든다. 현재 draft PR5의 미병합 Cora 작업을 기초로 하면 먼저 **cora/project-bootstrap**에 대한 PR로 보내고, 통합 담당자가 검수/병합한 뒤 main 대상 PR5에서 회귀한다. 본인 task branch를 main에 바로 합쳐 통합 상태를 갈라놓지 않는다. 기존 브랜치를 강제푸시/reset하지 않는다.

Write 초대 전에도 공개 소스를 fork해 같은 기반 브랜치로 PR을 제안할 수 있다. fork/자기 clone은 작업 복사이며 별도의 제품 원본/Drive 소스 배포본이 아니다. Write를 주면 Rita-agent 전체 저장소 권한이다. Cora/만 수정한다는 약속과 기술적 폴더 접근 제한은 다르다. 형제 에이전트는 건드리지 않는다.

PR 본문: **문제/재현 → 변경 동작 → 검수와 결과 → 미검증/위험 → 원장ID → 증거**. AI 사용 여부는 검수 증거를 대신하지 않는다. 수정 전 재현과 수정 후 관련 시험, 통합 회귀를 기록하고 공동 상태/원장의 해당 항목만 갱신한다. 운영 데이터·키·배포·실제 첫 게시 결정은 교수와 합의한다.
