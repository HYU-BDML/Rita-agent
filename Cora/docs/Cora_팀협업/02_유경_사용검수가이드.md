## 지금 할 일

W01의 모의 전체 흐름·YouTube5건·작은 패치 핵심 과제는 완료로 인정했다. 패치가 반영된 기준은37af207이다. W01 전체 재실행 대신 기존 출력에서20~30분 정도의 보완만 요청했다. 공유폴더 outputs/Cora_유경_W01_검토_2026-10-06/02_유경에게_피드백.md를 보고, 이미 있는 PNG/작업JSON·수정 후 캡처·시간 기록과 가장 심한 불편점1개의 재현을 기존 outputs/조유경_10주/W01/에 제출한다. 없다면 미확인으로 기록하고 임의 결과를 만들지 않는다.

다음 사용 시험은 outputs/Cora_유경_2시간_워크북_2026-10-05/00_유경_2시간_워크북.html과 최신 집중 출시10주 안내 Cora/docs/Cora_출시집중_2026-10-04/08_유경_10주_출시검수.md를 기준으로 **가상 고객사 맥락→자료 선택→주간3개 선택→카드 수정→저장/재열기/내보내기/고객사 전환**을 본다. 자료 기반 흐름은 AI/Instagram 연결 없이 시작한다. 기존 API 과제의 블로그/긴 영상 확대를 자동으로 이어가지 않는다.

## 무엇을 평가하는가

- 콘텐츠가 누구에게 왜 유용한지, 고객사 목표·말투·피할 표현에 맞는지.
- 원문의 핵심 근거와 카드가 맞는지, 홍보·링크·연락처가 실제 내용 자리를 차지하는지.
- 다음 콘텐츠를 고르는 이유/시리즈/수정 이유가 분명한지. 좋은 콘텐츠를 추천했다고 말할 수 있는지 실제 카드로 판단한다.
- 다른 고객사의 규칙·자료·카드가 섞이지 않는지.
- 도움 없이 끝낼 수 있는지, 어디서 막히는지, 능동 작업/도움/대기 시간과 수정 카드 수.

브랜드3세트·서로 다른 카드/PNG·수정 전후 문장과 이유가 다음 주 중심이다. 개발자가 아직 구현/검수하지 않은 과제는 미실행으로 남기고 준비된 기능부터 시험한다. 실제 성과/성장 효과는 이 사용 시험으로 증명하지 않는다.

## 개발자와 함께 일하는 법

문제1건마다 **ID(예: W01-02)/버전commit/메뉴/입력 예시/클릭 순서/기대·실제/캡처/화면크기/재현횟수**를 적는다. 키·비밀번호·실제 고객DB를 넣지 않는다. 버그를 개발자가 못 재현하면 화면 공유나 가상 자료를 같이 보되, 추측으로 완료 표시하지 않는다. 학생 GitHub 계정은 지금 필수가 아니다. 기존처럼 patch 제출→AI/개발자 검토→관련 시험→통합으로 반영한다.

개발자가 고친 뒤 **같은 입력/순서로 재점검**하고 해결/남음/다른 문제를 기록한다. 두 계정 시험은 당분간 제작자 일반 창·검토자 시크릿 창으로 구분한다. 저장 오류가 나오면 계속 덮어쓰기보다 입력/화면을 보존하고 발생 경로를 기록한다. 같은 Drive checkout을 동시에 수정하지 않는다.

기존 학생 제출 위치는 그대로다. 워크북의 JSON 저장은 브라우저 내려받기이며 Drive 자동 제출이 아니므로 안내된 제출 폴더에 직접 올린다. 업무/패치 담당자가 합의되지 않은 문제는 우선 보고만 한다.
