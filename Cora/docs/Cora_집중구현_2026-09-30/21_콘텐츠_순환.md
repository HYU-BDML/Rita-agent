# 콘텐츠 순환 다섯 단계의 구현

2026-10-03 Claude(Opus)가 구현했다. 교수님은 이 흐름을 Cora의 중요한 일부분으로 정했다. 흐름은 AI가 콘텐츠 후보를 여러 개 만들고, 사람이 골라 게시하고, 게시 뒤 매일 성과를 분석해 점검하고, 다음에 무엇을 할지 정하는 순서다. 기존 기능을 고쳐 이 흐름이 한 화면에서 이어지도록 만들었다.

## 결론

스튜디오 왼쪽 메뉴의 “콘텐츠 순환” 화면에서 다섯 단계를 처음부터 끝까지 진행할 수 있다. 브라우저 검수에서 후보 생성부터 다음 후보 생성까지 7개 확인 항목이 모두 통과했다. 이 검수에서 순환이 실제로 닫히는 것도 확인했다. 성과가 높았던 시작 방식을 다시 쓰라는 할 일을 사람이 채택하면, 다음 후보 묶음이 그 시작 방식부터 만들어진다. 실제 AI 호출은 검수 1회당 1건이었다. 전체 단위시험은 483개 가운데 482개가 통과했고, 1개는 기존과 같이 건너뛰도록 지정된 시험이다.

## 단계별 구현 내용

| 순환 단계 | 하는 일 | 사람의 개입 |
|---|---|---|
| ① 후보 생산 | 같은 자료로 후보 2~5개를 만든다. AI 방식은 1회 호출로 여러 후보를 받으며, 후보마다 시작 방식(질문형·숫자형·결과 먼저·장면·이야기형·대비형)이 서로 다르다. 규칙 방식은 AI 없이 카드 구성과 첫 장 제목만 바꾸고 본문은 입력 자료를 그대로 쓴다 | 자료와 이번 회차 지시를 사람이 적는다 |
| ② 사람의 선정 | 후보를 나란히 놓고 하나를 고르면 편집 가능한 작업으로 저장된다. 버린 후보도 기록한다 | 고른 이유와 버린 이유를 하나 이상 표시해야 결정된다 |
| ③ 게시 | 고른 후보로 게시 기록을 남기면 시작 방식과 형식이 게시물에 이어진다. Instagram 게시물 ID를 적어 두면 계정 연결 뒤 성과를 자동으로 가져올 수 있다 | 실제 게시는 기존 게시 준비와 승인 흐름을 거친다 |
| ④ 매일 성과 분석 | 게시물마다 하루 한 번 도달·조회·좋아요·댓글·저장·공유·팔로우를 기록한다. 화면 입력, CSV, Instagram 성과 API 세 경로를 지원한다 | 계정 연결 전에는 사람이 수치를 입력한다 |
| ⑤ 점검과 다음 결정 | 게시물마다 같은 계정의 다른 게시물과 같은 게시 경과일끼리 비교하고, 규칙에 따라 다음 할 일을 제안한다. 채택한 할 일로 다음 후보를 만들면 ①로 돌아간다 | 할 일마다 채택 또는 보류를 사람이 정하고, 보류할 때는 이유를 적는다 |

## 비교 방법과 판정 기준

점검은 게시 1일째 게시물을 다른 게시물의 1일째 기록과 비교하는 식으로, 같은 게시 경과일끼리만 비교한다. 비교 지표는 도달, 저장률(저장 ÷ 도달), 공유율(공유 ÷ 도달)이다. 게시물의 값이 다른 게시물 중앙값의 1.2배 이상이면 “기준보다 높음”, 0.8배 이하이면 “기준보다 낮음”으로 표시한다. 비교할 게시물이 3개 미만이면 판정하지 않는다. 1.2배와 0.8배는 Cora가 정한 설계값이며 플랫폼이 정한 기준이 아니므로, 화면에는 배수와 비교 게시물 수를 함께 보여 준다.

모르는 수치를 비워 두면 0이 아닌 “없음”으로 저장하고 비교에서 뺀다. 0으로 적은 값은 실제 0으로 계산한다. 이 비교는 관찰값이며, 한 요소가 성과를 바꿨다는 인과효과로 해석하지 않는다.

## 규칙 체계

점검이 쓰는 규칙은 `lib/cora/loop-playbook.ts`에 있고, 규칙마다 근거와 출처, 신뢰 등급을 단다. 신뢰 등급은 세 가지다. “안정”은 플랫폼 공식 자료가 있거나 서로 다른 출처 3곳 이상이 같은 내용을 말하는 경우다. “미확인”은 출처가 하나뿐이거나 출처 사이에 주장이 엇갈리는 경우다. “Cora 기준”은 플랫폼 주장과 무관하게 Cora가 정한 운영 원칙이다.

지금 자동으로 적용되는 Cora 기준 규칙은 4개다.

1. 게시 다음 날부터 오늘 성과 기록이 없는 게시물이 있으면 기록하도록 알린다.
2. 저장률이나 공유율이 기준보다 높은 게시물이 있으면, 다음 후보 하나는 그 시작 방식을 유지하고 한 요소만 바꾼다.
3. 같은 시작 방식의 게시물이 3개 이상이고 저장률 중앙값이 전체의 0.8배 이하이면, 그 시작 방식을 다음 후보에서 맨 뒤로 보낸다.
4. 사람이 같은 이유로 후보를 3번 이상 버렸으면, 다음 후보 지시에 그 문제를 피하라는 문장을 넣는다.

TikTok·YouTube·블로그와 플랫폼 공식 자료에서 모은 노하우는 `lib/cora/loop-knowhow.ts`에 출처와 함께 넣는다. 이 조사 결과의 반영 범위는 아래 “노하우 반영” 절에 적는다.

## 노하우 반영

보조 에이전트가 Instagram·YouTube·TikTok 공식 자료와 많이 인용되는 대규모 조사·실무 자료에서 규칙 44개를 모았고, Claude가 출처 분류와 핵심 원문을 다시 확인했다. 규칙은 단계별로 후보 생산 7개, 사람의 선정 8개, 게시 9개, 매일 성과 분석 12개, 점검과 다음 결정 8개다. 규칙 원본은 `lib/cora/loop-knowhow-data.json`이고, 화면 아래 “순환 규칙과 근거”에서 출처 종류와 함께 볼 수 있다.

1. 보조 에이전트는 Social Media Today·Tubefilter 같은 언론 보도 24건을 공식 출처로 분류했다. Claude가 이를 “보도”로 바꾸고 신뢰 등급을 다시 계산했다. 그 결과 안정 등급은 38개에서 36개로 줄었고, 미확인은 6개에서 8개로 늘었다.
2. Claude가 원문을 직접 열어 확인한 공식 문장은 세 가지다. Meta 성과 API 문서는 수치가 최대 48시간 늦게 반영될 수 있다고 적었다. Instagram 크리에이터 FAQ는 팔로워 증가가 큰 크리에이터가 평균 월 10개 이상 릴스를 올린다고 적었다. 테스트 릴스 안내문은 테스트 릴스를 팔로워가 아닌 사람에게 먼저 보여 준다고 적었다.
3. 같은 Meta 문서에서 건너뛰기 비율(`reels_skip_rate`)과 릴스 평균 시청 시간(`ig_reels_avg_watch_time`) 지표도 확인했다. 보조 에이전트는 건너뛰기 비율을 API로 받을 수 없다고 보고했지만, 이 문서를 근거로 계정 연결 뒤 자동 수집 대상에 넣었다.
4. 데이터로 자동 판정하는 노하우 규칙은 지금 2개다. R27은 Instagram에서 받은 게시 2일 미만 수치로는 판정하지 않고 48시간 뒤 다시 점검하게 한다. R18은 최근 30일 Instagram 릴스 기록이 10개 미만이면 게시 일정을 늘리라고 제안한다. 나머지 42개는 단계별 확인 목록으로 화면에 보인다.
5. 확인하지 못해 뺀 주장도 있다. “71%가 첫 3초에 계속 볼지 정한다”, “첫 30~60분이 확산을 결정한다”, 릴스 길이별 공유 증가율 같은 수치는 공식 출처나 원문을 찾지 못해 넣지 않았다.

## Instagram 계정 연결과 하루 1회 자동 점검

키가 오기 전에 할 수 있는 부분을 2026-10-03에 미리 만들었다. Meta 앱을 발급해 서버 설정 4개를 넣으면 추가 개발 없이 실제 연결을 시험할 수 있다.

1. 계정 연결은 Meta 공식 문서의 Instagram 비즈니스 로그인 절차를 따른다. 사용자가 Instagram에서 권한을 허용하면, Cora가 받은 코드를 60일짜리 장기 토큰으로 바꿔 저장하고 만료 7일 전부터 자동으로 갱신한다. 원문 확인 결과 연결에 쓰는 값은 Meta 앱 ID가 아니라 Instagram 앱 ID다. 그래서 발급 방법 문서 4-1도 함께 고쳤다.
2. 토큰은 서버 설정 `CORA_SECRET_KEY`로 암호화해 저장하고, 화면에는 계정 이름과 만료일만 보낸다. 연결 요청마다 한 번만 쓰는 확인값을 붙여, 다른 계정의 요청이나 10분이 지난 요청은 거부한다.
3. 필요한 서버 설정은 `CORA_IG_APP_ID`, `CORA_IG_APP_SECRET`, `CORA_IG_REDIRECT_URI`, `CORA_SECRET_KEY` 4개다. 연결 주소는 `/api/cora/connect/instagram/callback`이다. Instagram이 HTTPS 주소만 받는지는 발급할 때 확인 필요하며, 받는 경우 교수님 컴퓨터에서 시험하려면 HTTPS 임시 주소가 필요하다.
4. 예약 실행이 켜진 서버(`CORA_SCHEDULER=1`)는 한국 시각 오전 9시 이후 하루 한 번씩 사용자별로 세 가지를 한다. 연결된 계정의 성과를 가져오고, 점검을 실행하고, 제안된 할 일이 있으면 “오늘 점검 결과” 알림을 보낸다. 같은 날 두 번째 실행은 아무것도 하지 않는다.
5. 순환 화면 ③에는 연결 상태가 표시된다. 설정이 없으면 빠진 설정 이름을, 연결 전이면 연결 버튼을, 연결 후에는 계정 이름·만료일과 “Instagram에서 오늘 성과 가져오기” 버튼을 보여 준다.

## 검증 기록

1. `tests/cora-loop.test.ts` 6개 시험: 후보 생성의 시작 방식 중복 금지와 자료 보존, AI 응답의 형식 검사, 다섯 단계 전체 흐름, AI 하루 한도와 CSV 전체 취소와 사용자 분리, Instagram 성과 API의 지표 이름 변환과 토큰 비노출, 노하우 44개의 출처 등급과 48시간 규칙·릴스 게시량 규칙을 확인한다.
2. `scripts/cora-loop-proof.mjs` 브라우저 검수: 회원가입부터 다음 후보 생성까지 실제 화면을 조작한다. 첫 실행에서 페이지를 새로 고친 뒤 ①의 브랜드·자료 칸이 비어 다음 후보를 만들 수 없는 결함을 찾았다. 칸이 비어 있으면 가장 최근 후보 묶음의 자료로 채우도록 고친 뒤 통과했다.
4. 전체 회귀 검수: 유료 AI를 부르지 않는 브라우저 검수 26개를 모두 다시 실행해 통과시켰다. 이 과정에서 세 가지를 고쳤다. 첫째, 콘텐츠 순환 메뉴를 추가해 왼쪽 메뉴가 길어지면서 데스크톱에서 로그아웃 버튼이 화면 밖에 걸린 회귀가 있어 메뉴에 세로 스크롤을 허용했다. 둘째, 600px 이하 화면에서 계정 영역이 숨겨져 휴대폰에서 로그아웃할 수 없던 기존 결함을 고쳤다. 셋째, 검수 스크립트 3개의 낡은 기대값과 선택자를 고쳤다. AI를 부르는 검수 6개는 하루 AI 한도 때문에 이번에 다시 실행하지 않았다.
3. 같은 작업에서 결제 동시성 시험의 날짜 의존 결함을 고쳤다. 두 번째 연결이 고정 시계 대신 실제 시각을 써서, 2026-10-01부터 무료 월간 지급이 한 번 더 들어가 사용 가능 횟수가 5회에서 7회로 늘었다. 제품 코드는 바꾸지 않고, 시험의 두 연결이 같은 고정 시계를 쓰도록 고쳤다.

## 한계와 다음 작업

1. Instagram 계정 연결과 하루 1회 자동 수집은 가짜 응답으로만 시험했다. Meta 앱 발급 뒤 실제 계정으로 연결·수집·토큰 갱신을 확인해야 한다.
2. 실제 게시와 게시 기록은 아직 자동으로 이어지지 않는다. 게시 대기열이 실제 게시를 마치면 게시 기록을 자동으로 만드는 연결은 Meta 앱 발급 뒤 실제 게시와 함께 만든다.
3. 판정 기준 1.2배·0.8배와 비교 최소 3개는 설계값이다. 실제 계정 자료가 쌓이면 조유경의 노하우 수집 결과와 함께 다시 정한다.
4. 기능 원장 119개 체계에는 아직 이 순환 기능을 별도 행으로 넣지 않았다. 원장 도구가 119행을 고정으로 검사하므로, 행을 추가하려면 원장 도구도 함께 바꿔야 한다.
