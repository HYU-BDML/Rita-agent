# 승인본 게시 준비와 Blotato 어댑터

2026-09-30 구현. 유료 AI 호출 0회, 실제 SNS 전송 0회.

## 지금 사용할 수 있는 경로

콘텐츠 저장 → 다른 Cora 계정의 버전별 검토 승인 → 게시 준비함 → 승인된 저장 버전 선택 → 대상 계정 메모와 희망 시각 입력 → 게시 준비 저장.

게시 준비함은 승인 당시 콘텐츠의 고정 사본을 SQLite에 보관한다. 같은 버전·계정 메모·시각은 중복 저장하지 않는다. 최신 목록 50개 밖에 있는 기존 준비 작업도 중복 요청 시 같은 식별자를 반환한다. 원본을 다시 저장하거나 검토 공유를 회수하면 재검토 필요로 표시한다. 소유자만 준비 목록 조회와 취소를 할 수 있다. 취소한 동일 작업을 다시 준비하려면 새 콘텐츠 버전이 필요하다.

희망 시각은 기기 시간대로 입력하고 UTC로 저장한다. **이 시각은 실제 예약 발행이 아니다. 계정 메모도 연결된 SNS 계정 식별자가 아니다.** 화면과 API 모두 실제 전송이 연결되지 않았음을 표시한다. 전송 action을 호출하면 거절한다.

## Sabrina 흐름에서 채택한 게시 코드

Sabrina 글의 n8n → Blotato 흐름에서 게시 공급자 경계를 채택했다. 이번에는 Cora 서버에서 재사용할 TypeScript 어댑터를 작성했으며 n8n 템플릿을 실행하거나 복제하지 않았다.

공식 문서에 맞춰 Instagram 계정 목록 조회, 게시 요청, 접수 식별자로 상태 조회하는 코드를 작성했다. 예약 시각은 요청 최상위 scheduledTime에 넣는다. 접수됨·예약됨·게시됨·실패·결과 불명을 구별하며, 타임아웃 또는 응답 유실 시 POST를 자동 재전송하지 않는다. 다른 접수 ID의 응답을 성공으로 처리하지 않는다.

코드: apps/trend-hub/lib/cora/publishing/blotato.ts. 현재 이 어댑터는 실제 전송 API에 연결되지 않았고 시험용 응답으로 검증했다. 준비 작업 DB와 공급자 상태 조회를 연결한 영구 실행 큐·대조 기능은 아직 없다.

## 검증 증거

- 프로덕션 빌드 및 전체 단위 시험: 337개 통과, 기존 데이터 의존 시험 1개 제외. 이 중 Cora TypeScript 시험은 15개이며 신규 게시 시험 3개에 여러 시나리오를 포함한다.
- 새 브라우저/API 검수 5개: 승인본 준비와 UTC 변환, 중복 저장 방지, 다른 계정 접근 및 전송 action 거절, 원본 변경 시 재검토와 캡션 보존, 취소.
- 기존 운영 브라우저 회귀 7개 통과.
- 재현 스크립트: scripts/cora-publication-proof.mjs. 검증 JSON은 검증기록/publication-proof.json 및 publication-regression.json, 화면은 outputs의 증거/publications 폴더.

## 실제 게시 전에 남은 개발

사용자별 공급자 자격 증명 보관, 브랜드와 연결 계정의 소유권 검사, 승인된 카드의 공개 미디어 호스팅, 파일 형식·크기 및 URL 대상 검증, 실행 직전 승인 버전 재확인, 영구 실행 큐, 공급자 결과 저장·대조, 예약 변경·취소 정책을 구현해야 한다. 현재 URL 검사는 기본 HTTPS 및 IP/localhost 형태만 제한하며 DNS 해석이나 미디어 소유권을 검증하지 않는다. 이미지 1~10개라는 어댑터 범위도 실제 계정 계약 시험이 필요하다.

공급자 사용 조건·다중 고객 SaaS 사용 범위, 연결 키와 테스트 계정 권한, 실제 공개 게시 승인을 확보한 뒤 외부 결과를 검증한다. 원장 F069/E204는 부분 구현 상태를 유지한다.
