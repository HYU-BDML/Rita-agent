# 저장 버전별 검토 요청

2026-09-30 자동 개발 실행. 유료 AI 호출 0회.

## 사용 경로

제작실에서 콘텐츠를 저장한다 → 검토자 이메일을 입력한다 → ‘저장한 버전 검토 요청’을 누른다 → 상대 계정이 ‘검토함’에서 카드와 캡션을 확인한다 → ‘이 버전 승인’ 또는 의견을 적어 ‘수정 요청’을 선택한다.

공유 대상은 같은 Cora 서버에 이미 가입한 다른 계정이다. 이메일을 실제로 발송하지 않는다. 교수님과 유경이가 각자 별도 로컬 서버를 실행하면 서로 다른 계정 저장소이므로 이 기능으로 연결되지 않는다. 공동 사용에는 같은 서버의 계정이 필요하며 공개 배포 준비는 별도 작업이다.

## 구현한 권한과 버전 규칙

- 제작자만 자신이 소유한 저장본을 공유한다. 저장하지 않은 편집 내용은 공유되지 않는다.
- 공유 버튼은 카드·캡션뿐 아니라 브랜드 원문 자료도 전달한다고 안내한다.
- 지정 검토자만 검토 결과를 남긴다. 검토자는 프로젝트 원본 API에 접근하거나 수정할 수 없다. 제작자 본인이 상대방 대신 승인할 수 없다.
- 공유본은 당시 저장 버전의 고정 사본이다. 이후 원본 수정으로 이전 공유본이 바뀌지 않는다.
- 원본을 다시 저장하면 이전 검토는 재검토 필요 상태다. 이전 요청으로 새 버전을 승인하지 못한다. 검토 메모만 바꿔 재저장한 경우에도 보수적으로 새 버전으로 처리한다.
- 동일 작업·버전·검토자 요청은 중복 생성하지 않는다. 이미 결정한 검토를 두 번 승인하지 못한다.
- 제작자는 검토 공유를 회수할 수 있다. 서버는 이후 검토자의 해당 사본 접근을 거부한다. 이미 보았거나 내려받은 정보까지 회수되는 것은 아니다.
- 원본 프로젝트를 삭제하면 연결된 검토 요청도 삭제된다.

## 검증

프로덕션 빌드 통과. TypeScript 단위 시험 334개 통과·기존 데이터 의존 시험 1개 제외(신규 검토 정책 시험 1개에 권한·고정 사본·중복 결정·수정 충돌·공유 회수·삭제 검증 포함). 별도 브라우저 두 계정으로 요청, 실제 카드 검토와 승인, 권한 분리, 수정 후 재검토, 새 버전 수정 의견, 접근 회수 등 6개 경로를 통과했다. 기존 운영 회귀 7개도 통과했다.

재현: `scripts/cora-review-proof.mjs`. 증거 JSON은 검증기록/review-proof.json. 브라우저 화면은 outputs의 증거/reviews에 있다.

## 남은 범위

워크스페이스 팀 초대·관리자/편집자 역할, 이메일 알림, 댓글 스레드, 실제 SNS 발행 직전 승인 버전 검사, 영구 감사 로그는 아직 없다. 개인 작업 상태의 ‘내 검토 완료’와 다른 사람의 버전별 승인은 서로 다른 상태다. 게시 어댑터를 구현할 때 반드시 발행 대상 버전과 승인 버전을 대조해야 한다.
