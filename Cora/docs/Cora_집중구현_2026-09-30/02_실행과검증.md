# Cora 실제 작업본 — 실행과 검증

2026-09-30. 전체 Mirr 기능 완성본이 아니라, 실제 생성·편집·내보내기와 운영 저장을 연결한 집중 구현 작업본이다. 전체 목표는 기능별 개발 원장 119행에서 유지한다.

## 지금 사용

교수님 컴퓨터: http://127.0.0.1:3210/studio . 로컬 계정을 만든 뒤 예시를 불러오거나 브랜드 자료를 입력한다. 장수를 선택하고 **AI로 바로 만들기**를 누르면 편집기가 열린다. 문구·사진·순서·색상·비율·디자인·서체를 바꾸고 작업 저장, PNG ZIP, JSON, MP4로 내보낸다.

왼쪽 **소재 · 글 · 영상 대본 · 운영**에서는 RSS 소재, 링크 본문, AI 글·대본, CSV 성과 분석, 내부 발행 계획, 반복 지시, 자산 보관함을 사용한다. AI 결과는 검토 후 사용한다. 현재 MP4는 카드별 3초인 무음 슬라이드다.

유경이의 별도 컴퓨터에서는 Rita-agent를 별도로 clone하고 `cora/project-bootstrap` 브랜치를 받아 개인 작업 브랜치를 만든다. `Cora/apps/trend-hub`에서 `node scripts/run-local.mjs`로 실행한다. Node 22.13 이상, AI는 Python llmgw의 개인별 설치·설정, 영상은 FFmpeg가 필요하다. 교수님의 비밀키나 공유 Drive의 운영 DB를 복사하지 않는다. GitHub 사용자명이 아직 없어 실제 저장소 권한 초대는 하지 않았다.

## 실제로 확인한 것

|---|---|---|
|프로덕션 빌드|통과|Next 15.5.26, 최종 코드 빌드 로그|
|단위 시험|331 통과, 1 제외|Cora 9개 시험 포함. 나머지 다수는 기존 Trend 시험. 원본 관측 DB가 없는 시험 1개 제외|
|기존 운영 회귀|7개 경로 통과|브랜드 저장/복원, 검토 상태 무효화, 필터, 사본, 삭제/복원, 카드 추가/삭제, 타 계정 차단|
|새 작업실 통합|11개 경로 통과|소재 저장, CSV 분석, 달력, 반복 지시, 실제 URL/RSS, 실제 AI 블로그/카드, MP4, 재접속, 무인증 차단|
|직접 생성·디자인|5개 경로 통과|실제 AI 3장 생성, PNG 세 비율, 서체/디자인 서버 저장|
|MP4 파일 검사|통과|ffprobe: H.264, 1080×1920, 18초, 음성 없음|

PNG 검수는 다운로드한 ZIP 안 PNG 헤더의 실제 너비·높이를 확인했다: 1080×1080, 1080×1350, 1080×1920. AI 시험은 실제 게이트웨이 연결로 수행했으며 모형 응답으로 대체하지 않았다. RSS는 이번 시험에서 80개 중복 제거 결과, 실패 피드 0개였다. 외부 출처는 다음 실행 때 결과가 바뀔 수 있다.

재현 스크립트: 앱의 `scripts/cora-operations-proof.mjs`, `scripts/cora-sprint-proof.mjs`, `scripts/cora-design-proof.mjs`. Playwright/Chrome이 필요하다. 시험 서버 기본 포트는 3211이며 사용자 자료와 분리한 CORA_DATA_DIR로 실행한다. 실제 AI 호출 시험은 공급자 사용량이 발생할 수 있다.

## 아직 완료가 아닌 부분

- 달력은 내부 계획이며 SNS 예약 전송이 아니다. 자동화 레시피는 저장/수동 실행이며 타이머가 아니다.
- CSV 진단은 수동 자료 계산이다. Instagram OAuth·지표 동기화·계정 비교·ML 예측은 없다.
- 팀/고객 승인, 댓글/DM, 목소리 복제, 음악/자막 편집, PDF/YouTube 자료 추출, 링크 페이지, 결제, API/MCP 등은 전체 원장에 남아 있다.
- GitHub 원본 카드뉴스 폴더는 현재 README만 확인했다. 배포된 원본 앱의 전체 코드를 통합했다고 주장하지 않는다.
- 생성 모델 비용은 게이트웨이 단가 미등록으로 미확인이다. 하루 10회 한도는 로컬 안전장치이며 상용 과금제가 아니다.
- 기존 Trend API의 사용자 격리, 분산 실행/큐, 운영용 인증/백업, 남은 의존성 보안 문제를 해결해야 고객 공개 운영이 가능하다. npm audit는 업그레이드 후 4개 항목(중간 3·높음 1)을 보고했다. 일부 해소는 Next 메이저 업데이트를 요구한다.

## 다음 코드 구현 순서

1. 원본 Trend 경로 격리, 공통 작업/권한 기반과 팀 검토 버전 연결.
2. Sabrina에서 채택한 계정 선택→확정 콘텐츠→게시 요청→결과 확인 구조를 실제 게시 어댑터로 구현. 외부 키/계정이 없으면 모의 계약 시험과 실제 연결 대기를 구분.
3. 반복 작업 스케줄러, 실패/결과 불명 처리, 작업 내역. 게시 계획과 실제 예약 큐 연결.
4. 영상 장면 편집·자막/음성·미디어 입력. 카드 템플릿/자유 편집 보강.
5. 공식 지표 수집과 진단→다음 콘텐츠 제작 연결, 나머지 전체 기능 원장 구현.

독립 모듈은 공통 데이터 계약 위에서 함께 진행한다. 문서 몇 개 완료를 기다리는 단계별 승인 방식으로 진행하지 않는다. 외부 계정/권한이 필요한 작업 때문에 다른 코드 구현을 멈추지 않는다.
