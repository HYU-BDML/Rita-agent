# Cora 집중 구현 기준

2026-09-30. 사용자 정정 반영: 12주 동안 조금씩 MVP를 만드는 방식이 아니라, **1~2일 집중 구현을 목표로 기능을 최대한 연결한 뒤 유경이가 실제로 쓰고 직접 수정한다.** 12주는 이후 고객 검증·개선의 참고 일정이다. Mirr 109개 기능은 모두 목표 목록에 유지하며 10개 추가 채택 기능과 함께 119개 원장으로 관리한다. 기능 간 중복은 묶어서 구현하되 목표 행을 삭제하지 않는다.

## 구현 순서

1. B01 공통 계정·저장·권한/작업 원장, B02 자료 수집, B03 기존 트렌드 자료를 제작 입력으로 연결.
2. B04 브랜드 규칙·템플릿, B05 실제 AI 카드와 편집·내보내기, B07 실제 글/대본 생성. 독립 기능은 공통 기반 위에서 함께 연결.
3. B06 영상 장면·음성/자막·렌더, B08 반복 제작, B09 계정/게시/예약·실패 복구, B11 진단/분석.
4. B10 댓글/DM, B12 링크 페이지, B13 사용량/결제, B14 API/MCP, B15 소개/도움말/제휴.
5. 기능별 단위·API·브라우저 회귀와 실제 외부 성공 증거. 학생에게 전체 사용 경로와 수정 권한/브랜치 안내 전달.

P0/P1/P2는 구현 순서이며 제외 목록이 아니다. 1~2일은 집중 구현 목표이지 119개 외부 기능의 운영 검증 보장이 아니다. 화면/API만 만든 항목과 실제 브라우저 검증 항목, 계정/키/심사 대기 항목을 구분한다. 유료 공급사 계약·플랫폼 권한 심사는 코딩 속도로 대체하지 않는다.

## 이번 즉시 진행

공통 work_items 저장소, 기존 RSS 수집 재사용, 공개 URL 본문 추출, 실제 llmgw 카드/블로그/영상 대본/소재 생성, CSV 근거 분석, 운영 작업 화면을 구현 중이다. 자동화의 수동 실행과 타이머 실행, 게시 계획과 실제 SNS 예약, 대본과 영상 MP4를 각각 구분해 완료 처리한다.

기능의 자세한 원문 입력·출력·미확인 사항은 기능별_개발원장.csv에 있다. 과거 7개 문서 작업 완료표를 제품의 완료율로 사용하지 않는다.
