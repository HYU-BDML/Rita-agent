# 게시 큐와 결과 대조 — 로컬 모의 검증

2026-09-30. 유료 AI 호출 0회, 실제 외부 게시 요청 0회.

## 추가한 기능

게시 준비함에서 승인된 준비 작업의 ‘모의 큐 등록’을 누른다. ‘모의 단계 실행’으로 접수 상태를 만들고, 10초 이상 지난 뒤 다시 누르면 모의 결과를 조회한다. 화면은 ‘모의 완료 (실제 게시 아님)’로 표시한다. 실제 SNS 계정·외부 공급자에 요청하지 않으며 자동으로 반복 실행하는 스케줄러도 아직 없다.

작업 상태와 전환 이력은 SQLite에 저장한다. 페이지 새로고침과 저장소 재연결 후에도 같은 작업을 유지한다. 같은 준비 작업을 다시 등록해도 새 작업이 생기지 않는다. 등록·조회·진행·취소·이력 조회는 해당 소유자에게만 허용한다.

## 실행 규칙

- 전송 직전 트랜잭션에서 승인 버전, 원본 버전, 검토 회수 여부, 준비 취소 여부를 다시 확인한다. 조건이 바뀌면 실행을 중단한다.
- 전송 권한을 30초 동안 한 실행자가 잡는다. 두 DB 연결에서 동시에 시작해도 모의 전송은 한 번만 수행한다.
- 접수 전에만 큐 취소가 가능하다. 접수 이후의 실제 공급자 취소를 흉내 내지 않는다.
- 전송 중 작업이 끊겨 30초가 지났으면 다음 단계 실행 때 결과 불명으로 바꾼다. 무조건 재전송하지 않는다. 늦게 돌아온 이전 실행 결과도 무효화된 실행권으로 덮어쓰지 못한다.
- 접수 ID가 있는 작업은 최소 10초 간격으로 결과를 대조한다. 조회 응답의 ID가 다르면 결과 불명으로 유지한다. 이후 올바른 응답이 오면 상태를 갱신할 수 있다.
- 접수 ID 없이 결과가 불명확하면 자동 복구하거나 성공으로 표시하지 않는다. 현재는 수동 조사 필요 상태로 남는다.
- 원본 삭제 후에는 큐의 콘텐츠 사본을 비우고, 작업 상태·시각·전환 이력만 남긴다. 이미 시도한 작업의 운영 기록은 원본 삭제와 구분한다.

## 검증

프로덕션 빌드 및 전체 단위 시험 342개 통과, 기존 데이터 의존 시험 1개 제외. Cora 관련 TypeScript 시험은 총 20개이며 이번 큐 시험 5개에 재시작, 동시 실행, 타임아웃, 늦은 응답, ID 불일치, 승인 변경, 취소, 원본 삭제, 권한 분리를 포함했다.

브라우저/API 8개 경로를 검수했다. 승인본 준비, 중복 준비, 계정 격리, 큐 등록·단계 실행, 새로고침 후 상태 유지, 모의 완료와 이력 조회, 원본 변경, 취소를 확인했다. 큐의 상태 복구와 동시 실행은 단위 시험에서, 실제 화면 사용 경로는 브라우저에서 검증했다.

재현: apps/trend-hub/scripts/cora-queue-proof.mjs 및 tests/cora-queue.test.ts. 증거는 검증기록/queue-proof.json과 queue-unit-tests.txt, 화면은 outputs의 증거/queue에 저장한다.

## 아직 완료하지 않은 범위

이 큐는 simulation 모드만 저장하도록 제한했다. Blotato 어댑터와 실제 실행 큐는 연결하지 않았다. 사용자별 자격 증명·대상 계정 소유권·승인 미디어 URL 검증, 실제 공급자 응답과 게시물 대조, 주기적 작업 스케줄러, 다중 서버 배포, 실제 예약 취소, 접수 ID 없는 결과 불명 작업의 운영 복구 절차가 남아 있다. 자동 반복 생성이나 SNS 자동 운영을 완료했다고 주장하지 않는다. E204는 부분 구현 상태를 유지한다.
