# 글·대본의 기존 자산 수정 저장

2026-09-30. 유료 API 호출 0회.

자산 보관함에서 블로그 글·영상 대본·생성 아이디어를 열고 본문을 수정한 뒤 ‘기존 자산에 수정 저장’을 누른다. 원래 자산 ID를 유지하며 출처, 생성 공급자·모델 등 다른 정보는 보존한다. 수정 시각과 사람이 편집했다는 표시를 저장한다. 기존 ‘편집본 새로 저장’도 별도 사본이 필요할 때 사용할 수 있다.

서버는 소유자를 확인하고, 화면에서 열었던 본문과 현재 저장된 본문을 비교한 뒤 트랜잭션 안에서 수정한다. 다른 창에서 먼저 본문을 바꾸면 409 충돌로 거절한다. 이때 입력 중인 문구는 화면에 남아 파일로 내려받거나 복사할 수 있다. 보관함에서 최신 자산을 다시 열기 전에 편집본을 보관하라는 안내를 표시한다.

API는 본문이 있는 blog/script/material만 허용하고 분석 결과·영상·게시 작업 등 다른 종류는 거절한다. 본문은 공백만 입력할 수 없으며 최대 50,000자다. 이것은 본문 충돌 보호이며, 전체 편집 이력 복구·실시간 공동 편집·AI 동시 수정 시스템은 아니다. 소재 일반 편집 화면에는 이번 버튼을 추가하지 않았다.

## 검증

프로덕션 빌드, 전체 단위시험 349개 통과·기존 데이터 의존 시험 1개 제외. 신규 단위시험은 자산 ID·출처 유지, 중복 미생성, 오래된 본문 저장 거절, 타 계정·비본문 자산 거절을 확인한다. 브라우저 2개 경로에서 기존 자산 수정과 서버의 선행 변경 이후 충돌 안내·편집본 보존을 확인했다.

재현: tests/cora-text-edit.test.ts, scripts/cora-text-edit-proof.mjs. 검증기록/text-edit-proof.json 참조. 기존 글·대본 기능의 보강이며 전체 Mirr 문체 학습이나 AI 수정 기능의 완료로 처리하지 않는다.
