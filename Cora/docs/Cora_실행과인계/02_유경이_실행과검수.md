## 이번 프로젝트에서 할 일

Cora는 여러 브랜드의 콘텐츠를 만드는 작은 팀의 작업을 돕는 서비스다. 첫 작업은 카드뉴스와 캡션 제작이며, 이후 소재 탐색·고객 검토·계정 게시·성과 해석을 연결한다. 처음부터 모든 기능을 개발하는 과제가 아니다. 임보람 교수와 AI가 만든 실행본을 실제 자료로 써 보고, 막힌 지점을 정확히 재현하고, 작은 개선을 AI와 구현해 확인한다.

먼저 `01_전체로드맵.html`에서 고객·가치·MVP·12주 계획을 읽는다. 상세한 판단은 `01_사업과제품_실행계획.md`에 있다. 현재 완료 상태는 `00_진행체크리스트.md`와 `04_검증결과.md`를 본다. ‘구현됨’과 ‘실제 고객에게 효과가 확인됨’은 다르다.

## 실행 방법

임보람 교수 컴퓨터에서는 http://127.0.0.1:3210/studio 로 접속한다. 다른 컴퓨터에서 이 주소를 열면 교수 컴퓨터에 연결되지 않는다. 자신의 컴퓨터에서 별도로 실행해야 한다.

1. GitHub의 HYU-BDML/Rita-agent 접근 권한을 확인한다. 비공개라면 조직 초대가 필요하다. 비밀번호나 개인 토큰을 채팅으로 공유하지 않는다.
2. Node.js 22.13 이상(권장 22.22)과 Git을 설치한다. Node 확인 명령은 `node --version`이다.
3. 동기화 폴더 밖의 일반 작업 폴더에서 아래 명령을 실행한다. 이미 체크아웃이 있으면 새로 덮어쓰지 말고 현재 변경부터 확인한다.

```bash
git clone --branch cora/project-bootstrap --single-branch https://github.com/HYU-BDML/Rita-agent.git
cd Rita-agent/Cora/apps/trend-hub
node scripts/run-local.mjs
```

4. 브라우저에서 http://127.0.0.1:3210/studio 를 연다. 로컬 시험 계정을 만든다. 이메일은 식별용이며 인증 메일은 발송하지 않는다. 비밀번호는 10자 이상, 다른 서비스에서 쓰지 않는 것으로 만든다.
5. 시험이 끝나면 터미널에서 Ctrl+C로 서버를 종료한다. 다시 실행해도 `data/cora`의 DB는 유지된다. 폴더를 통째로 삭제하면 보관 데이터도 잃을 수 있으므로 필요한 작업은 JSON으로 백업한다.

처음 실행하면 의존성을 인터넷에서 내려받는다. 설치·빌드는 OS 임시 폴더, 작업 DB는 앱 안의 `data/cora`에 저장된다. Drive로 같은 SQLite를 여러 컴퓨터에서 동시에 사용하지 않는다. 코드는 Git으로 공유하고 사용 자료는 권한과 보관 범위를 정해 따로 전달한다. 아직 원격 공동작업 서비스가 아니다.

Windows·Safari는 이번 자동 시험 범위 밖이다. 실행 오류가 있으면 OS, Node 버전, 명령, 오류 전문에서 비밀값을 가린 기록을 남긴다. 로컬 포트 충돌 시 다른 앱을 임의 종료하지 말고 오류를 기록한다. macOS에서 임시로 `CORA_PORT=3212 node scripts/run-local.mjs`로 실행할 수 있다.

## 첫 4.5시간 배정

| 시간 | 할 일 | 남길 것 |
|---|---|---|
| 30분 | 전체 로드맵·역할 읽기 | 제품이 누구의 어떤 일을 돕는지 한 문단 |
| 30분 | 설치와 예시 실행 | 실행 환경, 첫 PNG ZIP |
| 60분 | 실제 사용할 권한이 있는 브랜드 자료로 제작 | 입력 출처, 완성 카드, 캡션, 작업시간 |
| 60분 | 아래 기능 검수 | 테스트 CSV의 결과·증거·재현 절차 |
| 60분 | 가장 중요한 오류 1개 재현/AI와 수정 제안 | 별도 브랜치와 변경 내용, 전후 결과 |
| 30분 | 교수와 다음 작업 결정 | 다음 한 주의 작업 하나와 완료 기준 |

처음부터 모르는 기술 전체를 공부하느라 시험을 미루지 않는다. 단, 시험하지 않은 코드를 동작한다고 제출하지 않는다. 시간 안에 못 끝내면 완료한 부분과 막힌 조건을 구분한다.

## 첫 사용자 경로

1. 예시 불러오기 → 브랜드 작업 메모 작성 → 현재 브랜드 설정 저장.
2. 새로고침 → 저장한 브랜드 선택 → 이름·대상·목표·색상·메모가 다시 적용되는지 확인. 브랜드 메모는 현재 보관용이다. 생성 규칙으로 자동 적용되지 않는다. 같은 이름으로 다시 저장하면 새 설정이 추가된다. 설정 수정·삭제 화면은 후속 과제다.
3. 내 자료를 넣고 방향 선택. 원문에 없는 사실이 추가됐는지, 문구를 얼마나 고쳐야 하는지 기록한다. 현재 초안은 규칙 기반이며 AI 생성이 아니다.
4. 카드 제목·본문·사진·순서·색상을 바꾼다. 추가·삭제도 시험한다. 원본과 미리보기를 비교한다.
5. 검토 메모를 남기고 작업 상태를 바꿔 저장한다. ‘내 검토 완료’는 자신의 작업 상태이지 고객 승인/게시 완료가 아니다. 완료 후 문구를 바꾸고 저장하면 ‘작성 중’으로 되돌아와야 한다.
6. 보관함에서 브랜드·상태를 필터링한다. 저장본을 다시 열어 확인한다.
7. ‘새 사본 만들기’ → 수정·저장. 원래 작업이 유지되고 새 작업으로 보관되는지 확인한다.
8. PNG 묶음 내보내기. ZIP 안의 이미지·캡션·project.json을 확인한다. JSON은 백업·복원 파일이다. renderer-contract.json은 기존 렌더러 호환용이며 외부 렌더가 실행됐다는 뜻은 아니다.
9. 보관함에서 project.json을 불러온다. 새 작업이며 원래 ID·게시 URL·검토 완료 상태를 이어받지 않아야 한다. 저장해야 보관함에 남는다.
10. 시험 사본만 삭제한다. 다른 계정에서는 내 브랜드 설정과 작업을 볼 수 없어야 한다. 중요한 실제 자료를 삭제 시험에 쓰지 않는다.

## 문제 보고 방식

`03_기능검수표.csv`를 복사해 실행한다. 기존 자동 검증은 `증거/`에 있고, 학생의 결과는 빈칸이다. 자동 시험이 통과했다고 학생 칸에 합격을 미리 채우지 않는다.

한 문제에 포함할 내용: OS/브라우저·버전 / 사용자 목표 / 입력 자료 식별자 / 클릭 순서 / 기대 결과 / 실제 결과 / 반복 여부 / 화면 또는 파일 / 심각도 / 수정 후 재시험 결과. 비밀번호·토큰·고객 개인정보를 첨부하지 않는다.

예: ‘두 번째 카드 문구를 수정→저장→새로고침→보관함에서 열기. 기대는 수정 문구 유지, 실제는 이전 문구. 3회 중 3회 발생. 시험 자료 A, 스크린샷 A-03.’ ‘안 돼요’ 한 줄보다 수정에 필요한 정보가 훨씬 많다.

심각도는 P0=타인 자료 노출·오게시·중복 결제, P1=주요 작업 불가·데이터 손실, P2=일부 기능/표시 문제, P3=개선 제안이다. P0/P1은 사용을 멈추고 교수에게 알린다. 학생에게 상시 장애 대응을 맡기지 않는다.

## 고객 관찰 시 질문

고객에게 아이디어를 칭찬해 달라고 요청하지 않는다. 최근 실제 게시물 하나를 기준으로 묻는다: 자료를 누구에게 받았는가, 어떤 도구를 거쳤는가, 어떤 부분을 다시 고쳤는가, 누가 승인했는가, 다음 제작은 언제인가, 현재 무엇에 비용을 내는가. 화면 조작을 대신해 주었다면 그 시간도 기록한다.

`03_사용실험기록.csv`에는 고객군·자료·기존 방식/Cora·작업시간·지원시간·사실 오류·실제 채택·다음 주 재사용·유료 선택을 각각 적는다. 같은 자료를 두 번 사용하면 학습 효과가 생기므로 순서를 교차하거나 비슷한 난이도의 자료를 사용하고 조건을 기록한다. 적은 수의 평균만으로 시장 전체의 시간 절감을 주장하지 않는다.

## AI와 코딩할 때

새 작업 전에 `git status`로 수정사항을 확인하고 `Cora/` 안에서만 작업한다. 예: `git switch -c cora/yukyung-library-empty-state`. 다른 사람이 작업한 브랜치를 덮어쓰거나 강제로 push하지 않는다. 변경은 PR에서 비교한다. 키와 DB는 커밋하지 않는다.

AI 요청 예시: ‘Cora 보관함에서 필터 결과가 0개일 때 안내 문구가 없다. 원본 프로젝트는 보존하고 Cora 안에서 수정해 줘. 결과 없음 상태와 필터 초기화 버튼을 추가하되, 기존 보관함 열기를 유지해 줘. 브라우저에서 결과 0개→초기화→다시 열기를 검증하고 변경 파일과 결과를 알려줘.’

한 번에 한 사용자 문제를 맡긴다. 완료 기준을 먼저 적고, 화면 확인과 저장 후 재열기까지 본다. AI가 만든 시험 결과도 직접 증거 파일을 확인한다. 이해하지 못한 권한·토큰 처리 변경을 그대로 공개 배포하지 않는다.

## 개발자에게 넘길 묶음
