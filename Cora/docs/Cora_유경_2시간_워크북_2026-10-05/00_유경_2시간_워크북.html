유경의 2시간 첫 사용 워크북

가상 고객사 두 곳을 구분하고, 한 고객사의 이번 주 카드뉴스 한 묶음을 완성해 주세요.

목표는 칭찬이나 전체 기능 검사가 아니라 혼자 만들 수 있는지 · 어디서 막히는지 · 무엇을 고쳐야 쓸 만한지를 찾는 것입니다.

워크북 ≠ Cora 앱

이 파일은 안내와 피드백 수첩입니다. 실제 제작은 Cora를 별도 탭에서 열어 진행합니다.

이 파일은 응답을 교수님이나 Drive에 자동 전송하지 않습니다. 마지막에 파일을 내려받아 제출해 주세요.

0–20분 · 준비

먼저 실행하고, 목표를 확인하세요

최종 제출물은 세 가지입니다.
  1. 이 워크북에서 내려받은 피드백 JSON + 읽기용 보고서
  2. Cora에서 만든 카드 PNG ZIP + 작업 JSON
  3. 문제가 보인 화면 캡처(있을 때만)

실행이 막혔다면 2번 없이, 오류·시도한 방법·환경을 기록해서 제출하면 됩니다.

Cora는 여러 브랜드의 SNS를 정기 제작하는 작은 대행사·프리랜서 팀을 위한 서비스입니다. 고객사 규칙과 근거 자료 → 주간 제작 → 카드·캡션 → 수정·승인 → 게시·성과를 잇는 것이 제품 목표입니다. 이번 시험은 근거 자료부터 카드 저장·내보내기까지만 다룹니다.

실제 게시는 하지 않습니다. 합성 자료를 사용하고 AI 생성·광고 생성·Instagram 연결 버튼은 누르지 마세요. 현재 자료 기반 초안은 원문 발췌이며, AI 글쓰기 품질 시험이 아닙니다. 운영 계정 bdm.lab도 연결하지 않습니다.
실행 방법 — 해당하는 한 가지만

교수님 컴퓨터라면

교수님/AI에게 새 시험 DB로 서버 준비를 요청하세요. 운영 DB를 함께 열지 않습니다. 현재 공유 배포본은 없으며 서버가 준비되어야 아래 주소가 열립니다.

유경의 컴퓨터라면

  1. 전달 ZIP을 풀고 그 안의 Cora_첫사용_소스.zip을 다시 풉니다. 동기화 폴더 밖의 일반 작업 폴더를 사용하세요. GitHub 가입은 필요 없습니다.
  2. Node.js 22.13 이상에서 터미널로 node --version을 확인합니다.
  3. 소스의 Cora/apps/trend-hub 폴더로 이동한 뒤 아래 명령을 실행합니다. 첫 실행은 인터넷으로 패키지를 설치합니다.
node scripts/run-local.mjs

DB와 키는 제출하지 않습니다. 교수가 쓰는 원본 코드를 덮어쓰지 않고, 첫 회에는 소스 수정도 하지 않습니다. 학생 Mac/Windows 실제 설치는 아직 검수하지 않았으므로 실패도 기록할 대상입니다.

소스 ZIP 받기

전달 묶음을 풀면 HTML과 소스 ZIP이 나란히 있습니다. 소스 링크가 안 열리면 같은 폴더의 ZIP을 직접 여세요.

Cora 열기 ↗

이 주소는 지금 브라우저가 열린 컴퓨터의 서버를 가리킵니다. 다른 PC에서 교수님의 서버에 원격 접속하는 주소가 아닙니다. 모바일로 워크북을 기록할 수 있지만, 카드 제작 시험은 PC로 하세요.

  1. Cora에서 시험 계정을 만듭니다. 식별용 이메일과 다른 서비스에 쓰지 않는 10자 이상 비밀번호를 사용하세요. 비밀번호는 이 워크북에 쓰지 않습니다. 인증 메일은 현재 발송하지 않습니다.
  2. 다음 단계부터 처음 10분은 혼자 찾아보세요. 이후 도움을 받아도 괜찮습니다. 누가 어느 부분을 설명했는지, 도움 시간을 따로 기록하세요.
20분 넘게 실행이 막히면 중단하세요. 오류 문구·OS·시도한 순서를 Y01에 기록하고 판정을 ‘막힘’으로 선택한 다음 ‘제출’ 단계로 가세요. 남은 검사는 ‘미실행’ 그대로 둡니다.
20–35분 · 고객사

가상 고객사 A와 B를 만드세요

Cora의 왼쪽 고객사 → 새 고객사에서 아래 두 고객사를 저장하세요. 클릭 위치를 못 찾으면 그것도 기록합니다. 규칙은 제품에 입력하고, 이 워크북에는 불편점만 기록합니다.

  1. A를 만들고 규칙을 입력·저장합니다.
  2. B도 만든 뒤 다시 A를 선택합니다.
  3. A의 이름·색상·말투·규칙 근거가 유지되는지 확인합니다.

처음에는 계정 소유자로 시험합니다. 이번에는 팀 초대나 검토자 등록을 하지 않습니다.

35–60분 · 이번 주 제작

A 자료로 후보 5개를 보고, 3개를 고르세요

고객사 A를 선택하고 이번 주 제작 → 주간 콘텐츠 묶음으로 갑니다. 고객사에서 만들 3개를 계획하되, 이번 회에는 실제 카드 한 묶음만 완성합니다.

  1. 아래 A의 자료 이름·원문을 ‘주간 자료 이름 / 원문 직접 입력’에 붙입니다. URL과 게시일은 비웁니다.
  2. 직접 자료 저장 → 저장한 자료 선택 → 자료로 후보5개 만들기.
  3. 5개 중 3개에 ‘이번 주 제작’을 표시합니다. 각 후보에 선택 이유 · 본인 담당 · 같은 주 마감을 넣습니다. 후보 이름과 이유는 아래에도 기록합니다.
  4. 주 시작일은 월요일입니다. 이번 주 목표를 쓰고 주간 계획 저장을 누릅니다.
예시 시험 주 . 날짜가 지난 뒤 시험하면 실제 시험 주의 월요일과 같은 주 마감일로 바꾸세요. 후보 3개 모두 이유·담당·마감을 입력해야 초안을 만들 수 있습니다.
이 5개는 같은 원문을 다르게 구성한 편집 방향입니다. 새로운 트렌드나 독립적인 자료 5건을 찾았다는 뜻은 아닙니다. 새로고침 전 자료와 주간 계획을 직접 저장하세요. 주간 폼의 미저장 입력은 자동 복구함 대상이 아닙니다.
60–85분 · 카드 한 묶음

초안을 편집하고 PNG·JSON을 내려받으세요

  1. 저장한 주간 계획의 선택 후보 하나에서 카드 초안 만들고 편집을 누르고 연결된 카드 편집 화면을 엽니다. 버튼이 비활성화라면 계획 저장과 3개 입력을 확인합니다.
  2. 4–6장의 카드와 캡션을 읽습니다. A 자료에 없는 날짜·시간·가격·신청 주소가 사실처럼 쓰였는지 찾습니다. 빠진 사실은 만들어 넣지 말고 담당자 확인 필요로 남깁니다.
  3. 첫 카드 제목 · 적어도 한 카드 본문 · 캡션을 직접 다듬습니다. 가능하면 ‘차분한 존댓말’과 ‘짧은 제목’을 맞춰 보세요.
  4. 작업 저장 → PNG ZIP 내보내기 → JSON 백업을 내려받습니다. ZIP을 풀어 PNG 한 장 이상 직접 열어 글자 잘림·가독성을 확인합니다.
자료 발췌 초안이 모든 말투·시각 규칙을 자동으로 충족한다고 가정하지 마세요. 고객사·색상·규칙 참조가 맞는지와 사람이 고쳐야 할 분량을 각각 평가합니다. 좋은 결과라고 판단되면 불필요한 수정은 하지 말고 ‘수정 불필요’ 이유를 적으세요.
85–105분 · 보존과 구분

저장·고객사 전환·다음 주 복제를 확인하세요

먼저 카드와 주간 계획을 모두 저장하세요. 20분 내 주요 검사 Y07–Y10을 우선하고, 시간이 남으면 Y11–Y12를 합니다. 못 한 검사는 그대로 ‘미실행’으로 제출합니다.

  1. Y07: 새로고침하고 저장한 주간 계획과 카드를 다시 엽니다. 바꾼 문구·카드 연결이 남아 있는지 봅니다.
  2. Y08: B를 선택해 아래 B의 원문으로 자료·후보를 만듭니다. A 카드나 규칙이 B에 섞이는지 봅니다. 다시 A로 돌아갑니다.
  3. Y09: A의 저장 계획에서 다음 월요일로 다른 주 계획으로 복제합니다. 마감은 새 주로 이동하고 카드 연결은 복제되지 않아야 합니다. 이전 주 계획·카드는 그대로여야 합니다. 같은 자료 겹침 안내를 봅니다.
  4. Y10: 주간 목표에 ‘이동 경고 시험’을 덧붙인 뒤 다른 화면으로 이동합니다. 경고에서 취소를 선택하면 입력이 남아야 합니다. 시험 문구를 지우고 저장합니다. 저장하지 않은 상태로 강제 새로고침하지 마세요.
  5. 선택 Y11: 카드 본문에 ‘복구 시험’을 덧붙이고 자동 보관 표시를 확인한 뒤 새로고침합니다. 복구함에서 현재 계정·고객사의 카드를 복구할 수 있는지 확인합니다. 성공하면 시험 문구를 제거하고 저장합니다. 주간 폼과는 다른 검사입니다.
  6. 선택 Y12: 작업 상태를 ‘내 검토 완료’로 저장한 후 문구를 수정·저장합니다. 상태가 ‘작성 중’으로 돌아가는지 봅니다. ‘내 검토 완료’는 고객 승인·게시 완료가 아닙니다.
105–120분 · 피드백

가장 중요한 문제와 다음 수정을 정하세요

문제가 적다면 없는 문제를 만들 필요는 없습니다. 가장 큰 막힘부터 최대 3건 작성하세요. 화면 캡처에는 비밀번호·API 키·개인 연락처가 보이지 않게 합니다.

시간은 구분해서 기록해 주세요

위 타이머는 단계 경과 시간입니다. 콘텐츠 제작 능동시간과 같은 값이 아닙니다. 아래는 기억·메모를 바탕으로 분 단위로 따로 기록합니다. 모르면 비우세요.

첫 회에는 관찰·재현·제안까지 합니다. 개선 코딩은 제출 이후 별도 학생 복사본에서 Claude와 진행하세요. 교수님과 같은 원본을 동시에 수정하지 않습니다. 이 시험은 사용성 확인이며 대행사 고객의 지불의사·수요를 증명하는 시험은 아닙니다.
제출 / 교수님 보기

내려받은 파일을 제출하면 끝입니다

임시 저장 ≠ 제출. 응답은 이 브라우저에만 임시 저장됩니다. Drive 원본 HTML이 바뀌거나 교수님에게 전송되지 않습니다. 다른 브라우저·기기·파일 경로에서는 임시 저장이 없을 수 있습니다. JSON을 내려받아 보관하고, 아래 폴더에 파일을 올려 주세요.
  1. 피드백 JSON과 읽기용 보고서(.md)를 내려받습니다. 미완성 응답도 내려받을 수 있습니다.
  2. Cora의 PNG ZIP·작업 JSON과 캡처를 함께 모읍니다. 피드백 JSON과 Cora 작업 JSON은 서로 다른 파일입니다.
  3. 공유 Drive의 조유경(소셜미디어)/outputs/조유경_10주/제출/시험일_조유경_첫사용/에 올립니다. 예: 2026-10-05_조유경_첫사용. 접근 권한이 없으면 교수님에게 내려받은 파일들을 전달하고 권한을 요청합니다.
  4. 교수님께 ‘첫 사용 완료/실행 막힘, 제출 폴더, 가장 큰 문제 한 줄’을 알립니다. 워크북은 알림을 보내지 않습니다.

파일은 브라우저의 다운로드 폴더로 갑니다. 다운로드 후 실제 파일이 있는지 확인하세요. 제출 버튼으로 합격 판정이 자동 입력되지는 않습니다.

제출 내용 미리보기 / 교수님 검토

교수님: 제출 JSON을 다시 열어 보기 / 학생: 다른 PC에서 이어 쓰기

아래에서 피드백 JSON을 가져오면 이 워크북의 응답 칸과 미리보기가 복원됩니다. 기존 응답을 바꾸기 전에 확인창이 뜹니다. Cora 작업 JSON은 이곳이 아니라 Cora의 ‘JSON 백업 불러오기’에서 여세요.

새 시험으로 초기화

필요하면 JSON을 먼저 백업하세요. 초기화는 이 워크북 응답만 지우고 Cora 작업물은 바꾸지 않습니다.
