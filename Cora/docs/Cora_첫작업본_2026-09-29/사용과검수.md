# Cora 첫 작업본 — 사용과 검수

2026-09-29. 임보람·조유경·AI가 12주 동안 합의한 출시 범위의 90% 이상 구현을 목표로 한다. 이 작업본은 첫 번째 실제 제작 흐름이며 전체 제품의 90%가 완성되었다는 뜻은 아니다.

## 지금 사용 가능한 것

로컬 계정 가입·로그인 → 브랜드 자료 입력 → 세 가지 구성 방향 선택 → 카드 제목·본문·사진·색상·순서 편집 → 사용자별 서버 저장 → 보관함에서 다시 열기 → PNG와 캡션 ZIP 다운로드.

자료는 사용자가 제공한다. 초안은 규칙으로 구성하며 AI 생성이 아니다. 링크는 출처로 저장할 뿐 본문을 수집하지 않는다. 실제 게시 URL은 사용자가 기록한다. 제작·편집 흐름부터 시험하기 위한 첫 구현이다.

## 이 컴퓨터에서 사용

http://127.0.0.1:3210/studio 를 연다. 로컬 계정을 만든다. 이메일 인증을 하지 않으므로 시험용 이메일과 다른 서비스에서 쓰지 않는 비밀번호로 시작할 수 있다. 비밀번호는 10자 이상이다. 현재 서버가 종료되면 아래 명령으로 다시 실행한다.

```bash
cd Cora/apps/trend-hub
node scripts/run-local.mjs
```

Node.js 22.13 이상, 권장 22.22. 첫 실행 때 의존성을 다운로드한다. 서버는 이 컴퓨터에서만 접속된다. 유경이 컴퓨터에는 GitHub의 `cora/project-bootstrap` 브랜치를 별도로 내려받고 같은 명령을 실행한다. SQLite 파일을 여러 컴퓨터에서 동시에 사용하는 방식으로 협업하지 않는다. 원격 공동 시험용 배포는 후속 작업이다.

소스를 바꾸면 실행기를 종료하고 다시 시작한다. 의존성과 빌드는 OS 임시 폴더에 있고, 사용자 DB는 앱의 `data/cora/studio.sqlite`에 남는다. DB와 비밀키는 Git으로 보내지 않는다. JSON 백업은 현재 다운로드만 지원하며 가져오기 화면은 후속 작업이다.

## 유경이의 첫 검수 — 30~45분

1. 가입 후 ‘예시로 먼저 해보기’를 눌러 한 번 끝까지 진행한다. 소재 방향마다 설명을 읽고 하나를 고른다.
2. 두 번째 카드 제목과 본문을 바꾸고 직접 사용할 권한이 있는 사진을 올린다. 카드 순서를 바꾸고 색상을 바꾼다. 추가·삭제도 직접 시험한다.
3. 저장하고 새로고침한 뒤 콘텐츠 보관함에서 다시 연다. 문구·사진·순서가 남아 있는지 비교한다.
4. PNG 묶음을 내려받아 압축을 푼다. 카드 이미지와 캡션을 실제 사용할 수 있을지 평가한다. 글 잘림·사진 잘림·줄바꿈이 어색한 부분을 기록한다.
5. 로그아웃 후 다시 로그인한다. 별도 브라우저의 다른 계정에서는 첫 계정의 콘텐츠가 보이지 않는지 확인한다.
6. 본인이 고른 작은 브랜드의 실제 자료로 다시 만든다. ‘처음 결과까지 걸린 시간’, ‘수정한 횟수’, ‘도움을 요청한 위치’, ‘그대로 게시할 의향’을 적는다. 연구 목적의 성장 효과는 아직 측정하지 않는다.

문제 기록 양식: 작업 목적 / 누른 순서 / 기대한 결과 / 실제 결과 / 화면 캡처 / 반복 여부 / 중요도. 파일과 비밀키·비밀번호·고객 개인정보는 분리한다. 예시만 잘 되는지보다 실제 자료에서 막히는 부분이 중요하다.

## 검증 기록

- 프로덕션 빌드 성공.
- 단위 시험 327개 중 326개 통과, 실패 0개, 원본 관측 DB를 요구하는 기존 recipe 시험 1개 명시적 건너뜀.
- 실제 Chrome: UI 가입, 문구·사진 편집, 순서 변경, 저장·새로고침·다시 열기, PNG ZIP, 오래된 창의 저장 충돌, 다른 계정의 조회/수정 차단, 외부 Origin 수정 차단, 로그아웃·재로그인, 390px 화면 확인 통과.
- ZIP CRC 검사, PNG 6장의 1080×1350 크기, 저장된 카드 순서와 문구 확인.
- 증거: proof.json, 01~04 PNG. 시험은 가상 책방 자료와 가상 계정으로 진행했으며 유료 API와 실제 SNS 게시를 실행하지 않았다.

## 다음 구현 순서와 담당

| 순서 | 내가 구현·검증할 것 | 임보람·유경이가 판단·제공할 것 |
|---|---|---|
| 1 | 첫 편집 흐름의 오류·불편 수정, 템플릿/줄바꿈 개선 | 실제 자료로 시험하고 게시할 만한 품질인지 판단 |
| 2 | 올라오는 카드뉴스 소스의 Cora 사본 통합, 실제 생성 성공/실패/비용 기록 | 소스 위치, 시험 계정 및 비용 범위 |
| 3 | 트렌드 소재를 브랜드별 제작안으로 연결, 다중 브랜드와 승인 흐름 | 브랜드 2~3개와 소재 선택 기준 |
| 4 | n8n+Blotato 계정 연결·즉시/예약 게시·결과 URL·중복 방지 | 본인 시험 계정 연결, 명시적으로 승인한 시험 게시물 |
| 5 | 공식 API 지표 수집과 근거를 보여주는 진단·다음 제작 제안 | 분석 목적, 동의받은 계정 데이터와 전문가 피드백 |

각 단계는 기능의 완료 조건으로 확인한다. 나는 인증·API·서버도 구현 범위에 포함한다. 개발자에게 모든 연동을 넘기지 않는다. 실제 계정 로그인·앱 등록·결제 및 사람의 콘텐츠 품질 판단은 사용자의 참여가 필요하다.

## 개발자 검토 및 출시 전 미해결 목록

- 기존 Trend 경로는 새 Cora 인증 범위 밖이다. 전체 앱 공개 전 레거시 API를 보호하거나 별도 서비스로 분리해야 한다.
- 복사한 Next 15.1.6 및 의존성 보안 업데이트, 취약점 점검과 회귀 시험이 필요하다. 이번 빌드 성공이 배포 보안 검토를 대체하지 않는다.
- 현재 계정은 로컬 MVP다. 이메일 확인/비밀번호 재설정, 인증 공격 제한의 공유 저장소, 계정·콘텐츠 삭제, 팀 역할 권한, 운영 로그를 보완한다.
- SQLite 단일 서버에서 시작했다. 운영 환경의 영구 저장·백업 복원·동시 사용·DB 이전 전략을 검증한다. 사진은 현재 DB에 작은 압축 이미지로 저장한다. 규모가 커지면 비공개 객체 저장소로 이전한다.
- 게시 연결에는 OAuth/토큰 보호·갱신·해제, 고객사별 권한 분리, 예약 작업의 재시도·중복 방지·실패 알림·삭제 요청 처리가 필요하다. 아직 게시 기능을 연결하지 않았다.
- 진단은 아직 없다. 데이터 접근 가능 범위, 지표 정의, 기준선과 표본 부족 처리, 시계열 검증 및 누수 방지를 설계한 뒤 ML 도입 효과를 비교한다. 임의의 점수를 과학적으로 검증된 성장 진단으로 표현하지 않는다.
- 키보드/스크린리더 전체 검사, Safari 및 모바일 편집·다운로드, 긴 한국어와 다양한 사진 비율은 추가 검수 대상이다. 현재 Chrome 기본 경로만 확인했다.

위 목록을 우리가 구현하며 줄인 뒤, 남은 항목과 검증 증거를 개발자에게 넘겨 독립적으로 확인받는다. 고객 운영 전에 미해결 사항을 해결해야 하며 ‘나중에 개발자에게 넘기기’가 출시 점검을 생략하는 뜻은 아니다.
