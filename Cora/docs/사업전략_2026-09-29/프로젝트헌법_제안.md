# 프로젝트 헌법 제안

버전 0.3 · 2026-09-29. 첫 대행사 고객군은 사용자 확정 사항이다. 개인 계정 운영자와 계정 분석·제작 연결에 관한 추가 요청을 반영했다. 경쟁사의 존재만으로 진입을 배제하지 않는 원칙은 사용자의 명시적 지시를 반영했다. 나머지 운영 원칙·상품·예산·투자 기준은 이번 조사에 따른 제안이다. Rita의 기존 규칙이나 운영 시스템을 변경한 문서가 아니다.

## 목적

계정의 목표와 성과를 이해하고 다음 콘텐츠를 고르고 완성하도록 돕는다. 여러 브랜드를 운영하는 소규모 대행사를 첫 유료 공략 대상으로 두며, 자기 계정을 시작하고 키우는 개인 운영자도 제품 경험과 비교 검증에 포함한다. 그 업무에서 검증된 모듈과 실행·평가 기록을 Rita에 재사용한다.

## 원칙

| 조항 | 원칙 | 실제 적용 |
|---|---|---|
| 1 | 실제 고객의 다음 행동이 제품 범위를 정한다 | 대행사의 승인·납품과 개인의 소재 선택·제작·게시 중 해결할 일을 명확히 한다 |
| 2 | 기능 수보다 고객이 채택한 결과를 본다 | 생성 100건보다 실제 승인·납품 1건의 이유를 먼저 조사한다 |
| 3 | 고객이 이미 가진 자료로 시작한다 | 소개서·지난 승인본·새 요청으로 첫 결과를 보여주며 API키·SNS 연결을 첫 입력으로 강요하지 않는다 |
| 4 | 최초 체험과 반복 가치를 따로 검증한다 | 광고 반응·가입·무료 체험과 다음 사용·결제·갱신을 다른 지표로 기록한다 |
| 5 | 서비스 수요와 도구 수요를 따로 검증한다 | 사람이 대신 제작한 패키지 구매를 고객이 직접 쓰는 SaaS 수요로 보고하지 않는다 |
| 6 | 사람이 보정한 시간도 원가다 | 고객 노동·우리 노동·설정·지원·실행비를 구분하고 합계도 본다 |
| 7 | 경쟁사가 있다는 이유로 시장을 포기하지 않는다 | 기능의 독점성 대신 같은 고객·업무의 품질·총비용·편의·신뢰를 비교한다. 작은 개선도 반복 가치와 낮은 도입 부담으로 선택을 만들 수 있다 |
| 8 | 자동화는 권한과 확인 가능한 상태를 가진다 | 승인 버전·발행 계정·결과 ID를 연결하고 실패·중복·권한 철회를 처리한다 |
| 9 | 판단의 근거와 알 수 없는 것을 함께 보여준다 | 출처·시점·분모·미지원 지표를 표시하고 바이럴 확률·매출 효과를 지어내지 않는다 |
| 10 | 고객 데이터는 고객별로 분리한다 | 공개 트렌드와 비공개 브랜드·수정·계정 지표를 다른 접근 범위로 관리한다 |
| 11 | Rita 호환은 작은 인터페이스부터 만든다 | 입력·출력·버전·작업 ID·원가·승인 기록을 남기되 범용 마켓·정산을 동시에 만들지 않는다 |
| 12 | 수업 사용량과 상업 수요를 섞지 않는다 | 과제·친분·무료 지원과 외부 자발적 사용·결제를 분리한다 |
| 13 | 개인 운영자도 초기 제품 경험과 비교 검증에 포함한다 | 새 계정은 시작 안내, 운영 계정은 성과 기반 다음 콘텐츠를 제공한다. 대행사와의 투자 비중은 채택·재사용·결제·원가로 결정한다 |
| 14 | 실험 전에 손실 상한과 중단 조건을 적는다 | 미채택·환불·실패를 포함해 판정하고, 결과를 본 뒤 통과선을 낮추지 않는다 |
| 15 | 사업 주장은 증거 수준에 맞춘다 | 기획·구현·실행·고객 사용·결제·갱신·이익을 서로 바꿔 쓰지 않는다 |
| 16 | 낮은 가격에는 지속 가능한 원가가 따라야 한다 | 경쟁사의 가격 인하·기능 복제를 전제하고도 고객 가치와 우리 이익이 남는지 확인한다. 무료 수작업을 원가 우위로 계산하지 않는다 |
| 17 | 첫 범위와 최종 사업 규모를 구분한다 | 좁은 업무에서 이긴 뒤 인접 업무로 확대한다. 현재의 인력 부족이나 한 상품의 실패를 시장 전체의 불가능성으로 일반화하지 않는다 |

상품·과금·투자 기준의 구체적 적용은 [BM 평가와 실행 계획](BM_평가와_구체실행계획.md)을 따른다. 월 구독의 직접 기여이익이 양수여도 고객 획득·설정비를 회수할 근거가 없으면 영업을 확대하지 않는다. 첫 8주 이후 추가 개발비는 다음 작업·금액·판정 시점을 적어 별도 투자 단위로 판단한다.

## 앞으로의 투자 순서

1. 고객의 최근 실제 작업을 관찰한다.
2. 기존 자산으로 한 건을 끝내고 품질·시간을 비교한다.
3. 같은 업무의 다음 주문과 기여이익을 확인한다.
4. 고객이 직접 쓰는 도구 상품에 별도 결제·재사용이 있는지 확인한다.
5. 비지인 고객과 다른 전달 담당자에게 재현되는지 확인한다.
6. 읽기 중심 계정 분석과 다음 제작 추천은 초기부터 검증하고, 자동 발행·다중 고객사·Rita 연결은 준비 상태와 구매 이유에 따라 늘린다.

계정별 구체 흐름은 [개인 계정 성장지원과 콘텐츠 추천 설계](개인계정_성장지원과_콘텐츠추천_설계.md)를 따른다. 계정 연결이 없어도 시작 경로를 제공하고, 실제 API 데이터와 고객 제공 자료·가상 샘플을 구분한다.

초기 실험이 실패하면 전체 Rita를 실패라고 판단하지 않는다. 해당 고객·업무·가격 가설을 중단하고 재사용할 가치가 있는 코드·평가 사례만 남긴다. 반대로 이 상품이 잘 팔려도 Rita의 제3자 에이전트 거래 시장이 검증됐다고 판단하지 않는다.
