2026-09-29 보완. 개인 계정을 시작하고 키우려는 사용자를 주요 고객 후보에 포함하고, 계정 분석과 다음 콘텐츠 제작의 연결을 제품의 중심으로 둔다. 사용자가 확정한 첫 대행사 고객군을 취소하는 문서는 아니다. 실제 계정 연결·진단·발행을 실행한 결과가 아니라 제품 설계 제안이다.

1. 제품을 콘텐츠 납품 도구로만 좁히지 않는다

제품의 공통 가치는 **‘내 계정의 목표와 성과를 이해하고, 다음에 만들 콘텐츠를 고르고 완성하도록 돕는다’**로 확장한다. 대행사에게는 여러 고객사 계정을 관리하는 형태로, 개인에게는 자신의 계정 하나를 키우는 형태로 제공한다. 소재 발굴·제작·편집·발행·성과를 하나의 작업 흐름으로 연결하는 방향이다.

계정 진단은 중요한 첫 경험이 될 수 있다. 운영 중인 계정은 자신의 자료를 사용하기 때문에 추천의 이유를 납득하기 쉽고, 다음 게시물을 올린 뒤 다시 확인할 이유도 생긴다. 다만 반복 방문이나 성장이 실제로 늘어나는지는 확인해야 한다. 보기 좋은 진단서만으로 구독 유지가 보장되지는 않는다.

기존 계획에서 계정 분석을 무조건 후순위로 둔 점을 수정한다. 읽기 중심의 계정 분석과 다음 행동 추천은 초기 제품 가설에 포함한다. 자동 발행과 영상 전체 편집기는 각각 별도 구현 범위로 관리한다. 사용자가 보는 한 흐름을 만들기 위해 모든 도구를 처음부터 직접 개발할 필요는 없다.

개인 사용자 가운데 우선 비교할 집단은 이미 정기적으로 게시하며 계정을 키우려는 사람이다. 기존 콘텐츠와 다음 제작 일정이 있어 추천의 채택과 반복 사용을 관찰할 수 있기 때문이다. 완전 초보도 배제하지 않으며, 그들에게는 없는 데이터를 분석하는 대신 시작을 돕는 경로를 제공한다.

‘개인 운영자’와 Instagram의 계정 유형인 ‘개인 계정’은 구분한다. 혼자 운영하는 사람도 Creator 계정을 사용할 수 있다. 공식 분석 API 연동은 계정 유형·권한·앱 승인 조건에 맞춰 제공해야 하며, 일반 개인 계정의 비공개 통계를 임의로 가져오는 방식으로 설계하지 않는다.

4. 첫 화면은 이번 주에 만들 콘텐츠를 보여준다

계정이 연결되어 있으면 첫 화면에 다음 네 영역을 둔다.

  1. 지금 계정에서 관측한 것: 선택 기간, 사용한 게시물 수, 잘된 콘텐츠와 덜된 콘텐츠의 차이, 데이터 부족 항목.
  2. 이번 주 추천 3개: 주제, 추천 이유, 원자료·참고 출처, 형식, 필요한 사진·영상, 예상 작업량, ‘초안 만들기’ 버튼.
  3. 제작 중인 콘텐츠: 문안·카드·영상 후보를 수정하고 확정하는 작업 목록.
  4. 올린 뒤 확인할 것: 실제 게시물과 제작안을 연결하고, 같은 조건의 기존 콘텐츠와 비교할 지표.

사용자가 실제로 내린 목표를 먼저 확인한다. 팔로워 확대, 저장·공유되는 전문 콘텐츠, 상품·서비스 문의는 같은 목표가 아니다. 목표와 다른 지표가 높다고 무조건 좋은 소재로 추천하지 않는다.

새 계정은 이 화면에서 성과 수치를 꾸며 넣지 않는다. ‘계정 시작하기’를 선택해 관심 주제·도움을 줄 사람·보유 사진이나 영상·제작 가능한 시간을 입력하고, 소개 문구와 첫 콘텐츠 계획을 받는다. SNS 연결 전에 샘플과 제작 가치를 볼 수 있게 하고, 연결은 실제 계정 분석을 원하는 시점에 안내한다.

5. 계정 분석을 실제 제작 요청으로 바꾼다

아래는 실제 사용자 계정을 분석한 결과가 아닌 제품 동작 설계 예시다. 독서 콘텐츠를 정기적으로 올리는 운영자가 있다고 가정한다.

  • 관측: 충분히 비교 가능한 게시물에서 실용적인 독서 방법을 설명한 콘텐츠의 저장 반응이 높게 나타났다. 비교한 게시물과 지표를 함께 보여준다. 데이터가 적으면 ‘초기 관찰’로 표시한다.
  • 추천: “다음에는 퇴근 후 독서 시간을 만드는 방법을 카드뉴스로 시험해 보자.” 과거의 잘된 소재를 그대로 복제하지 않고 다른 질문에 답하는 후속 주제를 제안한다.
  • 소재: 사용자가 남긴 메모·관련 참고 자료·사용 권한이 있는 사진을 묶고, 사실 확인이 필요한 항목을 표시한다.
  • 제작: 표지 문구, 카드별 내용, 캡션을 만들고 문구·사진을 수정할 수 있게 한다. 원본 영상이 있으면 사용할 만한 구간과 짧은 영상 대본도 제안한다.
  • 후속 확인: 게시 후 같은 관찰 기간의 유사 형식과 저장·공유·도달 등을 비교하고 다음 제안을 조정한다.

‘저장 반응이 높았으므로 이 주제 때문에 성공했다’고 인과적으로 단정하지 않는다. 형식·게시 후 경과시간·유료 노출·이벤트·외부 소개 등의 차이를 가능한 범위에서 구분한다. 없는 시청자 유지 곡선이나 매출 데이터를 만들어 후킹·전환 원인을 설명하지 않는다.

추천의 단위는 링크 목록이 아니라 제작 가능한 콘텐츠 한 건이다. 추천마다 내 목표와의 관계, 내 계정에서 관측한 근거, 외부 자료, 필요한 원본, 제작 방법을 연결한다. 외부 도구를 써야 할 때도 도구명만 추천하지 않고 전달할 대본·자막·편집 지시를 준비한다.

6. 소재와 영상 편집은 이렇게 연결한다

상황 추천·제작 동작 초기 구현 범위
좋은 주제를 모르겠음 계정 목표·기존 성과·최근 자료에서 주제 후보 제시 승인된 자료 수집·중복 제거·추천 이유·기획안
원본 글·자료가 있음 카드뉴스·캡션·짧은 영상 대본으로 재구성 기존 Dify·카드뉴스·렌더 자산 활용
본인 원본 영상이 있음 전사, 주제 구간 후보, 짧은 영상 구성, 자막 초안 처음에는 구간·자막·편집 지시. 정식 도구 연동 또는 제한된 렌더는 다음 구현 범위
원본 영상이 없음 촬영 구성·필요 장면·화면 글·나레이션 제안 촬영 계획과 제작 자료 제공; 없는 원본을 자른 척하지 않음
매주 반복 제작함 지난 채택·수정·성과를 다음 제안에 반영 사용자 선택과 추천 이유 기록, 간단한 주간 계획

자동 자막·세로 화면 변환·원본 잘라내기는 구현 또는 적법한 API 연동으로 제공할 수 있다. 자유로운 타임라인 편집과 모든 생성형 영상 기능을 동시에 직접 만드는 것은 별도 규모의 개발이다. 기능을 제품에 포함할 가치와 자체 개발 여부를 분리해 판단한다. 상용 API의 이용 조건·원가·파일 전달·실패 복구를 확인한 뒤 통합 범위를 정한다.

7. 대행사와 개인에게 같은 핵심 기능을 다른 화면으로 제공한다

공통 구조는 목표·계정·자료·콘텐츠·수정·게시물·성과다. 개인에게는 자기 계정과 이번 주 계획만 보인다. 대행사에는 고객사 선택·브랜드별 기준·담당자·검토 상태가 추가된다. 처음부터 별도 제품 두 개를 개발할 필요는 없다.

첫 대행사 고객군은 유지하되, 개인 운영자를 계속 미래 후보로만 미루지는 않는다. 제한된 비교 대상에 개인 운영자 1명을 포함하는 안을 제안한다. 기존 2고객 확장안의 대행사 두 곳을 ‘대행사 1곳 + 정기 운영 개인 1명’으로 바꾸면 고객 수를 늘리지 않고 비교할 수 있다. 최소 1고객안에서는 별도 개인 인터뷰·시연을 하고 유료 반복 검증까지 했다고 주장하지 않는다.

두 집단에서 추천 채택→실제 제작→게시→다음 주 재사용→결제·지원 시간을 같은 정의로 본다. 대행사는 최종 승인·납품 시간도 보고, 개인은 실제 제작을 지속하는 데 도움이 되었는지도 본다. 개인이 더 좋은 반복 사용과 경제성을 보이면 다음 모집 비중을 늘린다. 한 명의 반응만으로 전체 시장 우위를 선언하지 않는다.

8. BM과 초기 계획에 반영한다

개인에게는 계정 1개를 위한 기본 구독과 포함 제작량, 대행사에는 복수 브랜드·협업·보고 범위를 묶는 구조가 적합한 가설이다. 영상은 처리 분량·생성 원가가 달라 별도 포함량이나 추가 요금으로 설계한다. 단발 진단서만 팔기보다 매주 다음 콘텐츠를 결정하고 완성하는 데 계속 쓰는지를 본다.

이전 문서의 59,000원·149,000원과 기여이익은 카드뉴스 중심의 가정이다. 계정 동기화·지속 소재 수집·영상 처리 원가를 포함한 수익성이 검증됐다는 뜻이 아니다. 데이터 수집·추천·영상 원가와 API 연결 지원을 추가해 다시 계산한다. 개인의 지불 의사를 대행사 가격으로 대신 판단하지 않는다.

개발 계획은 다음처럼 보완한다. 1~2주에 목표·계정 연결 조건·API 앱 접근 준비와 고객 자료를 확인하고, 처음부터 데이터 출처와 최신 시점을 구분한다. 3~4주에는 확보한 데이터로 계정 요약과 다음 콘텐츠 3개를 만들고 기존 제작 흐름으로 연결한다. 5~8주는 실제 채택·게시·다음 주 사용을 관찰한다. 공식 API 승인이 지연되면 고객이 직접 제공한 자료로 추천을 검증할 수 있지만 이를 실시간 자동 분석이라고 표시하지 않는다.

추가 기능을 기존 72시간 안에 무조건 더하지 않는다. 자유 편집·새로운 협업 화면의 범위를 줄여 읽기 분석·추천을 앞당기고, 실제 데이터 연동량에 따라 일정·전문 개발 시간·운영비를 다시 산정한다. 자동 발행 권한 요청과 무거운 영상 렌더는 초기 읽기 분석과 분리한다.

현재 제품 방향은 계정 분석과 제작을 연결하는 운영 서비스다. 대행사는 첫 매출을 검증할 고객군이고, 개인 계정 운영자는 처음부터 제품 경험과 비교 검증에 포함하는 주요 후보 고객군이다. 어떤 고객에게 더 잘 맞는지는 실제 사용·지불·원가로 결정한다.

1. 판단을 바로잡는다

기존 기업이 같은 기능을 제공한다는 이유로 시장 진입을 포기하지 않는다. 선택한 고객이 품질·비용·편의·신뢰를 함께 고려했을 때 우리를 고르고, 그 선택을 반복하게 할 수 있는지가 기준이다. 완전히 새로운 기능이나 독점 기술은 진입의 필수조건이 아니다. 기능 중복은 비교해야 할 대상이 있다는 뜻이다.

이전 보고서가 ‘독점적 기능 차별화’를 미통과로 표시한 것은 잘못된 판정 기준이었다. 이를 ‘선택 고객의 실제 업무에서 종합 가치 우위’로 바꾸고, 현재 상태도 ‘비교 실험 미실시’로 수정했다. 경쟁사의 존재, 우리의 경쟁력 미확인, 현재 팀의 개발 용량 부족은 서로 다른 사실이다.

시장 진입과 전면 개발도 분리한다. 현재 학생 팀의 주 8~15시간이라는 조건은 첫 제품의 범위를 제한하지만, 시장의 매력이나 이후 투자 규모를 결정하지 않는다. 좁은 업무부터 시작하는 목적은 적은 비용으로 우위를 만들고 인접 업무로 넓히는 것이다. 작은 제작 대행업을 최종 목표로 정한다는 뜻이 아니다.

2. 권하는 경쟁 전략

대행사가 이미 받은 고객 자료·지난 승인본·수정 요청을 이용해, 다음 정기 콘텐츠를 바로 편집하고 검토할 수 있게 만드는 제작·수정 서비스로 진입한다. 첫 대상 작업은 정보형·상품 설명형 카드뉴스와 캡션이다. 소재 찾기만 필요한 고객에게 억지로 승인 기능을 팔지 않고, 촬영·인물성·독창적 캠페인 콘셉트가 핵심인 업무는 초기에 섞지 않는다.

첫 승리 가설은 **‘승인본이 있는 브랜드에서 수정 요청을 더 쉽게 반영하고, 다음 회차에 같은 지적을 받는 일을 줄인다’**로 둔다. 우선 지표는 최종 채택까지의 실제 수정·검수 시간이며, 사실 정확성·디자인 품질·편집 가능성을 하한으로 둔다. 이 선택은 기존 부분 수정·렌더 자산과 반복 제작 고객에 맞춘 가설이다. 실제 고객 관찰에서 더 큰 문제가 확인되면 실험 전에 이유를 기록하고 바꾼다.

고객이 돈을 내는 결과는 ‘AI가 여러 기능을 수행했다’가 아니라, ‘내가 다시 설명하고 고치는 일이 줄고 이번 납품이 끝났다’가 되어야 한다. 다만 제작 속도만이 유일한 구매 이유는 아니다. 같은 시간에 더 좋은 결과가 나오거나, 같은 결과를 더 낮은 총비용으로 얻거나, 새 담당자가 훨씬 쉽게 이어받을 수 있어도 유효한 경쟁 전략이다.

진입 방식 장점 약점 현재 권고

기존 도구와 함께 쓰는 제작·수정 제품 도입 부담이 작고 이미 쓰는 템플릿·계정을 살릴 수 있음 추가 구독료와 전달 과정이 생김; 불완전한 연동은 불편을 늘릴 수 있음 첫 진입 방식. 추가 도구를 쓰고도 일이 줄어야 통과

따라서 처음부터 도구 이전을 요구하지 않는다. 지난 승인본이 있는 브랜드를 새로 수임하거나, 기존 브랜드의 새 정기 작업을 시작하는 시점에 브랜드 하나와 납품 한 건으로 들어간다. 자료가 없는 신생 브랜드는 설정 원가와 구매 이유가 달라 별도 실험으로 구분한다. 기존 고객 전체를 옮기는 데 필요한 교육·권한·파일 이전을 피할 수 있는 진입 시점이라는 가설이다. 이후 고객이 자발적으로 더 많은 제작·수정 업무를 맡기는지를 본다.

4. 조금 더 나은 서비스도 이길 수 있다

반드시 열 배 좋아야 한다는 기준은 두지 않는다. 매일 반복하는 일이라면 작은 개선도 쌓인다. 반대로 드물게 쓰는 기능이 조금 좋아져도 큰 이전 작업을 요구하면 고객이 움직이지 않을 수 있다. 중요한 것은 개선의 크기 하나가 아니라 사용 빈도, 업무 중요도, 도입 부담, 실제 지불 의사의 조합이다.

비교할 때의 고객 총비용은 ‘도구 비용 + 실제 작업시간의 가치 + 외주·재작업 비용 + 도입 비용의 기간 배분’이다. 작업시간과 외주비에 같은 사람의 작업을 두 번 넣지 않는다. 대기 시간은 담당자가 계속 붙어 있어야 하는 시간이 아니면 노동시간과 분리한다. 오류 비용과 품질 가치는 측정 근거가 없으면 임의로 돈으로 환산하지 않는다.

다음은 구조를 설명하기 위한 가정 예시다. 실제 제품 가격·절감 실적·지불 의사가 아니다. 월 60건의 반복 제작에서 건당 10분을 줄이면 월 10시간이다. 그 시간을 시간당 3만원으로 평가하고 우리 추가 구독료를 월 10만원, 도입 비용의 월 배분액을 3만원으로 가정하면 월 순가치는 17만원이다.

항목 계산용 가정
절약 시간의 가치 10시간 × 3만원 = 30만원
우리 추가 구독료 10만원
초기 설정·학습의 월 배분 3만원
고객에게 남는 가치 30 − 10 − 3 = 17만원

기존 도구를 두 경우 모두 유지한다면 기존 도구의 구독료는 비교에서 상쇄된다. 그 도구가 가격을 절반으로 내려도 우리 추가 기능의 시간 절감 가치가 자동으로 사라지지는 않는다. 반면 경쟁사가 같은 절감 효과까지 무료로 제공하면 이 예시의 이점은 줄거나 없어질 수 있다. 가격 인하 대응과 기능 개선 대응은 따로 검토해야 한다.

절약한 시간이 매출이나 현금 절감으로 바로 바뀐다고 단정하지 않는다. 추가 납품, 야근 감소, 외주 축소 등 고객이 실제로 중요하게 여기는 결과로 이어지는지와 결제 행동으로 확인한다. 월 10만원도 확정 판매가가 아니며, 다른 문서의 5만원 시험 납품·39만원 구독 산술 예시와 서로 다른 가정이다.

5. 저가 전략도 가능하지만 원가부터 설계한다

같은 품질을 더 싸게 제공할 수 있다면 정당한 경쟁력이다. 다만 우리가 돈을 덜 받는 것과 생산 원가가 낮은 것은 다르다. 기존 트렌드·제작·렌더 자산은 시작 비용을 줄일 수 있지만 장기 운영 원가 우위까지 입증하지는 않는다.

확인할 원가 개선 수단은 승인된 구조·템플릿 재사용, 필요한 카드나 문장만 수정, 오류 자동 검사, 반복 입력의 재사용, 작업 난도에 맞는 모델 선택이다. 각 방법은 품질을 유지한다는 조건으로 채택한다. 값싼 모델 때문에 사람의 검수가 늘어나면 총원가가 오를 수 있다.

판매 단위는 브랜드 수와 포함 작업량·지원 범위를 고객이 이해할 수 있게 정한다. 고가 영상·과도한 재생성·대신 제작은 실제 원가에 맞춰 구분한다. 고객에게 토큰 계산이나 복잡한 자동화 노드 설계를 맡기는 것은 첫 경험의 부담을 늘릴 수 있다.

우리의 계산에는 실행·렌더·저장·결제비, 오류 복구, 사람의 보정·지원·온보딩, 고객 획득 노동이 들어간다. 창업자와 학생의 무료 노동도 반복 사업의 원가 추정에서는 뺄 수 없다. 경쟁사 가격이 낮아져도 우리의 요금을 유지할 이유가 있거나, 우리도 낮추고 이익을 남길 원가 구조가 있어야 한다.

6. 경쟁사의 대응을 전제로 한다

장기적으로 쌓을 것은 실제로 도움이 되는 브랜드별 수정 이력, 좋은 납품을 만드는 운영 기준, 안정적인 실행과 신뢰, 반복적으로 고객을 확보하는 경로다. 각각이 유지율·원가·획득비를 개선해야 사업 자산이다. 데이터량이나 오래된 계정 자체는 방어력을 증명하지 않는다. 고객이 다른 도구로 옮길 수 있게 하면서도 계속 선택받는 것을 목표로 한다.

7. 경쟁 우위를 만드는 제품 경험

첫 진입은 ‘고객사 자료와 지난 승인본을 넣어 보세요’로 시작한다. 가능하면 공개 샘플로 먼저 경험하게 하고, 실제 자료는 사용 권한이 있는 것을 받는다. 첫 결과 전에 모든 SNS 계정·팀·카드·API 키를 등록하게 하지 않는다.

결과는 보기 좋은 정지 이미지에 그치면 부족하다. 실제 작업에서 요구되는 문구·사진·배치 수정이 가능하고, 한 부분을 바꿔도 승인된 다른 부분이 유지되어야 한다. 수정이 이번 작업의 예외인지 다음 작업에도 적용할 기준인지 사용자가 확인할 수 있게 한다. 자동으로 외부에 발행하기 전에는 대상 계정과 승인 버전을 확인한다.

기존 편집기로 이어갈 때는 고객이 정말 쓸 수 있는 전달 형식을 확인한다. PNG 내보내기를 ‘Canva에서 모든 요소를 편집할 수 있다’고 표현하지 않는다. 편집 가능한 파일이나 API 연동은 실제 지원 범위·이용 조건·왕복 수정의 손실까지 확인해야 제품 약속으로 쓸 수 있다.

성과 추적은 다음 제작에 영향을 주는 설명과 연결한다. 도달·저장 같은 지표를 관측해 추천을 바꾸는 것과 콘텐츠가 매출을 올렸다고 인과적으로 입증하는 것은 다르다. 첫 제품에서는 실제 채택·작업시간·수정·원가부터 보고, 계정 연결 뒤 확보되는 지표를 추가한다.

8. 비교와 고객 확보를 실행하는 방식

최소 자원안에서는 실제 고객 1곳의 작업 2회와 가장 관련 있는 경쟁 대안 하나를 비교한다. 확장안에서는 대행사 2곳과 두 작업 주기를 보고 비교 대안을 늘린다. 이 표본으로 시장 전체의 우위나 장기 유지를 선언하지 않는다.

  1. 최근 실제 작업, 기존 도구·요금, 작업 빈도, 승인 기준, 담당자의 숙련도를 기록한다. 본 시험 전에 고객의 최종 편집 환경에서 결과물 한 건을 이어서 완성할 수 있는지 확인한다. 변환·재배치가 과도하면 전달 방식이나 첫 대상 작업을 조정한다.
  2. 동일한 자료·요청·납품 기준으로 비교한다. 기존 도구는 고객의 숙련된 설정을 쓰고 우리도 설정·학습 시간을 기록한다.
  3. 작업 순서로 인한 학습 효과를 기록하고 가능한 경우 순서를 바꾼다. 결과물 평가는 가능한 범위에서 도구 이름을 가린다.
  4. 처음 성공한 출력만 고르지 않는다. 실패·재생성·부분 수정·사람 보정·최종 전달까지 센다. 같은 납품의 카드 여러 장을 독립 고객처럼 세지 않는다.
  5. 시간·비용·품질·도입 편의 중 이번에 이기려는 주된 기준을 결과를 보기 전에 고른다. 나머지 기준에는 고객이 수용할 하한을 둔다.
  6. 다음 작업에서 직접 다시 사용하는지와 도구 자체에 결제하는지를 본다. 할인·친분·우리가 대신한 일을 구분한다.

‘시간 30% 절감’은 한 실험의 목표일 수 있지만 모든 제품의 필수 통과선은 아니다. 같은 품질의 총비용 감소, 같은 비용의 품질 향상, 훨씬 쉬운 도입으로 유료 반복이 생기는 경로도 인정한다. 어느 경로든 결과를 보고 유리한 지표만 선택하거나 나쁜 품질을 평균 시간으로 가리지 않는다.

고객 확보는 대행사 대표·실무자가 실제 다가오는 납품을 보여 주고 결정할 수 있는 곳부터 시작한다. 프리랜서 디자이너는 디자인 평가와 제작 기준 수립에 참여할 수 있지만, 실제 돈을 내고 반복 운영하는 고객을 대체하지 않는다. 사용자·학생의 지인 관계는 모집 경로로 쓸 수 있어도 상업 수요의 증거로 자동 환산하지 않는다. 이후 지인 밖 고객에게 같은 제안이 통하는지 확인한다. 연락·광고·외부 게시를 이번 조사에서 실행한 것은 아니다.

Rita에는 이 과정에서 실제 사용된 소재 조사·기획·제작·검수·발행·분석 모듈을 연결한다. 같은 코드와 평가 기록을 재사용하면 개발 효율이 높아질 가능성이 있다. 다만 Rita라는 목적이 독립 서비스의 나쁜 경제성을 가려서는 안 되고, 자사 서비스가 잘 팔렸다는 이유로 제3자 에이전트 거래까지 검증됐다고 말하지 않는다.

현재의 권고는 이 시장의 진입을 검증하는 데 투자하되, 첫 경쟁 목표를 ‘대행사의 정기 콘텐츠를 더 적은 수고와 합리적인 총비용으로 완성’에 두는 것이다. 기존 기업이 못 한다고 가정하지 않고, 같은 고객의 같은 작업에서 비교한다. 처음부터 모든 기능에서 이기려 하지 않아도 된다. 이긴 부분을 반복 가능한 상품으로 만들고 그 고객의 다음 업무로 넓혀 간다.

대행사 제작 담당자 카드뉴스·캡션 제작과 고객 수정 대응 경험 기존 방식의 시간·수정 이유를 기록하고 새 방식과 비교 고객사당 담당자 1명, 기존 업무 안에서 관찰
디자인 프리랜서 상업용 SNS 카드뉴스 납품 경험, 편집 가능한 템플릿 제작 능력 실제로 써도 되는 품질 기준 설정, 템플릿 2개 점검, 글자 넘침·가독성·브랜드 적합성 검수 초기 2~3시간 + 중간·최종 각 1시간; 견적 별도
경영 학생 경청·기록·스프레드시트, 반증 질문을 할 수 있음 고객 후보 모집, 인터뷰 기록, 작업 시간·채택·결제 원장 관리 주 4~5시간
프로그래밍 학생 Python 또는 JavaScript, HTTP·JSON, Git, 오류 로그 이해 기존 Dify·렌더 연결, 원본 보존, 실패 재현·수정, 사용·비용 기록 주 4~5시간
세 번째 학생이 있다면 콘텐츠 검수 담당 한국어 문장·출처 확인·시각 검수 근거 대조, 브랜드 규칙 입력, 결과물 점검, 재현 테스트 주 4~5시간
사용자 본인 고객 관계, 범위·가격·중단 판단 권한 첫 고객 인터뷰 일부 동석, 유료 제안 검토, 매주 진행·중단 판단 주 1시간 + 초기 인터뷰 동석 시간을 별도 확보하는 안

대행사를 채용하거나 회사 지분을 줄 필요는 없다. 시험 고객으로 참여하면 된다. 디자인 프리랜서가 여러 브랜드의 정기 납품·수정·결제까지 담당한다면 시험 고객 자격도 있다. 디자인만 수행한다면 품질 평가자이며 구매 검증을 대신하지 않는다. 고객사의 승인 담당자도 최소 한 차례 검토 과정에 참여해야 승인 화면의 가치가 확인된다.

학생 두 명이면 크리에이터 비교 인터뷰와 새 검토 화면 개발을 미루고, 기존 도구로 대행사 한 곳의 작업부터 수행한다. 첫 주 실제 소요 시간을 확인한 뒤 두 번째 고객을 추가한다. 세 번째 역할을 같은 시간 안에 그대로 나눠 맡는 계획은 세우지 않는다. 학생은 고객사 계정의 상시 운영이나 야간 발행 장애 대응을 맡지 않는다. 자동 발행을 제공하는 단계에서는 책임 있는 운영 담당자를 따로 정해야 한다.

2. 돈은 무엇에 필요한가

총예산은 아직 미확정이다. 추가 기술·모집 실비에 최대 30만원을 배정하고, 학생 보수·디자인 견적·사용자 시간을 별도로 계산하는 안을 제안한다. 충분하다는 가격 보장이 아니라, 기존 자산·소량 생성·직접 모집을 이용해 이 범위 안에서 실험을 제한한다는 뜻이다. 초과하면 범위나 예산을 다시 판단한다.

항목 제안 상한 사용 조건
AI 호출·이미지 생성·렌더 실행 10만원 실행별 비용 기록, 반복 생성 상한, 고가 영상 생성 제외
추가 호스팅·파일 저장 5만원 기존 서비스 재사용 우선, 새 유료 서비스는 필요할 때만
고객 모집·인터뷰 실비 5만원 직접 모집과 온라인 인터뷰 우선, 대규모 광고 제외
예비비 10만원 외부 도구 시험·예상 밖 소액 비용에 배정
합계 30만원 인건비·전문 디자인 외주·기존 구독비 제외

학생 보수를 지급한다면 총 학생 시간 64~120시간 × 합의한 시간당 보수를 추가한다. 디자인 외주는 위 작업 범위를 적어 견적을 받은 뒤 추가한다. 몇십만 원 예산에 학생 인건비와 전문 디자인 작업까지 모두 포함된다고 말할 수 없다. 사용자 시간과 무료 협업도 경제성 계산에서는 0원으로 처리하지 않는다.

고객별 기존 관계, 소개 경로, 접촉·상담·자료 제공·결제 수와 모집 노동을 기록한다. 돈을 받고 품질 평가를 하는 디자이너가 시험 고객도 되는 경우 보상과 구매 재원을 분리하며 독립 고객으로 자동 계산하지 않는다. 실비 보상·참여 보상과 구매를 구분한다. 우리가 보상한 돈을 고객이 다시 결제한 경우에는 독립적인 지불 의사 증거로 세지 않는다. 친분에 의한 결제와 자발적 반복 구매도 분리한다.

3. 가용 시간에 따라 8주 범위를 다르게 잡는다

이 일정은 제품을 완성하는 일정이 아니다. 학생 총 64~120시간 안에서 현재 상품 가설에 더 투자할지 결정하는 일정이다. 아래 표는 주 12~15시간이 확보되는 확장안이다. 주 8~10시간이면 인터뷰 3~4곳, 대행사 1곳의 납품 두 번, 기존 도구의 검토·전달 기능으로 제한한다. 최소안에서는 크리에이터 비교와 새로운 사용 화면을 만들지 않으며, 도구 유료 사용 시험을 못 하면 SaaS 수요는 미검증으로 종료한다. 디자이너를 확보하지 못하면 품질 판단을 학생 평가로 대체하지 않고 일정·산출 범위를 조정한다.

기간 고객에게서 얻을 것 팀이 만드는 것 다음 단계로 갈 기준
1~2주 대행사 6곳의 최근 작업 사례; 비교 관찰용 상업 크리에이터 2명 현재 작업 단계·도구·시간·실패·결재자 기록 실제 자료 제공 3곳, 같은 병목 2곳 이상, 시험 납품에 참여할 대행사 2곳
3~4주 대행사 2곳, 각 브랜드 1개의 실제 요청 카드뉴스 1개 + 캡션 + 검토 링크, 수정 1회 고객이 실제로 사용·납품하는지 확인; 유료 시험 제안에 대한 행동 기록
5~6주 같은 브랜드의 다음 작업 첫 수정 이유를 반영한 두 번째 결과물 사람 보정까지 합친 시간이 줄고 품질이 유지되는지 확인
7~8주 자발적인 다음 주문·재결제 반복 작업 기록과 손익표 아래 수치와 실패 조건으로 확대·수정·중단 판정

최소 자원안에서 두 번째 고객 추가나 크리에이터 비교는 필수가 아니다. 사용자 본인의 소개와 동석은 모집에 도움이 되지만 실제 영업망이 확보됐다고 가정하지 않는다. 모집에 시간이 더 걸리면 고객 수를 숨겨 채우지 않고 그 자체를 기록한다. 2주에 모집이 안 되면 대상·제안문을 한 번 바꾸고 1주 추가한다. 그래도 최소안의 1곳 또는 확장안의 2곳이 실제 자료를 제공하지 않으면 개발을 확대하지 않는다. 이는 수요 부재의 확정이 아니라 현재 접근 방식의 미통과다.

4. 첫 고객에게 제안할 상품

상품 이름은 ‘다음 납품용 카드뉴스 제작 시험’ 정도로 명확하게 둔다. 최종 브랜드 이름을 지금 정할 필요는 없다.

  • 입력: 고객이 사용 권한을 가진 소개 자료, 이전 게시물 3개, 이번 콘텐츠 요청.
  • 산출: 기획안, 편집 가능한 카드뉴스 초안 1개, 캡션 1개, 출처와 확인 필요 항목, 고객 검토 링크.
  • 범위: 브랜드 1개, 템플릿 1종, 수정 1회. 첫 제출 기한은 자료를 확인하고 가능한 범위로 약속한다.
  • 대신 제작 시험 가격은 별도 범위·소요시간을 확인한 뒤 견적한다. 이전 1회 5만원은 초기 탐색안으로, 현재의 주력 상품 가격이 아니다.
  • 첫 제안에서 약속하지 않을 결과: 팔로워 증가, 바이럴, 매출 증가, 완전 무인 운영.

초기에는 사람이 자료 확인과 디자인 보정을 돕는다는 사실을 고객에게 알린다. 고객이 산출물에 비용을 지불했다는 사실은 서비스 수요의 증거다. 이것만으로 고객이 직접 쓰는 SaaS 수요를 증명할 수 없다.

따라서 후반 시험에는 제작 담당자가 이전 브랜드 설정을 불러와 우리 팀의 대신 조작 없이 다음 초안 생성·부분 수정·검토 요청까지 수행하게 한다. 고객이 이 과정을 직접 사용하지 않고 완성품 외주만 원하면, 결과를 SaaS 검증 성공으로 기록하지 않는다.

직접 조작했다는 사실도 도구 구매를 뜻하지 않는다. 현재의 도구 시험 제안은 **브랜드 1개, 30일, 카드뉴스·캡션 최대 10세트, 직접 폼 편집·결과 내보내기, 대신 제작 없음, 59,000원(부가세 제외)**이다. AI 부분 수정은 실제 제공 여부를 명시한다. 이는 확정 판매가가 아닌 시험 제안이며 결과물 대행 가격과 합산하지 않는다. 상세 한도·원가는 최신 BM 문서를 따른다. 고객이 도구 자체에 결제하고 다음 제작 주기에 다시 쓰는지 확인하지 못하면 ‘제작 서비스 수요 확인, SaaS 수요 미검증’으로 기록한다.

5. 무엇을 측정할 것인가

같은 브랜드·같은 형식의 과거 또는 현재 작업과 비교한다. 난도가 다른 작업이면 차이를 기록한다. 고객의 추정 시간과 실제 측정 시간을 구분하며, 원본 디자인을 재사용해 쉬워진 효과와 우리 도구의 효과를 혼동하지 않는다.

측정 항목 정의
실제 채택 고객이 승인하고 실제 납품 또는 게시한 콘텐츠
작업시간 고객의 자료 준비·설정·편집·전달 시간과 우리 팀의 제작·보정·지원 시간을 별도 측정하고 합계도 제시. 고객 시간을 우리 팀으로 옮긴 것을 자동화로 세지 않음
초기 도입 비용 최초 자료 정리·설정·교육에 쓴 양쪽 시간과 비용. 이후 주문으로 몇 회 만에 회수되는지 별도 계산
대기 시간 고객의 승인 대기 등 작업자가 손을 쓰지 않은 시간; 작업시간과 별도
반복 오류 같은 브랜드의 이미 수정한 문제를 다음 초안에서 다시 만드는 횟수
고객 직접 사용 팀이 대신 누르지 않고 핵심 작업을 끝냈는지
유지 해당 고객의 다음 자연스러운 제작 주기에 실제로 다시 사용하는지
수요 다음 주문, 계약·입금, 취소·환불, 독립적인 재결제
경제성 매출에서 실행비·결제비·수정 노동·운영 지원비를 뺀 금액

제안하는 확장안의 다음 검증 투자 기준은 대행사 2곳 모두 실제 사용과 독립 재결제, 미리 정한 경쟁 우위의 확인, 초기 설정 비용 별도 회수 가능, 노동을 포함한 기여이익 양수다. 시간·총비용·품질·도입 편의 중 이번 실험의 주된 승리 기준을 결과를 보기 전에 고르고 나머지에는 고객이 수용할 하한을 둔다. 시간 절감 실험이라면 총작업시간 중앙값 30% 감소를 목표로 둘 수 있지만, 같은 품질을 더 싸게 제공하거나 같은 시간에 더 좋은 결과를 제공하는 경로도 인정한다. 별도 운영 지원 고객당 주 30분은 시험 목표이며 실제 제작 노동은 별도로 모두 원가에 포함한다. 30%와 30분은 보편적 성공 법칙이 아니다. 불만·중단·미채택 건도 분모에 넣는다.

비교 대안은 고객이 실제 쓰는 숙련된 방식으로 잡는다. 최소안은 관련 대안 하나와 작업 두 번을 비교하고, 확장안에서 범위를 늘린다. 기존 구독을 유지할 경우 추가 도구의 비용과 전달 시간을 모두 넣는다. 경쟁사 가격 인하와 기능 개선이 있어도 고객의 순이득이 남을지는 경쟁 전략 문서의 기준으로 별도 점검한다.

최소안의 고객 1곳 결과는 사례 연구로만 사용한다. 확장안 기준을 통과하면 고객 5~10곳으로 넓혀 독립 모집, 다른 담당자의 전달, 같은 가격·지원 범위, 도구 자체의 결제·재사용을 검증한다. 2곳의 성공으로 PMF나 대규모 투자 타당성을 선언하지 않는다. 둘 중 한 곳만 통과하면 잘된 고객의 공통 조건으로 한 번 더 좁혀 검증한다. 두 곳 모두 재사용하지 않으면 기능을 더 만들기 전에 상품 가설을 중단한다.

6. 고객에게 물을 질문

  1. 가장 최근 납품한 게시물 하나를 자료 수집부터 전달까지 보여줄 수 있는가?

해외 콘텐츠·SNS SaaS의 사업 증거와 적용 판단

조사 기준일: 2026-09-29. 대상은 Buffer, Metricool, Sprout Social, Canva, Later, OpusClip, Jasper 7개다. 사업 증거와 제품 설계 추론을 분리했다. 공식 자료를 읽었으며 제품별 유료 가입·전환율·리텐션 실험을 직접 수행하지 않았다. 비공개 기업의 보도자료는 당사자 주장이다. 매출, ARR, 거래액, 이용자, 투자금, 인수가격을 같은 성공 지표로 합산하지 않았다.

결론

해외 사례는 SNS 콘텐츠 제작·운영에 반복적으로 돈을 지불하는 시장이 있음을 보여준다. 같은 기능도 더 나은 품질·가격·편의로 제공하면 진입할 수 있다. 기존 기업들이 생성·승인·발행·분석·API/MCP를 제공한다는 사실은 비교 기준이며 진입 배제 사유가 아니다. 우리 제품의 종합 가치 우위는 실제 고객 작업에서 확인해야 한다. 2026-09-29 경쟁 전략 수정 내용은 경쟁에서 이기는 진입 전략에 반영했다.

한국 소규모 대행사를 첫 고객으로 검증할 이유는 존재한다. 고객사마다 되풀이하는 납품 업무를 한 번에 개선하면 반복 사용과 가치 측정이 가능하기 때문이다. 하지만 승인·일정 관리만 필요한 고객이라면 저렴한 기존 SaaS를 이기기 어렵다. 외부 도구를 써도 남아 있는 ‘고객 자료를 이해해서 초안을 만들고, 고객의 수정 의견을 반영해 다음 납품까지 마치는 일’에서 실제 우위가 나야 한다. 이것은 아래 해외 기업에서 인과적으로 입증된 법칙이 아니라, 경쟁 상황과 기존 자산을 종합한 진입 가설이다.

추천은 대규모 범용 제품 개발이 아니라, 한 고객 유형과 한 납품 형식에 대한 유료 검증이다. 크리에이터로의 확장은 열어 두되, 취미 계정 전체가 아니라 정기 콘텐츠 생산과 수익원이 있는 운영자를 대조군으로 모집해야 한다. 계정 진단은 좋은 유입 도구가 될 수 있지만, 진단을 받은 뒤 다음 주에 유료로 재사용할 이유가 없으면 독립 사업의 중심이 되기 어렵다.

중단 조건과 크리에이터 확장 판단

중단할 상황: 팀이 기획·제작보다 촬영·독창적 비주얼을 원하고 우리 결과를 다시 만드는 경우; 승인 자체보다 고객 의사결정 지연이 지배적인 경우; 기존 Canva/미리캔버스/Planable 조합 대비 측정 가능한 절감이 없는 경우; 창업자·학생의 수작업이 늘어야만 유지되는 경우; 자료 제공과 실제 사용을 요청하면 관심 고객이 사라지는 경우; 무료는 쓰지만 결제·반복 사용이 없는 경우. 신규 기능 추가가 이런 문제를 자동 해결한다고 가정하지 않는다.

크리에이터는 일괄적인 대체 시장이 아니다. 취미형보다 정기 콘텐츠로 상품·교육·협찬 매출을 만드는 1–3인 운영자를 별도 후보군으로 둔다. 그들에게 대행사의 ‘고객 승인’ 화면을 억지로 요구하지 않고 자기 검토와 발행으로 단순화한다. 원래 영상이 핵심이면 현재 카드뉴스 중심 자산과 맞지 않을 수 있다.

전환은 유입 수나 ‘좋아요’ 반응으로 결정하지 않는다. 같은 기간·같은 지원 수준에서 (a) 실제 게시에 채택된 결과 비율, (b) 2번째·3번째 제작 사용, (c) 다음 결제, (d) 계정당 운영 지원 시간, (e) 결제액에서 API·외주·운영 지원 원가를 뺀 기여가 대행사보다 좋아야 한다. 서로 다른 객단가의 전환율만 비교하지 않는다. 최소한 여러 팀/운영자에게 반복 관측하고, 숫자가 작으면 일반화하지 않는다. 전환하더라도 같은 소재·브랜드 규칙·렌더·작업 기록 기능을 재사용하고 독립 제품 두 개를 동시에 만들지 않는다.

문서 간 충돌: 새 헌법에서 정리해야 할 부분

  1. API 비용과 최초 체험. 9/11 전략문서는 오너가 키를 Rita 금고에 넣고 비용을 부담한다고 적었다. 같은 날 개발자 미팅은 학생 공급자 키를 설명한다. 9/15 학생팀 미팅은 마켓 이용자가 자기 API 키를 발급·입력하도록 지시한다. 동일한 운영정책으로 합쳐 쓸 수 없다. 상업 대행사 제품에서는 최초 샘플을 보기 위해 키 발급부터 요구하면 낮은 진입장벽 목표와 충돌한다. 제안은 제한된 무료 샘플 비용을 서비스 원가로 편성하고, 유료 플랜에 사용량을 포함하는 것이다. 고사용량 고객용 BYOK는 이후 선택지로 검토한다. 수업 비용정책을 유료제품의 온보딩에 그대로 옮기지 않는다.

  2. 실행·성과 추적. 9/11 전략문서는 프록시·성과 배지·회신을 강조하지만 실제 개발자 미팅은 SNS 지표 회수를 보류하고 경연·심사를 다음 일로 잡았다. 설계 의지와 구현 완료를 구분해야 한다. 새 서비스는 자체 run_id를 먼저 남기고 Rita 연동은 어댑터로 붙일 수 있다.

  3. 모델 로그와 고객 성과. 기존 전략문서의 '프록시 원장이 재구매율·실제 조회수를 공짜로 준다'는 표현은 수정해야 한다. 모델 호출 로그는 호출량·원가·처리 상태를 알려 준다. 조회수는 게시 ID와 SNS 지표 조회, 재구매는 결제·계약 갱신 기록이 있어야 안다. 서명된 회신 역시 공급자 신원을 확인할 뿐 산출물의 품질이나 사업 성과를 자동 입증하지 않는다.

  4. 데이터 소유. 기존 문서의 '성과 기록은 Rita 소유'는 설계 희망을 법적·계약적 확정으로 취급하면 안 된다. 고객 원자료·브랜드 규칙·수정 피드백·계정 지표는 사용 목적과 접근 권한을 구분해야 한다. 실행 메타데이터 보관, 익명 집계 활용, 공개 포트폴리오, 다른 고객 추천에 활용하는 행위는 별도 정책으로 정의해야 한다.

  5. 수업과 시장. 학생의 수강 과제 제출·강제 사용·코드 공개는 외부 고객의 지불 의사나 자발적 잔존을 입증하지 않는다. 수업은 품질 문제 발견과 사용성 시험에 유용하다. 상업 검증 수치에는 수업 표본을 섞지 않는다.

실제로 재사용할 수 있는 구현 자산

트렌드 레이더

로컬 구현은 FastAPI + SQLite이며 탐색·채널 대비 이상치·감시/추세·해외 소재·한외 비교가 존재한다. backend/app/db.py에는 영상/채널/기준값/지표 스냅샷/감시 목록/아이디어/일별 쿼터 테이블이 있다. watch.py는 채널 검증, 일별 스냅샷, 미완료·실패 표시 등 운영상 발견한 문제를 처리한다. 이는 재사용할 가치가 있는 경험이다.

그러나 현행 인증은 API 키 허용목록이고, watched_channels는 채널 ID가 전역 기본키, ideas에는 테넌트 식별자가 없다. 감시 목록과 아이디어가 고객별로 분리되는 SaaS 구조로 확인되지 않는다. list_watched()는 전체 목록을 읽고 remove_watch()는 채널 ID 하나로 삭제한다. 원래 학생·도구 공유 환경의 구조를 여러 고객사 운영 서비스로 그대로 노출하면 안 된다.

공개 영상·공개 트렌드 수집 캐시는 공용으로 둘 수 있다. 하지만 '누가 무엇을 저장·감시·기획했는가', 비공개 브랜드 정보, 고객 계정 지표는 고객 범위를 붙인 새 저장소가 필요하다. 점수 공식과 영상 분류는 이전 조사에서 문서/코드 차이까지 확인했으므로 공식 설명을 다시 고정해야 한다.

카드뉴스 렌더

src/server.py는 덱 JSON→PNG, 상태 확인, 디자인 측정·저장 등을 처리한다. 손질판·부분 수정·평가·디자인 자료가 함께 존재한다. Dify가 구조화된 콘텐츠를 만들고 렌더러가 이미지를 굽는 경계는 유지할 가치가 있다. 생성 모델을 바꾸더라도 편집·렌더를 재사용할 수 있기 때문이다.

다만 README는 겉모습 추출 제외라고 쓰지만 코드에는 /measure·/styles 분기가 있다. 9/29 인계는 옛 렌더 주소가 남아 있는 배포본과 미통합 상태를 기록한다. 전체 유형의 최신 품질, 고객별 접근통제, 상용 운영 용량이 확인된 것은 아니다. 새 서비스에서 이 서버를 내부 렌더 워커로 재사용하고 사용자 자산 접근은 서비스가 통제하는 방식을 제안한다.

Dify 및 샘플 디자인

소재발굴과 카드뉴스의 입출력·유형별 규칙·평가 사례는 자산이다. 워크플로 전체를 사용자 UI로 노출할 필요는 없다. 구조화된 입력을 받아 주제·근거·카드 문구·레이아웃을 반환하는 함수 경계로 감싸면 독립 서비스와 Rita가 모두 호출할 수 있다. 기존 브랜드를 따라 만든 디자인은 품질 학습자료와 상업 배포용 템플릿을 구분해 검토한다.

연결 흐름 제안

  1. 독립 서비스 방문자는 Rita 계정 없이도 제한된 샘플을 확인한다. 실제 저장·협업 시 서비스 계정을 만든다.
  2. Rita에서 실행하면 짧은 수명의 교환 코드를 서버에서 검증해 로컬 조직·사용자·권한과 연결한다. 조직이 같다는 추정만으로 계정을 자동 합치지 않는다.
  3. run_id를 발급하고 작업 입력/권한/모듈 버전을 기록한다. 생성은 작업 큐에서 처리하며 실패·취소·비용상한을 표시한다.
  4. 결과물과 수정 버전이 저장되고, 고객 승인은 승인자가 본 정확한 버전에 붙는다.
  5. SNS 발행은 별도 권한과 승인 상태를 확인한 전용 서비스만 실행한다. 콘텐츠 생성 모듈이나 외부 공급자 앱에 계정 토큰을 넘기지 않는다.
  6. 게시 ID를 결과물 버전과 연결한 뒤 시점별 지표를 수집한다. 실제 API 관측, 고객 입력, 공급자 보고를 다른 증거 수준으로 표시한다.
  7. Rita에는 허용된 실행/결과 요약 이벤트만 회신한다. 고객 자료·SNS 토큰·전체 작업 대화가 기본적으로 Rita 마켓에 공개되지 않는다.

범위 팽창을 막을 판단

  • 첫 대행사 서비스의 고객 문제를 해결하는 기능과 Rita의 먼 미래에만 필요한 기능을 구분한다. 이번 제품 고객에게 직접 효용이 없으면 공통 데이터 규격만 남기고 기능 구현은 미룬다.
  • 크리에이터 고객이 유료 반복 사용에서 더 좋게 나오면 같은 엔진에 1인 작업실·자기 승인·계정 운영 화면을 붙일 수 있다. 다중 브랜드/협업은 기본 기능의 강제가 아니라 필요할 때 켜는 구조로 한다.
