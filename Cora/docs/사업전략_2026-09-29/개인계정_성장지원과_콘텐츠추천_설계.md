# 개인 계정 운영과 대행사 업무를 함께 지원하는 제품 설계

2026-09-29 보완. 개인 계정을 시작하고 키우려는 사용자를 주요 고객 후보에 포함하고, 계정 분석과 다음 콘텐츠 제작의 연결을 제품의 중심으로 둔다. 사용자가 확정한 첫 대행사 고객군을 취소하는 문서는 아니다. 실제 계정 연결·진단·발행을 실행한 결과가 아니라 제품 설계 제안이다.

## 1. 제품을 콘텐츠 납품 도구로만 좁히지 않는다

제품의 공통 가치는 **‘내 계정의 목표와 성과를 이해하고, 다음에 만들 콘텐츠를 고르고 완성하도록 돕는다’**로 확장한다. 대행사에게는 여러 고객사 계정을 관리하는 형태로, 개인에게는 자신의 계정 하나를 키우는 형태로 제공한다. 소재 발굴·제작·편집·발행·성과를 하나의 작업 흐름으로 연결하는 방향이다.

계정 진단은 중요한 첫 경험이 될 수 있다. 운영 중인 계정은 자신의 자료를 사용하기 때문에 추천의 이유를 납득하기 쉽고, 다음 게시물을 올린 뒤 다시 확인할 이유도 생긴다. 다만 반복 방문이나 성장이 실제로 늘어나는지는 확인해야 한다. 보기 좋은 진단서만으로 구독 유지가 보장되지는 않는다.

기존 계획에서 계정 분석을 무조건 후순위로 둔 점을 수정한다. **읽기 중심의 계정 분석과 다음 행동 추천은 초기 제품 가설에 포함한다.** 자동 발행과 영상 전체 편집기는 각각 별도 구현 범위로 관리한다. 사용자가 보는 한 흐름을 만들기 위해 모든 도구를 처음부터 직접 개발할 필요는 없다.

## 2. 개인 계정 운영자는 세 집단으로 나눈다

| 고객 | 지금 해결해야 할 일 | 첫 경험 | BM에서 확인할 점 |
|---|---|---|---|
| 계정을 처음 시작하는 사람 | 주제·대상·표현 방식·첫 게시물 결정 | 관심사·목표·보유 자료·가능한 시간을 받고 첫 콘텐츠 묶음 제안 | 데이터 없이도 첫 결과가 유용한지, 시작 후 계속 제작하는지 |
| 정기적으로 올리며 성장하고 싶은 사람 | 무엇이 효과가 있었고 다음에 무엇을 만들지 결정 | 본인 계정 분석과 이번 주 콘텐츠 3개 추천 | 추천을 실제 제작·게시하고 다음 주 다시 쓰며 결제하는지 |
| 이미 협찬·상품·서비스 등 상업 활동을 하는 사람 | 제작 효율과 자신의 사업 목표를 함께 개선 | 원본 영상 재사용, 시리즈 기획, 성과에 따른 다음 콘텐츠 | 시간 절감과 매출 관련 목표를 구분해 지불 이유 확인 |

개인 사용자 가운데 우선 비교할 집단은 **이미 정기적으로 게시하며 계정을 키우려는 사람**이다. 기존 콘텐츠와 다음 제작 일정이 있어 추천의 채택과 반복 사용을 관찰할 수 있기 때문이다. 완전 초보도 배제하지 않으며, 그들에게는 없는 데이터를 분석하는 대신 시작을 돕는 경로를 제공한다.

‘개인 운영자’와 Instagram의 계정 유형인 ‘개인 계정’은 구분한다. 혼자 운영하는 사람도 Creator 계정을 사용할 수 있다. 공식 분석 API 연동은 계정 유형·권한·앱 승인 조건에 맞춰 제공해야 하며, 일반 개인 계정의 비공개 통계를 임의로 가져오는 방식으로 설계하지 않는다.

Meta 공식 문서상 Instagram Login은 Business/Creator 계정을 대상으로 하며 Facebook 페이지 연결은 필요 없다. 계정 분석용 읽기 권한과 게시 권한은 분리해 요청할 수 있다. 외부 고객용 서비스는 해당 권한의 Advanced Access·앱 심사·사업 확인 준비가 필요하며, 우리 계정에서 시험하는 것과 일반 고객 연동은 구분한다. 일반 개인 계정은 Creator 등으로 전환할지 사용자가 선택하도록 하고 공개 설정 등 전환 영향을 안내한다. [Instagram Login](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-instagram-login), [Meta Overview](https://developers.facebook.com/documentation/instagram-platform/overview)

도달·조회·저장·공유, 릴스의 일부 시청 관련 지표 등을 실제 반환 범위에서 활용할 수 있다. 팔로워 100명 미만은 전체 연동 금지가 아니라 특정 지표에 제한이 생기는 조건이다. 캐러셀의 개별 카드 이탈은 이 API로 알 수 없고, 과거 게시물의 ‘게시 24시간 후 성과’를 지금 누적값에서 복원할 수도 없다. 지원 지표와 결측·갱신 시점을 명시하고 연결 후부터 비교 가능한 시점의 기록을 남긴다. 이번 조사는 계정 연결·권한 승인·API 호출을 실제 완료한 상태가 아니다. [계정 Insights](https://developers.facebook.com/documentation/instagram-platform/api-reference/instagram-user/insights), [게시물 Insights](https://developers.facebook.com/documentation/instagram-platform/reference/instagram-media/insights)

## 3. 실제 서비스에서 확인한 연결 방식을 참고한다

Buffer의 공식 Insights 도움말은 성과 패턴·기존 콘텐츠 재사용 제안과 함께, 추천 카드를 누르면 계정 성과를 바탕으로 준비된 요청이 AI 작성 화면으로 이어지는 흐름을 설명한다. 이 사례에서 가져올 것은 ‘그래프 확인→사용자가 해석→새 도구에서 다시 입력’의 수고를 줄이는 연결 방식이다. 이는 기능이 존재한다는 증거이며 추천의 성장 효과를 입증한 실험은 아니다. [Buffer 공식 도움말](https://support.buffer.com/en-us/articles/using-insights-in-buffer-x4gLauQU5a)

vidIQ의 AI Coach는 YouTube 채널 자료를 이용한 진단·소재 추천과 새 계정의 시작 안내를 함께 설명하며, 썸네일·클립·짧은 영상 생성으로도 연결한다. 개인 운영자의 ‘무엇을 해야 할지 모르겠다’를 구체 작업으로 바꾸는 제품의 참고 사례다. YouTube 기능을 Instagram에서도 동일하게 구현할 수 있다는 의미는 아니다. [vidIQ 공식 도움말](https://support.vidiq.com/en/articles/8017871-ai-coach)

Flick은 소재 발상·문안·기획을 제작 계획 안에 모으는 방식을 참고할 수 있다. 해당 공식 페이지의 재가공 설명은 현재 블로그 글 변환과 향후 영상 계획을 구분하므로, 이 페이지를 영상 편집 지원의 근거로 사용하지 않는다. [Flick 공식 설명](https://www.flick.social/ai-social-media-assistant)

OpusClip의 ClipAnything은 업로드한 영상에서 요청에 맞는 장면을 찾고 짧은 영상·하이라이트·화면 비율 변경으로 이어가는 기능을 설명한다. 우리가 참고할 부분은 이미 가진 원본에서 다음 게시물 후보를 찾는 경험이다. 이 기능 설명이 우리 서비스 안에서 재판매·연동할 API 사용 권한까지 입증하지는 않는다. [OpusClip 공식 설명](https://www.opus.pro/clipanything)

이 서비스들이 제공한다고 시장 진입을 포기하지 않는다. 한국어 품질, 추천 이유의 명확성, 실제 제작 가능성, 편집 완료까지의 수고에서 비교한다.

## 4. 첫 화면은 이번 주에 만들 콘텐츠를 보여준다

계정이 연결되어 있으면 첫 화면에 다음 네 영역을 둔다.

1. **지금 계정에서 관측한 것:** 선택 기간, 사용한 게시물 수, 잘된 콘텐츠와 덜된 콘텐츠의 차이, 데이터 부족 항목.
2. **이번 주 추천 3개:** 주제, 추천 이유, 원자료·참고 출처, 형식, 필요한 사진·영상, 예상 작업량, ‘초안 만들기’ 버튼.
3. **제작 중인 콘텐츠:** 문안·카드·영상 후보를 수정하고 확정하는 작업 목록.
4. **올린 뒤 확인할 것:** 실제 게시물과 제작안을 연결하고, 같은 조건의 기존 콘텐츠와 비교할 지표.

사용자가 실제로 내린 목표를 먼저 확인한다. 팔로워 확대, 저장·공유되는 전문 콘텐츠, 상품·서비스 문의는 같은 목표가 아니다. 목표와 다른 지표가 높다고 무조건 좋은 소재로 추천하지 않는다.

새 계정은 이 화면에서 성과 수치를 꾸며 넣지 않는다. ‘계정 시작하기’를 선택해 관심 주제·도움을 줄 사람·보유 사진이나 영상·제작 가능한 시간을 입력하고, 소개 문구와 첫 콘텐츠 계획을 받는다. SNS 연결 전에 샘플과 제작 가치를 볼 수 있게 하고, 연결은 실제 계정 분석을 원하는 시점에 안내한다.

## 5. 계정 분석을 실제 제작 요청으로 바꾼다

아래는 실제 사용자 계정을 분석한 결과가 아닌 **제품 동작 설계 예시**다. 독서 콘텐츠를 정기적으로 올리는 운영자가 있다고 가정한다.

- **관측:** 충분히 비교 가능한 게시물에서 실용적인 독서 방법을 설명한 콘텐츠의 저장 반응이 높게 나타났다. 비교한 게시물과 지표를 함께 보여준다. 데이터가 적으면 ‘초기 관찰’로 표시한다.
- **추천:** “다음에는 퇴근 후 독서 시간을 만드는 방법을 카드뉴스로 시험해 보자.” 과거의 잘된 소재를 그대로 복제하지 않고 다른 질문에 답하는 후속 주제를 제안한다.
- **소재:** 사용자가 남긴 메모·관련 참고 자료·사용 권한이 있는 사진을 묶고, 사실 확인이 필요한 항목을 표시한다.
- **제작:** 표지 문구, 카드별 내용, 캡션을 만들고 문구·사진을 수정할 수 있게 한다. 원본 영상이 있으면 사용할 만한 구간과 짧은 영상 대본도 제안한다.
- **후속 확인:** 게시 후 같은 관찰 기간의 유사 형식과 저장·공유·도달 등을 비교하고 다음 제안을 조정한다.

‘저장 반응이 높았으므로 이 주제 때문에 성공했다’고 인과적으로 단정하지 않는다. 형식·게시 후 경과시간·유료 노출·이벤트·외부 소개 등의 차이를 가능한 범위에서 구분한다. 없는 시청자 유지 곡선이나 매출 데이터를 만들어 후킹·전환 원인을 설명하지 않는다.

추천의 단위는 링크 목록이 아니라 **제작 가능한 콘텐츠 한 건**이다. 추천마다 내 목표와의 관계, 내 계정에서 관측한 근거, 외부 자료, 필요한 원본, 제작 방법을 연결한다. 외부 도구를 써야 할 때도 도구명만 추천하지 않고 전달할 대본·자막·편집 지시를 준비한다.

## 6. 소재와 영상 편집은 이렇게 연결한다

| 상황 | 추천·제작 동작 | 초기 구현 범위 |
|---|---|---|
| 좋은 주제를 모르겠음 | 계정 목표·기존 성과·최근 자료에서 주제 후보 제시 | 승인된 자료 수집·중복 제거·추천 이유·기획안 |
| 원본 글·자료가 있음 | 카드뉴스·캡션·짧은 영상 대본으로 재구성 | 기존 Dify·카드뉴스·렌더 자산 활용 |
| 본인 원본 영상이 있음 | 전사, 주제 구간 후보, 짧은 영상 구성, 자막 초안 | 처음에는 구간·자막·편집 지시. 정식 도구 연동 또는 제한된 렌더는 다음 구현 범위 |
| 원본 영상이 없음 | 촬영 구성·필요 장면·화면 글·나레이션 제안 | 촬영 계획과 제작 자료 제공; 없는 원본을 자른 척하지 않음 |
| 매주 반복 제작함 | 지난 채택·수정·성과를 다음 제안에 반영 | 사용자 선택과 추천 이유 기록, 간단한 주간 계획 |

자동 자막·세로 화면 변환·원본 잘라내기는 구현 또는 적법한 API 연동으로 제공할 수 있다. 자유로운 타임라인 편집과 모든 생성형 영상 기능을 동시에 직접 만드는 것은 별도 규모의 개발이다. 기능을 제품에 포함할 가치와 자체 개발 여부를 분리해 판단한다. 상용 API의 이용 조건·원가·파일 전달·실패 복구를 확인한 뒤 통합 범위를 정한다.

## 7. 대행사와 개인에게 같은 핵심 기능을 다른 화면으로 제공한다

공통 구조는 목표·계정·자료·콘텐츠·수정·게시물·성과다. 개인에게는 자기 계정과 이번 주 계획만 보인다. 대행사에는 고객사 선택·브랜드별 기준·담당자·검토 상태가 추가된다. 처음부터 별도 제품 두 개를 개발할 필요는 없다.

첫 대행사 고객군은 유지하되, 개인 운영자를 계속 미래 후보로만 미루지는 않는다. 제한된 비교 대상에 개인 운영자 1명을 포함하는 안을 제안한다. 기존 2고객 확장안의 대행사 두 곳을 ‘대행사 1곳 + 정기 운영 개인 1명’으로 바꾸면 고객 수를 늘리지 않고 비교할 수 있다. 최소 1고객안에서는 별도 개인 인터뷰·시연을 하고 유료 반복 검증까지 했다고 주장하지 않는다.

두 집단에서 추천 채택→실제 제작→게시→다음 주 재사용→결제·지원 시간을 같은 정의로 본다. 대행사는 최종 승인·납품 시간도 보고, 개인은 실제 제작을 지속하는 데 도움이 되었는지도 본다. 개인이 더 좋은 반복 사용과 경제성을 보이면 다음 모집 비중을 늘린다. 한 명의 반응만으로 전체 시장 우위를 선언하지 않는다.

## 8. BM과 초기 계획에 반영한다

개인에게는 계정 1개를 위한 기본 구독과 포함 제작량, 대행사에는 복수 브랜드·협업·보고 범위를 묶는 구조가 적합한 가설이다. 영상은 처리 분량·생성 원가가 달라 별도 포함량이나 추가 요금으로 설계한다. 단발 진단서만 팔기보다 매주 다음 콘텐츠를 결정하고 완성하는 데 계속 쓰는지를 본다.

이전 문서의 59,000원·149,000원과 기여이익은 카드뉴스 중심의 가정이다. **계정 동기화·지속 소재 수집·영상 처리 원가를 포함한 수익성이 검증됐다는 뜻이 아니다.** 데이터 수집·추천·영상 원가와 API 연결 지원을 추가해 다시 계산한다. 개인의 지불 의사를 대행사 가격으로 대신 판단하지 않는다.

개발 계획은 다음처럼 보완한다. 1~2주에 목표·계정 연결 조건·API 앱 접근 준비와 고객 자료를 확인하고, 처음부터 데이터 출처와 최신 시점을 구분한다. 3~4주에는 확보한 데이터로 계정 요약과 다음 콘텐츠 3개를 만들고 기존 제작 흐름으로 연결한다. 5~8주는 실제 채택·게시·다음 주 사용을 관찰한다. 공식 API 승인이 지연되면 고객이 직접 제공한 자료로 추천을 검증할 수 있지만 이를 실시간 자동 분석이라고 표시하지 않는다.

추가 기능을 기존 72시간 안에 무조건 더하지 않는다. 자유 편집·새로운 협업 화면의 범위를 줄여 읽기 분석·추천을 앞당기고, 실제 데이터 연동량에 따라 일정·전문 개발 시간·운영비를 다시 산정한다. 자동 발행 권한 요청과 무거운 영상 렌더는 초기 읽기 분석과 분리한다.

**현재 제품 방향은 계정 분석과 제작을 연결하는 운영 서비스다.** 대행사는 첫 매출을 검증할 고객군이고, 개인 계정 운영자는 처음부터 제품 경험과 비교 검증에 포함하는 주요 후보 고객군이다. 어떤 고객에게 더 잘 맞는지는 실제 사용·지불·원가로 결정한다.
