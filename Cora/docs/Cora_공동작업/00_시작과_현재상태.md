## 작동하는 기능과 한계

로컬 계정·사용자별 SQLite 저장, 브랜드 프리셋, 소재/공개 링크/RSS, llmgw AI 카드·글·대본, 카드 편집·PNG/JSON 내보내기, 장면별 시간·선택형 한글 자막이 있는 FFmpeg MP4/SRT, 수동 CSV 성과 분석, 내부 달력·반복 지시 보관, 자산 편집, 다른 계정의 저장 버전 검토, 승인본 게시 준비, 영구 모의 게시 큐가 구현돼 있다. 정확한 범위와 검수는 원장과 증거를 따른다.

- 실제 SNS 게시/공식 분석 연결은 없다. Blotato 코드는 계약 모의 시험만 했고 실전 큐와 미연결이다. 모의 완료를 실제 게시로 표시하지 않는다.
- 반복 지시는 저장만, 게시 큐는 버튼으로 진행하는 simulation만 지원한다. 백그라운드 주기 실행이 완성된 것이 아니다.
- 팀 전체 역할·초대·공동 편집은 없다. 지정 검토자만 공유된 버전을 승인/수정 요청한다.
- 영상은 카드 슬라이드 + 선택형 자막. 음성/TTS·BGM·번인 자막·전체 타임라인 편집 미구현.
- 진단은 수동 CSV의 기술 통계 및 사람이 작성한 실험 가설 전달. 공식 Instagram 동기화·학습된 성장 점수·XGBoost·인과효과 없음.

- npm audit 미해결 이슈와 공개 운영 보안·배포 검수는 남아 있다. 로컬 개발용이지 출시 완료가 아니다.

## 다음 구현 우선순위

원장에서 실제 미완료인지 먼저 확인한다. 독립 구현은 계속하고, 키가 없는 항목은 연결 코드·계약 시험과 실검증 대기를 분리한다.

1. 주기 실행 스케줄러/영구 작업 큐: 현재 게시 simulation과 실제 자동 운영을 혼동하지 않고, 반복 작업의 재시작·중복 방지·실패 복구·사용자 격리를 구현한다. 유료 AI 자동 호출은 기본 끔.
2. 음성·영상: TTS 공급자 경계 및 모의 계약, 소유 음성 업로드/합성, 장면 길이 충돌, 자막 번인 등 실제 결과 검수. 새 유료 구독 불가.
3. 팀 워크스페이스 역할/권한과 승인 버전, 공급자 계정 소유권·미디어 호스팅·게시 결과 대조를 보강하되 실제 게시 안 함.
4. 공식 분석 어댑터와 표본/결측 공개, 진단→제작→평가 연결 및 나머지119개 기능. 연구 모델의 효과를 학습/외부 검증 없이 주장하지 않는다.

사용자는 1~2일 집중 통합 구현을 원한다. 12주는 이후 사용자 테스트·보완 기간이다. 학생 조유경은 주4~5시간. 사용자/학생/AI 90%+ 구현은 목표이지 달성률이 아니다. 완료된 부분을 다시 설계하느라 시간을 쓰지 않는다.

## 실행과 검증

Cora 폴더에서:

Node22.13+ 및 FFmpeg 필요. http://127.0.0.1:3210/studio 에서 확인한다. 이 runner는 소스를 OS 임시 runtime에 복사하고 의존성을 설치하며 사용자 DB는 원래 앱의 data/cora에 보존한다. 소스를 고친 뒤 runner를 재시작해야 복사가 반영된다. 기존 프로세스의 소유자를 확인하고 자기 프로세스만 종료한다.

프로덕션 검수는 소스를 별도 runtime으로 복사(node_modules/.next/data/.env.local 제외)하고 그 폴더에서 npm ci --ignore-scripts, npm run build, npm test를 실행한다. 테스트 서버는 127.0.0.1:3211과 별도 CORA_DATA_DIR를 사용해 사용자 DB를 오염시키지 않는다. 기존 검수 runtime은 `/var/folders/hq/jsdxnlqs5hzcxdfq1d8q_h1r0000gn/T/cora-runtime-bb3q2_1b`였으며 임시 폴더는 없어질 수 있으니 존재/최신 소스를 확인한다.

브라우저 검수 스크립트는 scripts/cora-*-proof.mjs. 해당 기능 스크립트만 선택한다. 일부 sprint/design 스크립트는 실제 AI를 호출하므로 무작정 전체 실행하지 않는다. ## Claude ↔ Codex 전환 규칙

1. **한 번에 한 도구만 같은 checkout을 수정한다.** 이 문서는 협업 규칙이며 자동 파일 잠금이 아니다. Claude가 작업 중일 때 Codex heartbeat를 재개하지 않는다.
2. 받는 도구는 이 문서와 Git 상태를 읽는다. 변경이 있으면 이전 작업으로 취급하고 보존한다. reset --hard, clean, 무단 stash·브랜치 교체·새 clone 금지. 중복 구현 여부는 원장/실제 코드로 확인한다.
3. 작업 종료 시 이 파일의 ‘현재 인계 상태’를 갱신한다: 수행 기능, 커밋 기준, 미커밋 파일과 이유, 시험 명령/결과, 실행 중 프로세스·포트·DB, 다음 우선 작업, 외부 입력 필요 사항. 종료하지 못한 작업도 정확히 적는다.
4. 기능 원장 CSV/JSON/HTML 및 증거를 함께 갱신한다. 사용자 문서를 outputs에 반영한다. Git diff --check 후 본인이 바꾼 Cora 파일만 커밋·같은 브랜치에 푸시하고 PR1 설명을 최신화한다. 푸시 불가 시 사유와 로컬 커밋을 기록한다.
5. 인계 직전 자기 테스트 서버/수정 작업을 끝낸다. 미리보기를 남기면 위치와 재시작 방법을 적는다. 이 문서의 outputs 사본도 동기화한다.
6. 돌아오는 도구는 문서가 오래됐을 가능성을 감안해 git log/diff와 실제 파일을 재확인한다. 사용자에게는 ‘공동 인계 파일을 읽고 이어서 진행해’ 한 문장이면 충분하도록 유지한다.
