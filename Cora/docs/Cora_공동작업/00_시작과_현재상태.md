## 2026-10-04 Cora 구현: Instagram 읽기 권한 기본 연결

`@bdm.lab`의 Cora-IG 테스터 초대 수락을 Instagram PC 화면과 Meta 앱 역할 화면 양쪽에서 확인했다. 연결 버튼의 기본 OAuth 범위를 `instagram_business_basic`·`instagram_business_manage_insights`로 좁혔다. 게시·댓글 권한은 명시적 `access=manage` 요청에서만 포함한다. OAuth 확인값에 요청 범위를 묶어 저장하고, 연결 상태에 요청 범위를 표시한다. 기존 DB는 요청 범위가 불명이므로 게시 권한을 가진 것으로 추정하지 않는다. 브라우저 표시 또한 **요청 내역**이지 Meta의 실제 허용 검증으로 표현하지 않는다.

`instagram-connect.ts`, 연결 API·콘텐츠 순환 UI·이전 시험을 수정했다. Instagram 연결 관련 시험 11개, 타입 검사, Next 프로덕션 빌드 통과. 실제 Meta OAuth·인사이트 API 호출·게시 호출은 0회. 현재 서버 비밀 설정과 안정적인 HTTPS 복귀 주소가 없어 실계정 연결은 아직 하지 않았다. 다음에는 이 두 설정을 준비하고 `@bdm.lab` 사용자가 공식 Instagram 승인 화면에서 직접 읽기 권한을 허용한 뒤, 읽기 API 결과를 검증한다. 운영 계정에는 첫 실제 게시를 하지 않는다.

이 파일이 두 도구의 공통 시작점이다. 채팅 기록 전체를 다시 읽거나 다른 폴더에 재구축하지 않는다. 실제 코드·Git 상태·기능 원장이 문서보다 우선한다.

## 작동하는 기능과 한계

로컬 계정·사용자별 SQLite 저장, 브랜드 프리셋, 소재/공개 링크/RSS, llmgw AI 카드·글·대본, 카드 편집·PNG/JSON 내보내기, 장면별 시간·선택형 한글 자막이 있는 FFmpeg MP4/SRT, 수동 CSV 성과 분석, 내부 달력·반복 지시 보관, 자산 편집, 다른 계정의 저장 버전 검토, 승인본 게시 준비, 영구 모의 게시 큐가 구현돼 있다. 정확한 범위와 검수는 원장과 증거를 따른다.

- Instagram OAuth·다중 계정·암호화 토큰·성과 수집 코드와 공식 게시/Reels 어댑터·S3 업로드가 있다. 실제 계정 인증·공개 게시·성과 수집은 미검증이며 게시 큐의 실제 공급자 실행 연결은 남아 있다. Blotato는 대안 어댑터로 유지한다. 모의 완료를 실제 게시로 표시하지 않는다.
- 반복 지시와 모의 게시 큐는 예약 작업 스케줄러(`lib/cora/scheduler.ts`, 13_예약작업_스케줄러.md)로 백그라운드 진행이 가능하다. 단, `CORA_SCHEDULER=1`일 때만 루프가 돌고, 레시피의 유료 AI 자동 호출은 예약별 허용 + `CORA_SCHEDULER_AI=1`이 모두 필요하며 기본은 건너뜀이다. 단일 프로세스용이며 다중 서버 워커는 아니다.
- 팀 관리 메뉴에서 가입 계정을 편집자·검토자로 초대하고, 수락한 편집자는 허용 브랜드의 소유자 작업을 열고 저장한다(14_팀_권한과_초대.md). 초대 이메일 발송, 저장자 기록, 소유권 이전, 동시 편집 병합은 없다. 검토 요청은 기존처럼 가입한 어느 계정에나 보낼 수 있다.
- 영상·음성·자막은 Claude가 확장했다. 세부 지원 범위와 외부 서비스 의존은 20_API없이_마무리한_기능.md 및 원장을 확인한다. 이번 Codex 세션에서는 영상 전체 회귀를 다시 실행하지 않았다.
- 진단은 수동 CSV와 콘텐츠 순환의 성과 비교·다음 후보 반영을 포함한다. Instagram 수집 코드는 모의 시험까지만 검증했다. 학습된 성장 점수·XGBoost·인과효과 검증은 없다.
- 기존 Trend API/페이지는 CORA_LEGACY_OPERATOR_ID 없는 경우 기본 차단한다. 이를 편의상 해제하지 않는다. 원본 cron도 서비스 인증 구현 전 차단 상태다.
- npm audit 미해결 이슈와 공개 운영 보안·배포 검수는 남아 있다. 로컬 개발용이지 출시 완료가 아니다.
