고객사 맥락은 주요 고객·목표·말투·시각 규칙·주제·피할 표현·색상을 저장한다. 새 카드 제작에는 고객사 이름/대상/목표/색상을 적용하고 AI 카드 생성은 소유자가 가진 clientId로 말투/주제/피할 표현을 찾는다. 시각 규칙 전체 적용과 광고 스타일 통합은 아직 아니다. focused AI 생성은 보존된 브랜드 이름 기반 지식검색을 사용하지 않는다. 이번 검수에서는 실제 AI 생성 0회이며 고객사 맥락을 포함하는 실제 출력 품질은 검증 대기다.

기존 작업은 고객사 미지정으로 보존한다. 같은 이름이라고 자동 연결·병합하지 않는다. 작업 고객사 선택은 저장해야 반영된다. 변경은 새 버전/재검토 대상이다. JSON 가져오기는 다른 체크아웃의 clientId를 신뢰하지 않고 제거한다. 같은 소유자의 명시적 사본은 ID를 유지한다. 새 프로필을 만들면 기존 카드의 ID를 바꾸지 않으며 고객사 이름 변경에도 연결이 유지된다.

## 권한과 보존의 경계

기존 팀 권한은 브랜드 이름을 사용한다. 이를 새 고객사 권한으로 추측 이전하지 않았다. clientId가 붙은 작업은 새 고객사 권한을 구현하기 전까지 **소유자만 편집**한다. 이미 지정된 검토자는 기존 검토 요청의 승인 버전 사본을 볼 수 있다. 기존 팀 편집자는 ID가 없는 기존 작업의 권한을 유지하지만 고객사 지정은 소유자만 한다. 이 임시 제한은 화면에 안내하며 L07을 완료한 것으로 표시하지 않는다.

고급 영상·블로그·링크 페이지·공개 API/MCP·제휴·결제 화면·범용 레시피·모의 게시 작업은 원래 위치에 보존한다. focused에서 모의 큐/레시피 worker는 실행 전에 skip하고 기존 큐를 지우지 않는다. 전체 옛 scheduler 루프는 시작하지 않는다. 이는 출시용 실제 Instagram 예약 워커 구현이 아니다. labs는 인증을 우회하는 모드가 아니며 공개 고객 운영에 사용하지 않는다.

독립 콘텐츠 순환(/loop) 역시 focused에서 보존한다. 기존 순환의 임의 등록/즉시 게시와 여러 출력 형식을 승인 흐름의 우회로로 열지 않았다. **승인본→연결 계정→실제 큐**를 구현·검수한 뒤 필요한 부분만 첫 출시 흐름에 연결한다.

Instagram 연결 화면은 기존 공식 읽기 OAuth 경로와 준비 검사를 사용한다. 요청 범위와 실제 허용 검증을 구분한다. 현재 HTTPS 복귀주소·비밀 설정·실API 검증은 남는다. bdm.lab에는 게시하지 않았다. 광고는 현재 별도 수동 계정 스타일 입력을 사용하며 카드 편집기로 가져온 뒤 고객사를 명시 지정한다. 계정/프로필/광고 자동 통합으로 표현하지 않는다.
