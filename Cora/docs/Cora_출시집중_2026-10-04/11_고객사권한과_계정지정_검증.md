# 구현 2 — 고객사별 팀 권한과 Instagram 계정 지정

2026-10-04 · 검증 코드 **7389d42** · 구현 및 로컬 검수: Codex. Claude/Astra 독립 검수는 미실행이다. 사용자 지정 Drive checkout·기존 브랜치·PR1에 저장했다. 자동화는 재개하지 않았다.

## 실제로 바뀐 동작

- 팀 초대와 권한 수정에서 허용할 **clientId를 명시적으로 선택**한다. 같은 고객사 이름도 서로 다른 ID로 구분한다. 빈 목록은 권한 없음이며 새 고객사가 자동 추가되지 않는다. 기존 이름 기반 멤버십은 legacy로 보존하며 새 ID 작업에 적용하지 않는다. 소유자가 권한을 저장하면 명시적 고객사 범위로 전환한다.
- 초대 수락 전에는 접근할 수 없다. 수락한 편집자는 선택한 고객사의 프로필을 읽고 카드·캡션을 만들거나 수정한다. 편집자가 만든 카드도 해당 고객사 소유자에게 저장하며 응답의 editor 표시를 유지한다. 편집자는 기존 카드의 고객사를 바꾸거나 지정 해제할 수 없다. 고객사 설정 수정·삭제·검토 요청·게시 준비는 소유자만 한다.
- 팀 초대 수락/역할·범위 변경/회수는 버전으로 충돌을 검사한다. 명시적 고객사 멤버십은 저장소 메서드에서도 버전을 요구한다. 반복 초대로 활성 멤버의 권한을 덮어쓰는 경로를 거부한다. 카드 저장의 권한 검사와 갱신은 같은 쓰기 트랜잭션에서 수행한다.
- 고객사가 지정된 카드의 검토 요청은 그 고객사의 초대를 수락한 팀원에게만 보낸다. 검토자는 자신에게 요청된 저장 사본만 보고 원본 편집·전체 고객사 프로필 읽기는 못 한다. 권한 회수 뒤 사본 읽기·목록·결정·계정 내보내기에서 접근을 막는다. 소유자의 과거 검토 기록은 보존한다. 이미 내려받은 파일을 원격 삭제하는 기능은 아니다.
- Instagram 연결 화면에서 소유자가 공식 승인으로 연결된 **숫자 계정 ID**를 직접 선택해 고객사에 지정한다. 고객사당 하나, 같은 워크스페이스 안에서 한 Instagram 계정은 한 고객사에만 지정한다. accountId는 연결 지정의 고유 UUID이며 계정 교체 시 유지된다. 이름 변경으로 연결 대상이 바뀌지 않는다.
- 계정 지정 변경/해제는 accountId와 version을 함께 확인한다. 연결을 해제한 뒤 새 연결이 v1로 생겨도 옛 창이 이를 해제할 수 없다. Instagram 승인 연결 삭제는 외래키로 고객사 지정을 함께 제거한다. 고객사 지정만 해제하면 공식 승인 연결은 유지한다.
- 편집자는 허용된 고객사의 지정 계정 메타데이터만 확인한다. 소유자의 다른 계정 선택지나 토큰은 반환하지 않는다. 만료된 계정 신규 지정은 거부한다. 표시한 범위는 OAuth **요청 내역**이며 실제 허용 권한으로 단정하지 않는다. OAuth 후 고객사 자동 지정도 하지 않는다.

원본 사용자 DB·키는 읽지 않았다. 임시 격리 DB와 합성 계정만 사용했고, Instagram 계정 선택 화면은 DB에 심은 **무효한 합성 토큰**으로 검수했다. 실제 AI/Meta/SNS 호출·외부 메시지·결제·배포는 모두0회다. 시험 서버는 종료했다. 원본 DB에 의존하는 recipe 시험1개 제외는 기존 상태다. 이전 구현의 모드3종 재시작 증거는 구현1에 보존하며 이번에는 새로 실행한 것으로 계산하지 않는다.

증거: `증거/구현2_고객사권한과_계정지정/`. 화면 PNG는 Drive outputs 사본에 있으며 Git에는 합성 JSON·시험/빌드 기록을 보관한다.

재현:
1. Cora/apps/trend-hub와 integrations/rita의 상대구조를 보존해 격리 runtime에 복사한다. 원본 data/.env는 복사하지 않는다. npm test, npm run typecheck, npm run build를 실행한다.
2. `/tmp/cora-client-proof-*`의 새 CORA_DATA_DIR로 로컬3211 서버를 시작한다. focused 모드·로컬 CORA_ORIGIN을 명시하고 사용자 비밀값은 로드하지 않는다.
3. `scripts/cora-client-access-proof.mjs`에 CORA_PROOF_DIR과 CORA_PROOF_DB=<격리 data>/studio.sqlite를 지정한다. 스크립트가 가짜 계정 메타데이터를 넣으므로 **원본 DB에 실행하지 않는다**. localhost와 임시 DB 경로를 검사한다.
4. `scripts/cora-focused-proof.mjs`로 기존 출시 회귀를 실행한 뒤 자신이 시작한 서버만 종료한다. 두 스크립트는 실제 생성·Meta 승인·게시를 하지 않는다.

## 완료로 처리하지 않은 부분

L05/L07은 **부분검증**이다. 카드·검토 사본·연결 메타데이터 권한은 붙었지만 자산/광고/지식/성과의 전체 clientId 연결은 남았다. 현재 이 모듈은 개인 소유 저장을 유지하며 팀 고객사의 자료가 연결된 것으로 보이지 않게 추가 구현해야 한다. 동시 여러 서버의 모든 실패 순서·백업/복원·독립 검수·실환경 검증도 남았다.

기존 DB 추가 필드와 재시작은 합성 구버전 시험으로 확인했지만 L06의 이전2회/중단복구/검증 복원 기준은 충족하지 않았다. 미저장 초안의 새로고침 복구·주간 묶음·실제 게시 큐 연결·성과 수집도 아직 없다. accountId 지정 저장을 실제 게시 가능 증거로 취급하지 않는다. 첫 실제 게시에는 전용시험계정과 그때 교수의 명시 확인이 필요하며 bdm.lab에 게시하지 않는다. 119개 원장과 완료 기준은 변경하지 않았다.

## 유경이 바로 확인할 것

가상 고객사 두 개를 같은 이름으로 만들고 소유자/편집자/검토자 Cora 계정으로 시험한다. 한 고객사만 초대해 수락한 뒤 다른 고객사 카드 접근이 막히는지, 편집자의 새 카드·수정이 소유자에게 반영되는지, 역할 변경과 권한 회수 뒤 저장/검토가 막히는지 확인한다. 날짜·코드 버전·행동·기대/실제·화면을 기록한다. 실제 Instagram 연결이나 키가 없어도 이 검수는 가능하다. 기존 학생 계획의 이름 기반 브랜드 선택 설명은 이 ID 선택 기준으로 읽는다.
