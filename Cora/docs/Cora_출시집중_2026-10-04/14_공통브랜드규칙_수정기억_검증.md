# Cora 공통 브랜드 규칙·수정 기억 — 2026-10-04

검증 코드 **101449b**. 지정한 Drive checkout의 Cora에서 구현했다. 고객사 맥락을 한 번 수정하면 일반 카드 생성과 광고 제작이 같은 최신 규칙과 최근 수정 메모를 참조한다. 결과에는 실제 생성 시 캡처한 규칙 버전을 보관한다. 규칙에 맞는 결과가 나왔는지는 별도 사람 검수 대상이다.

## 사용할 수 있는 흐름

1. 고객사 화면에서 말투·시각 규칙·반복 주제·피할 표현·색상과 **규칙의 근거·참고 자료**, **이번 수정 이유·다음 제작에 반영할 메모**를 저장한다. 공통 규칙 수정은 소유자만 한다.
2. 저장하면 규칙 버전과 당시 값, 변경 필드, 저장한 사용자 ID, 시간이 한 트랜잭션으로 기록된다. 이력 기록 실패나 버전 충돌이면 규칙 변경도 롤백된다. 소유자와 해당 고객사의 현재 편집자는 이력을 읽을 수 있다. reviewer는 이력 API 접근이 없다.
3. 일반 AI 카드와 광고 생성은 서버의 동일한 규칙 사본을 제작 지시에 넣는다. 전체 규칙을 임의로 4,000자에서 자르지 않는다. **최근 수정 메모 5개**도 전달한다. 현재 규칙과 과거 메모가 충돌하면 현재 규칙을 우선하도록 지시한다. 검토 의견에서 자동으로 규칙 후보를 추출하는 L19나 머신러닝 학습은 이번 구현이 아니다.
4. 광고 계정 사용자명과 기존 캡션은 계정별로 기록한다. 고객사를 선택하면 브랜드 규칙 필드는 읽기 전용이다. 오래된 개인/계정 프로필이나 요청 본문이 공통 규칙을 덮어쓰지 않는다. 서버가 현재 공통 규칙을 적용한다. 기존 개인 프로필 자체는 보존한다.
5. 생성 결과·광고의 모든 카드 초안·프로젝트 저장/버전 이력·JSON 내보내기는 해당 규칙 사본을 유지한다. 기존 작업의 규칙 버전을 최신으로 조용히 바꾸지 않는다. 제작 중 규칙이 바뀌면 응답/화면이 재확인을 알린다. 과거 광고안을 열 때 현재 버전과 다른 것도 표시한다.
6. 편집 화면의 **참조 브랜드 규칙**을 펼쳐 당시 규칙·근거·확인 기록·수정 메모를 읽는다. 한 줄에 하나 입력한 피할 표현이 현재 카드/캡션에 그대로 나타나면 경고한다. 문자열 비교이며 의미 판단·사실 확인·광고 성과 예측은 아니다.
7. 과거 규칙을 불러와 수정·저장하면 새 버전으로 기록된다. 최근100개 이력을 화면에 보여주고, 그보다 오래된 결과의 버전 참조도 서버에서 보존한다. JSON을 새 사본으로 가져오면 고객사/규칙 연결을 지워 다시 지정하게 한다.

AI 없이 만드는 원문 구성 초안도 선택 고객사의 규칙 사본과 브랜드명·색상을 붙인다. 원문 내용과 자유 입력한 시각 규칙을 자동 변환·검증했다는 뜻은 아니다. 저장 시 사용자가 변조한 근거/확인자 사본은 실제 규칙 이력 값으로 대체한다. 미저장 복구함의 규칙 사본은 초안 자료이며 고객 승인 증거가 아니다.

## 입력 계약·구자료 이전

- 말투·시각 규칙·반복 주제·피할 표현은 각각 **2,000자**. 주제/피할 표현은 한 줄에 하나이며 줄바꿈을 포함한 총 길이를 검사한다. 광고만6개/12개·60자/80자로 제한하던 계약을 정리했다. 빈 선택 규칙도 고객사 광고에 허용한다. 캡션3~12개·예시 총12,000자 제한은 유지한다.
- 규칙 근거1,000자, 수정 메모500자. 근거 링크를 자동 조회하거나 사실로 인증하지 않는다. 계정 실제 피드/이미지 분석도 아직 없다.
- 광고 대상은 일반 카드 계약과 같은160자로 정리했다. 이전161~200자 입력은 생성 후 카드 검증에서 실패할 수 있었으므로 이제 생성 전에 거부한다(D13).
- `client_rule_history`만 추가하고 기존 clients JSON을 다시 쓰지 않는다. 구자료는 알고 있는 현재 버전 하나만 이전하고 확인 기록 없음으로 표시한다. 과거 버전·확인자를 지어내지 않는다. 반복 이전 시 사본은 동일하다. 계정 export/삭제와 DB 이전/복원 bootstrap에 포함된다.
- 고객사/규칙 ID가 다른 초안은 거부한다. 소유자가 고객사를 옮기면 예전 규칙 연결을 버리고 새 고객사 규칙으로 저장하며 검토 완료를 초기화한다. 템플릿 적용도 초안 고객사 범위를 먼저 검사해 기존404 계약을 유지한다.

## 남는 일과 인계

L09의 **첫 출시 공통 규칙 기능은 로컬 구현·검수됨**. 전체 L09는 labs에 보존된 이름 기반 지식/스타일 자료의 명시 이전과 독립 검수·실제 생성 품질 확인이 남아 부분검증으로 유지한다. 보존 모듈은 focused 서버에서 차단돼 일반/광고 제작에 몰래 섞이지 않는다. L10 소재 후보→L11 주간 묶음, L19 검토 의견에서 규칙 후보, L23 원자 비용 예약/정산, 실게시 job/Meta, staging/media/키 복원은 남는다. 전체 출시나90% 달성을 주장하지 않는다.
