# Cora 고객사별 자산·광고·성과 연결 — 2026-10-04

검증 코드 **229a87f**. 사용자 승인에 따라 기존 Drive checkout의 `Cora/`에서 구현했다. 개인 자료를 이름으로 추측해 고객사에 연결하지 않는다. 새 자료는 선택한 고객사 ID로 저장하며, 수락한 편집자는 해당 고객사 자료만 사용할 수 있다. 원본119개 원장과 sibling 프로젝트는 보존했다.

## 실제 바뀐 동작

| 작업 | 저장·사용 방식 | 접근권한 |
|---|---|---|
| 템플릿·로고·CTA | `library_*`의 nullable `client_id`; 템플릿 적용/추출도 작업과 같은 ID를 요구 | 고객사 소유자와 현재 편집자; 다른 ID·reviewer 거부 |
| 개인 자산 복사 | 소유자가 자료 하나를 선택해 새 ID로 복사; 원본 유지 | 편집자에게 소유자의 개인 자료/복사 목록 미제공 |
| 광고 계정 스타일 | `ad_client_profiles`의 user/client/handle 복합 키; 동일 handle도 고객사마다 독립 | 같은 고객사 소유자와 현재 편집자 |
| 광고안·편집본 | `ad_creatives.client_id`, 결과·모든 draft의 `clientId`; 편집기로 옮겨도 유지 | 소유자 workspace에 저장; 생성 전·응답 저장 직전에 권한 재확인 |
| 소재·CSV 진단·실험 | `work_items.client_id`; 선택 범위에서만 목록/진단/실험 생성 | 현재 고객사 권한을 트랜잭션 안에서 확인 |
| 성과 리포트 | 같은 고객사 분석 ID와 같은 범위 해석만 사용; 고객사 이름/ID 표기 | MD/HTML 다운로드에도 현재 권한 적용; no-store |
| 고객사 전환 | 자산·광고·작업실을 사용자+clientId 키로 새로 구성 | 늦은 이전 실험 응답으로 화면/제작 고객사를 바꾸지 않음 |

기존 `client_id IS NULL` 자료는 본인의 개인 영역으로 남는다. 선택한 고객사의 소유자만 자신의 개인 자산·소재·성과 복사 목록과 개인 광고 스타일 가져오기 목록을 본다. 목록에 나타난 자료가 자동으로 공유되는 것은 아니다. 자료 복사/고객사 스타일 저장을 명시 실행해야 한다. 편집자가 만든 고객사 자산은 대행사 소유자에게 저장하므로 편집자를 삭제해도 대행사 자료가 사라지지 않는다.

기본 로고 변경·삭제 후 승계, CTA 중복 검출·사용 횟수와 보관 한도도 고객사 범위 안에서만 동작한다. 즐겨찾기 변경은 템플릿 버전을 갱신해 오래된 편집 창의 덮어쓰기를 막는다. 로고는 보관/기본 지정 기능이며 이번 작업에서 자동 카드 배치 기능을 추가한 것은 아니다.

## 권한·이전의 구현 근거

- 요청의 ownerId는 신뢰하지 않는다. `withClientAccess(actor,clientId,fn)`가 실제 고객사 소유자를 찾고 수락된 editor grant를 확인한다. 동기 읽기/쓰기와 권한 검사를 같은 SQLite 쓰기 잠금 안에서 실행한다. 네트워크를 기다리는 동안 트랜잭션을 유지하지 않는다.
- 라이브러리 내부 변경은 savepoint로 묶어 바깥 권한 트랜잭션과 함께 롤백한다. 회수/오류 시 생성한 자료가 먼저 커밋되지 않는다.
- 광고 생성은 호출 전 검사를 하고 await 뒤 결과 INSERT와 권한 재검사를 묶는다. 다른 DB 연결이 생성 중 grant를 회수한 반례에서 결과가 저장/반환되지 않았다. 일반 카드 생성 응답에도 await 뒤 현재 권한 검사를 추가했다. 이미 시작한 제공자 호출을 취소하거나 비용을 환불하는 구현은 아니다.
- 고객사 ID가 잘못된 형식이면 개인 자료 영역으로 조용히 돌아가지 않는다. 이름이나 handle이 같아도 ID별 저장 영역은 합쳐지지 않는다.
- `schemaStep`으로 library/work_items/ad_creatives에 열·색인을 추가한다. 기존 ad_account_profiles는 그대로 두고 고객사용 프로필 테이블을 추가한다. 오프라인 DB 이전/복원 bootstrap에도 새 모듈을 등록했다. 합성 구스키마·새 스키마를 재이전·복원해 원본 행과 관계 보존을 확인했다.
