## 가장 중요한 발견

별도 cardnews 폴더가 비어 있어도 트렌드 허브에는 `lib/producers/cardnews-native.ts`가 있다. 후보의 근거를 이용해 카드 원고·캡션을 만들고 렌더 서버로 연결하는 코드다. 따라서 기존 기능을 전부 새로 만들 필요는 없다. 다만 실제 이미지 렌더 서버 구현 자체가 포함된 것은 아니다.

확인한 핵심 파일:

- `lib/core/candidate.ts`: 후보 데이터 계약.
- `lib/core/registry.ts`: 판정기/생성기 등록과 실행 상태 연결.
- `lib/core/store.ts`: JSON 파일 저장과 프로세스 내 쓰기 직렬화.
- `lib/producers/cardnews-native.ts`: 근거 기반 카드 원고·캡션 생성, 카드 장수·말투·계정 입력.
- `lib/core/render.ts`: 외부 렌더 서버 health·이미지 업로드·렌더 연결.
- `app/api/produce/route.ts`: 후보 종류와 생성 게이트 확인 후 생성·저장.
- `components/cardnews-view.tsx`, `components/poster-view.tsx`: 기존 출력 UI 후보. 편집·내보내기의 실제 수락시험은 별도 필요.

## 통합 전에 확인할 구체적 항목

1. `store.ts`는 로컬 data/db.json 기반이다. Cora의 고객·브랜드별 저장과 운영 환경은 별도 설계·검증한다. 현재 코드의 직렬화만으로 여러 서버의 동시 저장까지 보장한다고 보지 않는다.
2. 살펴본 produce API에는 사용자 인증·브랜드 소유권 검사가 보이지 않는다. 전체 접근 경계를 추가 점검하고 직접 구현한다.
3. 카드 생성 모델 이름은 코드에 고정돼 있다. 공급자의 현재 지원과 계정 접근을 확인하고 설정으로 분리할지 결정한다. 문자열 존재만으로 API 실행 가능이라고 판단하지 않는다.
4. 렌더 서버의 현재 접근 가능 여부·출력 형식·보관 방식은 아직 확인하지 않았다. README의 과거 정상 상태를 현재 사실로 사용하지 않는다.
5. 트렌드 레이더 본체와 허브의 연결 어댑터를 구분한다. README에는 별도 레이더 결과를 가져오는 구조가 설명돼 있다. 결과 수집 어댑터가 있다고 원래 레이더 전체 구현이 포함됐다고 판단하지 않는다.
6. 근거 URL 검사는 유용하지만 사실 정확성·콘텐츠 품질·성장 효과를 검증한 것은 아니다. 실제 입력과 결과를 함께 평가한다.

## 첫 구현 순서

1. 키·운영 데이터를 사용하지 않는 로컬 실행 환경에서 트렌드 허브의 빌드와 기존 단위 테스트를 확인한다. `_live_*`와 수집/렌더 시험 스크립트는 일반 테스트와 구분한다.
2. Cora의 브랜드→소재 후보→제작 초안→편집→저장·내보내기 화면 흐름을 구성한다. 미연동 기능은 샘플 상태를 명시한다.
3. 후보·근거·원고 생성 모듈을 재사용하되 Cora 데이터 계약과 연결한다. 실 API 시험은 소량으로 구분해 실행 결과와 원가를 기록한다.
4. 별도 카드뉴스 서버 코드가 확보되면 기존 렌더를 연결한다. 확보 전에는 독립적인 브라우저 미리보기와 카드 편집을 만들 수 있다.
5. 브랜드별 권한·저장, 계정 연결, 성과 기록을 두 사람과 AI가 직접 구현한다. 해결되지 않는 문제만 개발자 인계 목록에 쌓는다.

## 추가로 있으면 필요한 자료

- 카드뉴스 렌더 서버 구현 저장소/폴더와 사용 중인 Dify YAML.
- Dance-shortform의 app/ 전체, Short-form의 agent/·schemas/ 등 실제 소스.
- 별도 트렌드 레이더 본체를 재사용하려면 해당 소스 위치.

비밀키는 저장소나 대화에 올릴 자료가 아니다. 누락 자료가 없어도 Cora 화면·편집·저장 설계와 트렌드 허브 재현은 진행할 수 있다.

개발 원칙: Cora(Content Operations Run by Agents), 12주, 창업자·조유경 학생·AI가 합의한 출시 범위의90% 이상 구현 목표. 개발자에게 특정 기능 전체를 자동 외주하지 않는다.


## 추가 확인 — 배포된 카드뉴스 앱

사용자 제공 배포 주소: https://cardnews.david112702.workers.dev/

2026-09-29에 루트 HTML과 해당 HTML이 참조하는 공개 lib/chat.js를 HTTP로 읽었다. 브라우저 조작 도구의 초기화가 실패하여 실제 화면 클릭·업로드·생성·다운로드를 실행하지 않았다. 원본 응답은 work/cardnews-deployed.html, work/cardnews-deployed-chat.js에 보관했다.

공개 프런트엔드에서 확인한 구성은 채팅과 미리보기 분할 화면, 템플릿 탐색/선택, 사진·로고 파일 입력, 텍스트 수정용 UI, 이미지 자리 이동/제거 관련 UI, 화풍·언어 선택, 생성 진행/중단 및 대화 재개 경로다. 실제 성공 여부는 별도 시험 대상이다.

chat.js는 /api/chat, /api/bake, /api/upload, /api/jobs/{id}, /api/jobs/{id}/stop, /api/conversation/{id} 등을 참조한다. 이는 브라우저가 호출하도록 작성된 경로이며 서버 계약·인증·실행 성공을 확인했다는 뜻이 아니다. 변경 요청은 호출하지 않았다.

이 배포 앱을 Cora의 카드뉴스 기능 재사용 우선 후보로 추가한다. 코드가 올라오면 대화·초안·템플릿·편집·작업 상태·렌더를 Cora에 연결할 수 있는지 확인한다. 기존 cardnews-render.onrender.com과 같은 백엔드라는 가정은 하지 않는다. 별도 cardnews 폴더가 비어 있다는 앞선 관찰은 GitHub 당시 상태에만 해당하며, 카드뉴스 앱이 존재하지 않는다는 의미가 아니다.
