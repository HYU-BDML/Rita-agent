# Mirr의 노하우와 재현 가능성 — 조사 판단

2026-09-28 조사. 아래의 구현 방식은 원본 소스코드를 확인한 결과가 아니라, 공개된 동작을 독립적으로 구현하는 설계 판단이다.

기능을 만드는 일과 같은 품질을 내는 일은 다르다. 카드뉴스 생성 버튼, 편집기, 예약 발행, 댓글 규칙은 독립적으로 구현할 수 있다. 같은 입력에서 어떤 문구·디자인·영상이 나오는지, 수정이 얼마나 적게 필요한지, 발행과 메시지 전송이 얼마나 안정적인지는 별도의 검증이 필요하다.

## 확인된 단서

- 디자인 참고 이미지 1–5장을 분석하고 반복 사용 가능한 스타일로 만든다고 안내한다. 색·서체·레이아웃·패턴이 대상이다. 실제 내부 표현과 추출 정확도는 미확인. 출처: https://www.mirra.my/en/ai-carousel-generator
- 말투 지침과 참고 게시물을 저장·업로드해 생성 결과를 조정하는 사용법을 안내한다. 이것만으로 모델 가중치를 학습한다고 결론 낼 수 없다. 출처: https://www.mirra.my/en/help/brand-tone
- Instagram 계정 말투·과거 게시물·성과를 다음 콘텐츠 기획에 활용한다고 설명한다. 과거 정보의 수집 범위, 검색 방식, 추천식은 공개하지 않는다. 출처: https://www.mirra.my/en/instagram-content-ai
- 생성·음성·렌더링 등에 외부 공급자를 사용한다고 정책에 명시한다. 따라서 모든 능력이 Mirr 자체 개발 모델에서 나온다는 근거는 없다. 공급자 목록은 기능별 실제 호출 경로·버전·현재 활성 상태까지 증명하지 않는다. 출처: https://www.mirra.my/en/privacy

## 경험이 품질로 바뀌려면

데이터가 많다고 자동으로 노하우가 되지 않는다. 원문, 최초 초안, 수정본, 최종 승인본, 사용한 모델·프롬프트·템플릿 버전, 생성 비용, 게시물 ID, 발행 시각, 반응을 서로 연결해야 한다. 그래야 실패가 어느 단계에서 생겼는지, 사용자가 무엇을 고쳤는지, 어떤 수정이 반복되는지를 확인할 수 있다.

예를 들어 한 카드의 문장을 사용자가 세 번 줄였다면 단순히 최종 문장만 저장하면 부족하다. 최초 글자 수, 레이아웃의 텍스트 영역, 실제 줄 수, 수정 이유를 저장하면 다음 생성에서 해당 유형의 카드에 더 짧은 문장을 배치하는 규칙을 만들 수 있다. 이 규칙은 다른 문장·서체·화면 크기에서도 검증해야 한다.

반응 데이터도 마찬가지다. 조회수가 높은 게시물 하나만 보고 후크가 좋았다고 학습하면 계정 규모, 광고 집행, 계절 효과를 혼동할 수 있다. 같은 계정에서 비슷한 관측 기간을 사용하고, 저장률·완독률·문의 전환 등 목적에 맞는 지표를 따로 보아야 한다. 이는 우리 서비스 설계 제안이며 Mirr가 실제 이렇게 운영한다는 뜻은 아니다.

## 자체 모델이 있어야 하나

초기에는 반드시 그렇지 않다. 외부 모델 + 참고 자료 검색 + 업종 규칙 + 편집 가능한 출력 구조 + 품질 검사가 하나의 구현 경로다. 품질 차이가 확인되면 어떤 단계가 부족한지 먼저 측정해야 한다. 원문 수집이 틀렸는데 모델만 바꾸거나, 레이아웃이 깨지는데 문구 학습만 늘리는 방식은 원인을 해결하지 못한다.

자체 모델·파인튜닝 여부, 고객 간 학습 여부, 학습 데이터 규모, 추천 성능, 경쟁사 대비 우위는 현재 공개 근거로 확인하지 못했다. 홈페이지의 누적 조회·연결 콘텐츠 수는 자체 학습 데이터 크기나 성과 개선의 인과효과를 뜻하지 않는다.

## 같은 품질인지 확인하는 실험 설계

독립적으로 구성한 30개 입력을 권장 출발점으로 삼을 수 있다. 실제 비교를 수행한 결과가 아니다. 짧은 메모, 긴 글, URL, PDF, 숫자가 많은 설명, 한국어·영어 혼합, 여러 브랜드 스타일, 사용자가 제공한 사진을 포함한다. 양쪽에 같은 원문과 목표를 주고 사실 보존, 편집 가능성, 시각 오류, 말투 적합성, 수정 시간, 비용을 평가한다. 반복 생성으로 결과 편차도 본다. 예약 발행과 DM은 실제 고객에게 보내지 않는 테스트 계정에서 중복·지연·실패 복구를 확인한다.
