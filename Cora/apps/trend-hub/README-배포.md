# 트렌드 허브 — 배포 안내

이 폴더를 그대로 GitHub 에 올리고 Render 에 연결하면 됩니다.
**키는 들어 있지 않습니다.** 별도로 전달받아 4단계에서 직접 넣으셔야 합니다.

---

## 1. GitHub 에 새 저장소 만들기

1. github.com → 우측 상단 **+** → **New repository**
2. 이름은 아무거나 (예: `trend-hub`). **Private 으로 두셔도 됩니다** — Render 는 비공개 저장소도 연결됩니다
3. `Add a README file` 등은 **체크하지 마세요** (빈 저장소로 만듭니다)
4. 이 폴더의 파일을 모두 올립니다

터미널을 쓰신다면:

```bash
cd <이 폴더>
git remote add prof https://github.com/<계정>/<저장소>.git
git push prof master
```

**브랜치는 `master` 입니다.** `main` 이 아닙니다 — 3단계에서 이게 걸립니다.

웹으로 올리셔도 됩니다 — 저장소 화면의 **uploading an existing file** 로 폴더째 끌어다 놓으면 됩니다.

---

## 2. Render 에 연결

1. [render.com](https://render.com) 로그인 → **New** → **Blueprint**
2. 1단계에서 만든 저장소를 고릅니다
3. Render 가 저장소 안의 `render.yaml` 을 읽어 설정을 자동으로 채웁니다
4. **Apply** 를 누릅니다

---

## 3. 브랜치를 `master` 로 바꾸기 — **빼먹으면 배포가 안 됩니다**

Render 의 **Settings → Branch** 기본값은 `main` 인데, 이 저장소의 브랜치는 **`master`** 입니다.
그대로 두면 빌드가 안 돌거나 옛 코드가 계속 떠 있습니다.

**Settings → Auto-Deploy 도 `Yes` 인지 보세요.** `No` 면 push 해도 안 올라갑니다.
이미 뜬 서비스를 고치실 때는 **Manual Deploy → Deploy latest commit** 을 한 번 눌러 주세요.

---

## 4. 환경변수 5개 넣기

Render 대시보드 → **Environment** → 아래 다섯 개를 추가합니다.
**키 값은 별도로 전달받으셔야 합니다.**

| 이름 | 무엇에 쓰나 | 없으면 |
|---|---|---|
| `ANTHROPIC_API_KEY` | 이름 추출 · 권리 판정 · 본문 요약 | 캐릭터·밈 발굴이 가짜 데이터로 돕니다 |
| `TIKHUB_KEY` | 인스타 · X · 틱톡 수집 | 새 회차를 못 돌립니다 |
| `YOUTUBE_KEY` | 유튜브 영상 붙이기 | 참조 영상이 안 붙습니다 |
| `NAVER_ID` | 네이버 검색 추이(규모) | 급등·평소 비교가 안 나옵니다 |
| `NAVER_SECRET` | 〃 | 〃 |
| `CRON_SECRET` | 자동 수집 요청 검증 | 자동 수집이 401 로 막힙니다 |

`CRON_SECRET` 은 발급받는 키가 아니라 **아무 긴 임의 문자열**입니다. GitHub Actions 쪽에도
같은 값을 넣어야 합니다(아래 '자동 수집 일정' 참고).

수집 상한은 안 넣어도 됩니다 — 기본값(판정기별 3회 · 전체 10회)으로 돌고, **설정 화면에서
바꿀 수 있습니다.** 값으로 못 박고 싶으면 `TREND_HUB_MAX_RUNS_PER_DISCOVERY` ·
`TREND_HUB_MAX_RUNS_PER_DAY` 를 넣으세요.

`RADAR_BASE` 는 트렌드 레이더를 따로 띄웠을 때만 넣습니다. 없으면 레이더 버튼이 화면에서
내려가고, 이미 쌓인 레이더 후보는 그대로 보입니다.

**`TREND_HUB_MOCK` 은 비워 두세요.** 값을 넣으면 키가 있어도 전부 가짜 데이터로 돕니다.

`FAL_KEY`·`GEMINI_API_KEY` 는 없어도 됩니다. 그 기능(이미지 생성·영상 분석)만 화면에서 내려갑니다.

**키를 안 넣어도 화면은 열립니다.** 이미 쌓아 둔 데이터(후보 196건·게시물 2,023건)가
`data/db.json` 에 들어 있어서, 키 없이도 목록·상세·계약 JSON 을 다 보실 수 있습니다.
키는 **새 회차를 돌릴 때**만 필요합니다.

---

## 5. 무료 플랜에서 알아 두실 것

- **15분 놀면 잠듭니다.** 다음 접속이 깨우는 데 **50초쯤** 걸립니다. 고장이 아닙니다
- **재배포하면 데이터가 처음 상태로 돌아갑니다.** 무료 플랜은 디스크를 못 붙여서
  `data/db.json` 을 저장소에 넣어 들고 갑니다. 화면에서 누른 검토 표시나 새로 돌린
  회차는 재배포 때 사라집니다
- 회차 한 번에 **6~7분**, 비용은 **$1.5~2** 입니다(API 요금). 자주 누르는 버튼이 아닙니다

외부 연동은 `GET /api/brief?scope=character&limit=3` 하나입니다.
쌓인 후보를 계약 JSON 으로 내보내며 **API 를 부르지 않아 돈이 들지 않습니다.**

자세한 사용법은 `docs/` 를 보세요.

## 자동 수집 일정

GitHub Actions의 `.github/workflows/trend-hub-collect.yml`이 배포 URL의 자동 실행 API를 호출합니다.

- 뉴스 소재: 매일 오전 8시 (한국시간)
- 캐릭터·유행 포맷: 화요일·금요일 오후 8시 30분 (한국시간)

GitHub 저장소의 **Settings → Secrets and variables → Actions**에 아래 두 값을 추가하세요.

| Secret | 값 |
|---|---|
| `TREND_HUB_URL` | `https://trend-hub-wesa.onrender.com` |
| `CRON_SECRET` | Render의 환경변수 `CRON_SECRET`과 같은 임의의 긴 값 |

Render의 Environment에도 `CRON_SECRET`을 같은 값으로 넣어야 합니다. 키 값은 채팅이나 저장소에 올리지 말고 각 서비스의 Secret 입력란에 직접 넣으세요.
