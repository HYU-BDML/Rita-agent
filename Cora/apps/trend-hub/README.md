# 트렌드 허브

판정기가 낳은 후보를 사람이 검토하고 생성기로 넘기는 자리.
Dify 앱들 *사이*에 비어 있던 부분이다.

## 이어서 할 때 — 대화 복구

VS Code 를 껐다 켠 뒤, 이 폴더에서:

```
claude --continue     # 마지막 대화를 그대로 이어감 (줄여서 claude -c)
claude --resume       # 지난 대화 목록에서 골라서 이어감
```

`--continue` 는 디렉터리 기준이라 반드시 `C:\Users\mooja\trend-hub` 에서 실행한다.

## 서버 다시 켜기

명령 프롬프트(cmd)에서:

```
cd C:\Users\mooja\trend-hub
npm run dev
```

그 다음 브라우저 주소창에 `localhost:3100`. 끝.
개발 서버는 터미널에 매달려 있어서 터미널을 닫으면 같이 꺼진다.

### WSL 안에서 서버를 확인할 때

node 가 Windows 쪽에 있어서 WSL 의 `localhost` 로는 안 닿는다. 호스트 IP 를 써야 한다.

```bash
curl http://$(ip route | awk '/default/{print $3}'):3100/
```

브라우저(Windows)에서는 그냥 `localhost:3100` 이면 된다.

개발용:

```bash
npm test          # 29개 통과
npx tsc --noEmit  # 타입 검사

# 스크립트를 직접 돌릴 때는 --env-file 이 필요하다.
# WSL 의 환경변수는 Windows node 로 넘어가지 않는다(웹앱 자체는 Next 가 알아서 읽는다).
npx tsx --env-file=.env.local tests/_live_topics.ts
```

키를 넣으려면 `.env.example` 을 `.env.local` 로 복사해 채운다.
키가 없는 어댑터만 자동으로 목 모드가 된다.

## 구조

```
lib/core/candidate.ts   ← 유일한 계약. 여기만 알면 된다.
lib/core/adapters.ts    ← 판정기·생성기를 꽂는 자리
lib/core/registry.ts    ← 늘릴 때 한 줄 추가하는 곳. 세워 둔 것(held)도 여기서 갈린다
lib/core/trend.ts       ← 회차 간 추이. 저장된 원본을 다시 정규화해 만든다
lib/collect/            ← 앱이 직접 하는 수집
                          rss · naver · youtube · tikhub · topics · names · rights
lib/discoveries/        ← 뉴스 소재 · 캐릭터 발굴 · 본보기 찾기  (전부 Dify 없이)
lib/producers/          ← 카드뉴스 · 주제 포스터 · 이미지 · 릴스
```

### 판정기 늘리기 = 칸 3개 채우기

1. **수집원** — 어디서 긁나
2. **판정축** — 무엇을 근거로 '지금이다' 라고 하나
3. **산출 단위** — `topic`(주제) · `subject`(대상) · `format`(포맷)

`normalize()` 하나 쓰고 `registry.ts` 에 한 줄 넣으면 끝.
배관·화면·검토·연결은 따라온다.

### 발굴기와 부착기

- `role: 'produces'` — 후보를 낳는다 (소재 찾기, 캐릭터 발굴)
- `role: 'attaches'` — 후보에 붙는다 (벤치마크)

벤치마크는 소재 찾기와 노드 ID 가 그대로 겹치는 쌍둥이다.
독립 후보로 세우면 보드에 주제·캐릭터·영상이 섞이므로 부착기로 뒀다.

## 뉴스 소재 판정기 (Dify 안 거침)

RSS 9곳을 직접 긁고, Claude 로 주제를 묶고, 네이버로 검색추이를 잰다. 한 회차 약 40초 · $0.11.

판정축이 둘이라 이런 구분이 된다:

```
서울세계불꽃축제   지금 오르는 (검색 14.63배)      매체3
로또 1240회       여러 곳이 다뤘지만 검색은 평소    매체3  ← 늘 기사 나오는 소재
삼성 DX노조 광고   두 곳이 다뤘지만 검색은 식는 중   매체2
```

기사 수만 보면 로또가 상위지만 검색은 평소와 같다. 그 구분이 이 판정기의 전부다.

**숫자는 LLM 이 대지 않는다.** LLM 은 기사 번호만 고르고, 매체 수는 코드가 그 번호로 다시 센다
(`verifyTopics`). 없는 번호를 대면 그 기사는 버려지고 카운트에 안 들어간다.
Dify 의 names → verify 와 같은 구조다.

`run()` 에서만 API 를 부르고 검증은 `normalize()` 가 한다. 그래서 판정 규칙을 고친 뒤에는
저장된 스냅샷에 다시 돌리면 된다 — 수집도 LLM 도 네이버도 다시 안 부른다.

## 트렌드 레이더 (합쳐짐)

별도 앱이던 판정기를 여기로 들였다. 레이더는 파이썬이고 이 앱은 Windows node 라
프로세스를 부르지 않는다 — 레이더가 회차마다 남기는 `runs/<회차>/trends.json` 을 읽는다.
파일시스템은 양쪽이 공유하므로 이게 가장 얇은 접점이다.

```
레이더(파이썬)  1단계 급상승 → 2단계 유형 → 3단계 확산 검증 → 4단계 2축 4구간
                         ↓ runs/<회차>/trends.json
허브(여기)      lib/discoveries/radar.ts → 후보 → 검토 → 카드뉴스 · 포스터
```

- **수집을 여기서 하지 않는다.** `run()` 은 판정까지 끝난 파일을 집어 올 뿐이라
  API 도 LLM 도 부르지 않는다. 회차 폴더는 `RADAR_RUNS_DIR` 로 바꿀 수 있다.
- **재는 축이 다르다.** 뉴스 소재는 매체 교차 + 네이버 검색 급등, 레이더는 **검색어 없이**
  플랫폼이 "지금 뜬다"고 알려준 것 + 7일 곡선 기울기다. 검색어를 넣는 순간 발굴이
  확인으로 되돌아가기 때문에 레이더는 1단계에 검색어를 하나도 두지 않는다.
- **유형이 산출 단위를 가른다.** `모습` 만 `subject`, 나머지는 `topic` 이다. 레이더에서도
  권리 귀속 판정이 `모습` 에만 붙는다(`config.kinds.모습.rights_required`).
- **게시물 수를 계정 수로 쓰지 않는다.** 레이더의 `publish_count` 는 게시물 수다.
  서로 다른 계정 수는 3단계 확산 검증을 돌아야 알 수 있고, 모르면 `accounts: null` 로 둔다.
- **근거는 3단계 링크에서만 온다.** 3단계를 돌지 않은 회차의 후보는 `evidence` 가 비어 있고,
  그러면 카드뉴스·포스터 게이트가 막는다. 그게 맞는 동작이라 채워 넣지 않았다.

`isMock` 도 같이 고쳤다. 여기까지는 모든 어댑터가 키를 들고 있어서 '키 없음 = 목'이
성립했는데, 레이더는 키가 필요 없다. 그대로 두면 진짜 판정 결과가 후보 표에 '가짜'로 박힌다.

## 세워 둔 것 (held)

같은 일을 하는 어댑터가 두 벌 생겨서, 안 도는 쪽은 `held` 에 이유를 적어 화면에서 내렸다.
코드는 지우지 않았다 — 설정 화면 맨 아래에 이유와 함께 남는다.

| 어댑터 | 왜 세웠나 | 대신 쓰는 것 |
|---|---|---|
| `material` (Dify) | `for_next` 가 근거를 '고른_주제' 하나에만 붙임 | `news` |
| `character` (Dify) | 같은 일을 native 가 하고 그쪽만 돌았음 | `character-native` |
| `benchmark` (Dify) | `human-input` 노드에서 blocking 호출이 멈춤 | `benchmark-native` |
| `cardnews` (Dify) | `RENDER_BASE` 서버 응답 없음 | `cardnews-native` |
| `image` · `reels` | `hint.imagePrompt`/`motionPrompt` 를 채우는 경로가 앱에 없어 어느 후보로도 안 열림 | — |
| `character-native` | 교차 확인 문턱을 지키면 산출이 0건 (아래) | — |

키가 없어 숨긴 것(hidden)과는 다른 칸이다. **키 없음은 키를 넣으면 열리고, 세워 둔 것은
고쳐야 열린다.** 섞어 두면 사람이 헛되이 키를 찾으러 간다.

## 주제 포스터

FLUX 는 한글 자모를 뭉갠다. 그래서 이미지에 글자를 시키지 않고 처음부터 밖에 둔다.

```
Claude   → 한글 카피(머리말·헤드라인·한 줄) + 영어 키비주얼 프롬프트 + 출처 링크
fal FLUX → 글자 없는 배경 한 장            (public/gen/<회차>.jpg 로 받아 둔다)
브라우저 → 그 위에 한글을 CSS 로 얹고 PNG 로 저장
```

문구가 마음에 안 들면 이미지를 다시 뽑지 않고 화면에서만 고치면 된다.

**실존 인물의 얼굴은 만들지 않는다.** 주제 후보에는 정치인·연예인·피의자가 그대로 들어 있고,
그 얼굴을 만들어 붙이면 포스터가 아니라 조작된 사진이다. 모델에게 시키는 것만으로는 부족해서
나온 프롬프트를 코드가 다시 본다(`assertNoLikeness`). `portrait`·`headshot`·`likeness` 같은 말이
걸리면 저장까지 가지 않고 멈춘다. 테스트가 이 검사를 지킨다.

출처 규칙은 카드뉴스 원고와 같다 — 모델이 적은 링크가 후보 근거 목록에 없으면 버린다.
있는 척하는 출처가 제일 나쁘다.

`lib/producers/poster-shape.ts` 가 따로 있는 이유: 시안 컴포넌트가 생성기 본체에서 값을 하나라도
가져오면 `node:fs` 와 Anthropic SDK 가 클라이언트 번들로 끌려와 빌드가 깨진다. 실제로 깨졌었다.

## 캐릭터 판정기를 세운 이유

교차 확인 문턱(`MIN_AUTHORS`)이 **1** 이었다. 한 계정이 한 번 말한 이름이 전부 후보가 됐다.

```
회차 2026-09-05 · 수집 게시물 142건 · 이름 후보 25개
  계정 1개 이상 → 16건   ← 이랬다
  계정 2개 이상 →  0건   ← 문턱을 지키면 이렇다
```

142개 게시물 어디에도 **두 계정이 함께 말한 이름이 하나도 없었다.** 그런데도 12건이
보드에 올라가 있었다. 출처도 몰려 있었다 — `Sololv_ARISE_KR`(나 혼자만 레벨업 ARISE 공식
계정) 한 곳이 4건을 낳았고 그중 둘은 같은 게시물 하나에서 나왔다. 브랜드 자기 홍보물이
트렌드로 올라온 것이다.

뉴스 소재는 처음부터 매체 2곳을 요구했고 테스트가 그걸 지킨다. 캐릭터만 그 검사를
건너뛰고 있었다. 코드도 알고는 있었다 — `grounded` 계산에만 `authors.length >= 2` 를 쓰고
거르지는 않아서 산출 12건이 **전부 `grounded: false`** 로 나갔다.

| | 뉴스 소재 | 캐릭터 (고치기 전) |
|---|---|---|
| 교차 확인 | 매체 2곳 | 계정 **1개** |
| 독립 판정축 | 네이버 검색 급등 | **없음** |
| 회차당 | 40초 · $0.11 | 2분 50초 · **$0.44** (TikHub 호출당 과금) |

### 수집이 교차를 구조적으로 막는다

수집은 이미 키워드 검색이다(계정 타임라인 훑기가 아니다 — 앞서 그렇게 적었던 건 틀렸다).
`창작` 트랙 검색어 3개 × 플랫폼 3개 = 9콜, 게시물 142건.

```
검색어: 자캐 · 오리지널캐릭터 · 캐릭터드로잉
게시물 142건 · 서로 다른 계정 110곳   ← 계정당 1.3건
```

**"자캐"는 '자기 캐릭터'다.** 이 검색이 모으는 건 각자 자기 것을 보여주는 게시물이고,
서로 다른 작가가 같은 캐릭터를 그릴 일이 없다. 계정 2곳이 같은 이름을 말할 확률이
구조적으로 0에 가깝다. 문턱을 올려서 0건이 된 게 아니라 **이 검색어로는 애초에 교차가
나올 수 없다.**

교차가 생기는 자리는 `팬아트` 트랙(`팬아트`·`2차창작`·`그려봤어요`)이다. 여러 사람이
**같은 캐릭터**를 그리는 행위라서다. 대신 거기서 나오는 건 대부분 남의 IP다.

### 그래서 이건 트렌드 판정기가 아니었다

`min_authors` 입력칸의 기본값이 **1** 이었고 도움말이 이랬다 —
*"개인 창작 캐릭터는 창작자 계정 하나로도 유효하므로 1을 권합니다."*

즉 원래 의도는 '여러 곳에서 뜨는 것 찾기'가 아니라 **개인 창작자의 캐릭터를 발굴하고
권리를 판정하는 것**이었다. 그 일에는 계정 1개가 맞는 단위다 — 창작자 본인이니까.
판정축도 교차가 아니라 조회수와 권리다.

문제는 그게 "지금 뜨는 것" 보드에 트렌드 후보로 올라가 있었다는 것이다.
발굴 도구가 트렌드 판정기 옷을 입고 있었다.

**발굴형으로 세웠다** (2026-09-08). 아래 왼쪽 칸이다.

| | 발굴(스카우팅) | 트렌드 |
|---|---|---|
| 검색어 | 자캐·오리지널캐릭터 (지금 그대로) | 팬아트·2차창작 |
| 계정 문턱 | 1 (창작자 본인) | 2 이상 |
| 판정축 | 조회수 + 권리 판정 | 몇 계정이 같은 이름을 말하나 |
| 나오는 것 | 협업·라이선스 후보 | 대부분 남의 IP |
| 놓일 자리 | 보드가 아닌 별도 화면 | 지금 보드 |

### 지금 상태 — 발굴형

- `MIN_AUTHORS = 1`. 개인 창작 캐릭터는 **창작자 본인 계정 하나**가 유효한 단위다.
- 기본 트랙 `혼합`(자캐·굿즈·팬아트). **남의 IP 도 일단 수집한다** — 거르는 건 수집이 아니라
  권리 판정의 일이다.
- 화면은 `/characters` 로 뗐다. 보드("지금 뜨는 것")는 주제 전용이다. 재는 축이 달라서다 —
  보드는 검색 급등, 여기는 조회수와 권리. 정렬도 조회수 순이다(`momentum.views`).
- 권리별로 묶는다: 그대로 만들 수 있음 / 협상하면 만들 수 있음 / 기획까지만.

### 19금 걸러내기

`lib/collect/safety.ts`. 캐릭터 검색어에는 성인 창작물이 딸려 온다. 후보로 한 번 올라가면
권리 판정을 사서 붙이고 포스터 프롬프트로 넘어가고 화면에 뜬다. 그래서 **수집 직후**에 버린다.

- `run()` — LLM 에 넣기 전에 버린다. 토큰도 돈도 안 나간다. 원본에는 거른 뒤만 남긴다.
- `normalize()` — 규칙이므로 저장된 옛 원본에도 다시 걸린다.
- 태그(`nsfw`·`r18`·`19금`…)와 본문 패턴 둘 다 본다. **글자만 보고 그림은 못 본다.**
- 과잉 차단도 테스트로 조인다 — '성인식', 'nude 톤', '18세기', '노출 없는' 은 통과해야 한다.

**아직 정하지 못한 것:** 트렌드형(팬아트·2차창작 검색 + 문턱 2)을 따로 세울지.
발굴형과 판정축이 다르므로 같은 판정기에 옵션으로 넣는 것은 맞지 않다.

문턱을 바꿔 가며 세어 보는 스크립트: `npx tsx tests/_authors.ts` (저장된 원본에 다시
돌리는 것이라 TikHub 도 LLM 도 안 부른다).

## 렌더 서버 (연결됨)

`RENDER_BASE=https://cardnews-render.onrender.com`. 옛 주소(112.157.39.231:8787)는 죽었고
같은 서비스가 주소를 바꿔 살아 있다. 무료 티어라 자고 있으면 첫 요청에 20초쯤 걸린다.

**우리가 원고를 쓰고, 서버가 굽는다.** 나누는 이유가 양쪽에 있다 —
근거 대조·권리 게이트는 서버가 안 하고, 브랜드 겉모습 38벌과 서버사이드 렌더는 우리가 없다.
서버사이드 렌더가 중요한 이유는 자동화다. 브라우저 시안은 사람이 탭을 열어야 그려진다.

```
POST /render                     카드뉴스 한 벌
{"template":"explain_box", "style":"gogumafarm",
 "deck":{"brand":{"wordmark":"@계정"},
         "slides":[{"role":"cover","headline":…,"text":…,"kicker":""},
                   {"role":"body", …},
                   {"role":"outro","headline":…,"wordmark":…,"account_name":…}]},
 "photos":["주소", …]}
→ {"ok":true,"job":…,"count":N,"slides":[{"index","name","w":1080,"h":1350,"url"}]}

POST /image/타이틀                포스터(사진 위에 제목)
{"사진":"/data/out/_uploads/<번호>.jpg", "제목":"… *강조* …", "부제":…,
 "자리":"아래", "정렬":"왼쪽", "글자크기":"크게", "사진어둡게":"아래쪽만", "강조색":"#22E39A"}
→ {"ok":true,"조각번호":…}

POST /실험/유경/조각/올리기        그림 올리기 (굽기 전에 반드시)
{"올릴파일":{name,type,data:"data:image/jpeg;base64,…"}} → {조각번호, 파일경로}

GET  /health                     틀 8종 · 겉모습 38벌 목록
```

**계약은 지어낸 것이 아니다.** `OneDrive/문서/카카오톡 받은 파일/카드뉴스 만들기 (등록 디자인 연동).yml`
의 weave 코드 노드에서 읽었다. 그 전에 `title`·`body`·`caption` 으로 넘겨짚었다가 전부 틀렸다 —
실제로는 `headline`·`text`·`kicker` 다. **모르면 yml 을 읽는다. 키 이름을 지어내지 않는다.**

함정 네 가지, 전부 직접 부딪혀 확인했다:

- **사진은 절대 경로만 먹는다** (`/data/out/_uploads/<번호>.jpg`). 조각 번호·상대 경로·`file://`
  는 전부 "사진이 없습니다"가 온다. 에러 문구는 조각 번호도 된다고 하지만 실제로는 안 된다.
- **실패도 HTTP 200 으로 온다.** `ok` 필드를 봐야 한다.
- **모르는 칸을 얹지 않는다.** 워크플로우 주석: "photo_roles·photo_slots 를 더 얹었더니 사진이
  제대로 안 깔렸다. 서버가 모르는 칸을 무시하지 않고 다르게 받아들일 수 있다."
- **`/piece/<번호>` 가 404 다** (서버 쪽 버그). 옛 조각도 마찬가지라 손질판의 이미지 조각
  썸네일이 전부 깨진다. 카드 세트 `/out/<job>/slide_01.png` 는 정상이다.

굽기는 **실패해도 던지지 않는다**. 이미 Claude·fal 값을 치른 뒤라, 남의 서버 상태에
우리 생성기를 묶지 않는다. 실패하면 화면에 이유만 뜨고 원고·포스터는 그대로 남는다.

겉모습 목록은 코드에 박지 않고 `/health` 에서 받아 입력칸에 채운다(10분 캐시).
박아 두면 서버에 없는 것을 고를 수 있고, 그건 굽는 순간에야 드러난다.

직접 확인하는 스크립트: `npx tsx --env-file=.env.local tests/_render.ts` (목록),
`tests/_bake.ts` (저장된 원고를 실제로 굽기), `tests/_status.ts` (지금 무엇이 되나).

## 회차와 추이

### 다시 판정 (앱에서)

`/runs` 맨 위 「저장된 원본으로 다시 판정」. **판정 규칙을 고쳤을 때 쓰는 자리다.**
수집도 LLM 도 부르지 않아 돈이 안 들고 몇 초면 끝난다 — 스냅샷을 남겨 둔 이유가 이것이다.

- 그 판정기의 원본을 **오래된 회차부터 전부** 다시 돌려 표를 새로 세운다.
  회차 하나만 다시 돌리면 옛 규칙으로 들어온 다른 회차의 후보가 남는다.
- 채택·기각·메모는 이름으로 물려받는다.
- 후보가 사라지면 거기 붙어 있던 제작물이 갈 곳을 잃는다. 지우지는 않고 몇 개인지 알린다.
- 세워 둔(held) 판정기도 다시 판정은 된다. 새로 돌리는 게 막힌 것이지,
  옛 원본을 지금 규칙으로 다시 읽는 건 오히려 세워 둔 뒤에 해야 하는 일이다.

지금까지는 `tests/_renorm.ts` CLI 로만 됐다.


후보 표는 회차마다 덮어써진다(upsert). 그래서 '지난주보다 오른 건가'가 후보 화면에서 사라졌다.
회차마다 원본을 `snapshots` 에 남겨 뒀으므로 `normalize()` 를 다시 돌리면 그 회차의 후보가
되살아난다 — API 를 다시 부르지 않고. 추이를 위해 새로 쌓아 둔 데이터는 없다.

- `/runs` — 회차별로 그때 뜬 것, 처음 나온 것, 직전 회차 대비 배수
- 후보 카드·상세 — 직전 회차 대비 (`GrowthDelta`)
- 첫 화면 맨 위 — **채택함 · 만들 차례** / **채택하고 만든 것**.
  채택이 아무 일도 일으키지 않는 버튼이었던 걸 여기서 잇는다.

차트를 두지 않았다. 회차가 두세 번이라 점 두세 개짜리 선을 그릴 자리가 아니다 —
급등 미터(`SurgeMeter`)와 같은 판단이다.

## 아직 남은 것 (값어치 순)

### 1. 캐릭터 시간축 — 무료, 제일 값어치 큼

TikHub 는 **백필이 안 된다.** 3주 전 인스타에 뭐가 돌았는지는 어디에도 없다.
그래서 추이를 얻으려면 회차를 3번 쌓아야 하고(`RUNS_FOR_VERDICT`), 회차당 $0.44 다.

**답이 이미 앱 안에 있다.** `lib/collect/naver.ts` 가 키워드만 주면 63일·372일 시계열을
즉시 준다(무료, `trendsFor` 배치 함수까지 있다). 주제 판정기가 쓰고 있고 캐릭터엔 안 쓴다.
캐릭터 이름을 데이터랩에 넣으면 **1회차부터 급등 배수와 작년 대비가 나온다.**

이름이 검색될 만큼 알려져야 잡히는 건 한계인데, 그게 오히려 판정축이다 —
"소셜에선 도는데 검색은 0" = 아직 이른 것, "둘 다 오름" = 지금인 것.

덤으로 **회차 안의 시계열**도 공짜다. 한 번 수집해도 게시물은 30일에 걸쳐 흩어져 있고
`postedAt` 을 이미 파싱해 둔다. 주 단위로 묶으면 한 회차만으로 게시 속도 곡선이 나온다.

### 2. 회차 비용 낮추기 — 무료

`character-native.ts` 가 회차마다 **이미 판정한 이름의 권리를 다시 산다**(`judgeRights`).
권리 귀속은 잘 안 변한다. 새 이름에만 물어보면 2회차부터 LLM 값이 거의 사라진다.

### 3. 인증 + 배포 — "일일이 실행"을 없애는 유일한 길

- **`/api/discover` 에 로그인은 여전히 없다.** 대신 하루 실행 상한으로 비용을 막는다
  (판정기별 `TREND_HUB_MAX_RUNS_PER_DISCOVERY` 기본 3회 + 전체 `TREND_HUB_MAX_RUNS_PER_DAY`
  기본 10회 — `lib/core/run-limit.ts`). 주소를 아는 사람은
  누구나 누를 수 있지만 하루치 천장을 넘기지는 못한다. 상한은 **성공한 회차만** 세므로
  수집 도중 터진 회차는 돈을 쓰고도 칸을 비운다. 제대로 잠그려면 여전히 토큰이 필요하다.
- `Dockerfile`·CI 가 없고 저장소가 `data/db.json` 파일이라 서버리스에 그대로 못 올린다.
- 그다음에야 스케줄(주 2~3회)이 값어치가 있다. 같은 날 두 번 돌려도 추이는 안 늘어난다.
- 지금은 dev 서버가 대화 세션에 매달려 있다. 실제로 메모리 부족으로 한 번 죽었다.

### 4. 그 밖에

- **제작물 내보내기** — 서버 카드 URL 은 생겼지만 발행·예약이 없다.
- **벤치마크가 흐름에 안 들어가 있다** — 부착기는 도는데 붙은 후보가 20개 중 1개.
- **분류어(kicker)가 겉모습에 따라 안 그려지는 듯하다** — `careet` 으로 `순서` 를 보냈는데
  카드에 안 보였다. 겉모습마다 그리는 요소가 다른 것일 수 있다. 다른 겉모습으로 한 장
  뽑아 보면 갈린다. **미확인.**
- **KIPRIS 상표 조회** — 검색어 파라미터 이름을 아직 못 맞춤.
- **릴스·모션** — 서버에 `/image/움직이기`(GIF)가 있다. 아직 안 붙였다.
- `data/db.json` 저장이 가끔 Windows 에서 `EPERM: rename` 으로 실패한다(일회성, 재시도하면 됨).
  rename 재시도를 넣으면 사라진다.
